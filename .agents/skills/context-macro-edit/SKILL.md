# 上下文宏观编辑器（Context Macro-Edit）

## R — 原文 (Reading)

> "没有什么是独立存在的，所有的元素都要根据它最终在多大程度上有助于（或有损于）其他元素来评判……上下文要求相反的东西：你必须从宏观上审视你的作品。这时你需要的是俯瞰的视角。"
>

## I — 方法论骨架 (Interpretation)

上下文编辑切换到俯瞰视角，核心是五条互相支撑的判断：

1. **局部优秀可能损害整体**（p17）。一段单独成立的"优美文字"若与作品其他部分争夺主题、稀释焦点，就必须删——评判任何元素的唯一标准是它对整体的净助益，不是它自身写得多好。

2. **重复是最常见也最隐蔽的编辑问题**（p18、ce07）。单词 / 句子层面的重复容易识别；真正危险的是主题、场景、人物、目的的*模糊重复*——作者因写作周期漫长、断断续续而察觉不到，读者却感到"似曾相识"的疲倦。识别方法只有一种：一口气通读全稿，专门找重复。

3. **节奏靠对比维持**（p20）。悬念太多淹没悬念，行动太多淹没行动——全程高潮让基准线消失，每个高潮都失重。刺激需要非刺激的喘息段衬托才能发挥效果。

4. **有意识重复 ≠ 无意识重复**（c32 vs ce07）。《教父》开场与结尾的同一把椅子从唐传到迈克尔，是有意识的主题共鸣，应当保留；无意识的场景 / 人物重复则彼此削弱，必须删除。区分二者是宏观编辑的核心判断。

5. **必备工具：时间隔离 + 局外人视角 + 场景移植实验**（p22、c04）。隔两周再读让作者脱离写作时的意图沉浸，看到实际文本；局外人视角提供不受作者意图污染的纯读者反应；把场景 / 人物移到别处、删除或合并，观察对整体的影响——这是验证"助益还是损害"的最后手段。

> 作者亲身案例佐证：卢克曼要求作家重读全稿找重复，作家们总是两周后回来同意删掉那个他们原本力保的"很棒的场景"（c04）——证明俯瞰视角必须脱离写作沉浸才能获得。

## A1 — 书中的应用 (Past Application)

### 案例 1: 《精神病患者》——悬疑场景稀疏才有效（c33）

- **问题**：希区柯克要让每一处悬疑场景都对读者 / 观众产生最大冲击，而不是越放越多导致麻木。
- **方法论的使用**：运用 p20（悬念太多淹没悬念）+ f13③（用对比衬托）。诊断思路是：如果浴室谋杀场景一个接一个，作品会降格为 B 级血腥片——因为基准线消失了，每一次悬疑都被前一次预支。
- **结论**：悬疑场景必须稀有且相隔很远，让每一次都充分发挥效果。这是"稀缺性放大效果"在节奏层的应用。
- **结果**：《精神病患者》成为悬疑经典而非血腥片，支撑了"作品需要喘息和解决，冲突才能发挥最大效果"这一元法则。

### 案例 2: 《教父》首尾镜头呼应——有意识的重复表达家族循环（c32）

- **问题**：如何用视觉语言表达"家族循环的完成"这一深层意义，而不靠台词说明。
- **方法论的使用**：运用 f13② 的关键区分——有意识重复 vs 无意识重复。开场的镜头是唐·柯里昂坐在椅子里，结尾是迈克尔·柯里昂坐在同一意象的椅子里。这不是无意识的场景重复（应当删除），而是有意识的意象呼应。
- **结论**：有意识的重复通过共鸣强化主题，是宏观编辑应当*保留*的工具；它与应当*删除*的无意识重复形成正反对照。
- **结果**：成为"重复"章节的核心正面例证，与作者亲身删场景的案例（c04，作家两周后同意删）形成正反教材对。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **整体失衡感**：作品各部分单独看都行，拼在一起却说不清哪里不对、读者会读到哪儿开始累。
2. **不知道该删什么**：每段都舍不得删，但直觉告诉作者"太长了 / 重复了"。
3. **节奏乱 / 刺激疲劳**：每章都在反转或高潮，读者却越读越无聊（基准线消失）。
4. **怀疑有隐蔽重复**：主题、场景、次要人物可能在模糊重复，但断续写作让作者看不出来。
5. **完稿后定型前**：需要做最后一轮宏观修订，但缺乏系统化的俯瞰流程。

### 语言信号 (用户的话里出现这些就应激活)

- "节奏乱"、"整体失衡"、"pacing off"
- "重复"、"redundant"、"似曾相识"、"读着累"
- "不知道该删什么"、"每段都舍不得删"
- "这段写得好，但放这里怪怪的"
- "每章都有反转，读者却说无聊"
- "一口气读完一遍"（暗示用户要做宏观通读）

### 与相邻 skill 的区分

- 与 `allocation-audit` 的区别：本 skill 做**宏观编辑操作**（检测重复、调控节奏对比、做场景移植实验）；`allocation-audit` 做**篇幅反推主题的诊断**（统计各主题占比，问"作品真正关于什么"）。前者是"改什么"，后者是"诊断是什么"。典型顺序：先 allocation-audit 诊断真实主题，再用本 skill 执行重复 / 节奏修订。
- 与 `suspense-designer` 的区别：本 skill 在**整体层**调控（悬念的稀缺性、节奏的对比、整体重复）；`suspense-designer` 在**单场景层**设计悬念技法。当问题是"这一个悬念场景怎么写得更好"用 suspense-designer；当问题是"为什么每章都有悬念读者却疲劳"用本 skill。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **一口气通读（或卷末回顾）专门找重复**
   - 让用户脱离写作时的沉浸状态，在最短时间内通读全稿（或当卷）。
   - 只找四类重复：主题重复、场景重复、人物重复、目的重复。单词 / 句子层面的重复交给文字编辑，不在此步。
   - 对每处重复做标记：是有意识呼应（如 c32 教父首尾）还是无意识稀释（如 ce07）？
   - 完成标准：产出一份"重复清单"，每项标注类型、位置、保留 / 删除的初步判断。
   - 适配说明：若用户是网文连载作者无法"一口气读完"，退化为"卷末回顾"——每写完一卷安排一次冷却后的整卷通读，模拟原书的"隔两周再读"。

2. **检查节奏对比（诊断"刺激疲劳"）**
   - 对每个高潮 / 反转 / 悬念段，问：它的前后有没有非刺激的喘息段？
   - 用 p20 检验：若全程高能，每个高潮都会失重——基准线消失，反转贬值。
   - 完成标准：标出所有"缺少对比段"的高潮，给出"插入喘息段"或"压缩部分高潮"的修复建议。
   - 判停条件：若作品本身就是短篇或单元剧（天然无需长对比），跳到步骤 3。

3. **做场景 / 人物移植实验，验证上下文影响**
   - 对每个"写得好但放这里怪"的元素，做三种实验：移到别处、删除、与相似元素合并。
   - 用 p17 检验：这个元素对整体的净助益是正还是负？"写得很好"不是保留理由，"对整体有助益"才是。
   - 完成标准：每处疑点给出明确处置（保留 / 移动 / 删除 / 合并）+ 理由（基于对其他元素的影响，不是基于自身质量）。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **短篇或单场景作品**：宏观俯瞰的前提是"有整体可俯瞰"。短篇的"整体"几乎等于"单场景"，用 suspense-designer 等单场景 skill 即可。
- **早期未冷却的草稿**：作者脑中仍充满自己意图，看不到实际文本——p22 明确要求"至少间隔两周"再进行上下文编辑。若用户刚写完就要宏观修订，先劝退。
- **还在边写边发的网文连载中段**：原书的"一口气读完找重复"假设了完稿后的整体俯瞰；连载作者无此机会，应改用"卷末回顾"而非逐章宏观编辑。

### 作者在书中警告的失败模式

- **ce07 重复彼此削弱**：场景 / 人物 / 背景 / 主题 / 事件在作品中重复出现（即便单看都很精彩），导致彼此稀释。预警信号：两个次要人物功能相似可以合并、同一主题被不同场景重复演示、读者产生"似曾相识"的疲倦。
- **ce08 节奏失衡**：两种失衡——(a) 开场即高潮，后续降速铺陈时读者烦躁；(b) 全篇缓慢把行动压到结尾，读者已不在状态，高潮无法被吸收。
- **ce16 多视角牺牲叙事**：为展示多视角的力量频繁切换叙述者，结果是重复内容、故事停滞、读者精力被"区分视角"消耗。多视角天然制造重复，违背上下文编辑原则——除非作品本质要求多叙述者。

### 作者的盲点 / 时代局限

- **"一口气读完作品"的隐含假设**：卢克曼的修订流程假设了 2002 年纸质书完稿后的整体俯瞰机会。在网文断更连载、读者每天读 15 分钟、作者边写边发的模式下，这一工作流不成立——需适配为"卷末回顾"，每写完一卷冷却后通读整卷。
- **西方经典案例，无东方叙事对照**：全书用《教父》/《精神病患者》/《雨一直下》等西方案例。中国章回体"欲知后事如何"的钩子机制、单元剧主角刻意不变的设计，都不在作者的对照系内——套用时需注意东方叙事传统可能有自己的宏观节奏规则。
- **精英审美立场**：作者的"有机体论"以"经久不衰的杰出文学"为最高标准，对"快餐但高粘性的商业类型文"潜在低估。商业网文的"爽感密度"有时恰恰要求重复套路（装逼打脸、升级流），与作者"删除重复"的纪律存在根本张力——对爽文类型应放宽重复约束。

### 容易混淆的邻近方法论

- 与 `allocation-audit`：两者都在第7章、都用宏观视角，但本 skill 看的是"重复 / 节奏 / 对比"，allocation-audit 看的是"篇幅占比"。诊断方向不同——前者问"哪些元素彼此削弱"，后者问"作品真正关于什么"。
- 与单场景层技法（suspense-designer 等）：本 skill 不教"如何写好一个悬念场景"，只教"为什么每章都有悬念读者却疲劳"——这是整体层的诊断，不是单场景层的技法。

## 相关 skills

- **composes-with `allocation-audit`**: 先用 allocation-audit 诊断篇幅失衡与真实主题（量占比反推意图），再用本 skill 执行重复/节奏/对比的宏观修复——诊断标尺与修复操作的协同，典型工作流是先诊断后修复。
