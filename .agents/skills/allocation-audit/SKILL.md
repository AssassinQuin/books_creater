# Allocation Audit — 篇幅分配审计

## R — 原文 (Reading)

> "篇幅分配是你的总体规划，它比任何其他东西都更能反映你的故事是关于什么的……作家对作品的特定方面投入有多深，会极大地影响作品的节奏、进展、焦点和终极意义。"
>
> — Noah Lukeman, 第7章 上下文 · 意义

---

## I — 方法论骨架 (Interpretation)

篇幅分配是作品"关于什么"的客观证据——它比作者的自述更诚实。如果一部作品自述关于"崛起"却用 75% 篇幅写"衰落"，真正的主题就是衰落。

该方法可迁移到三层自检：
- **作品层**：花最多篇幅的人物/场景/主题，是不是你真的想说的事？
- **人生层**：花最多时间/注意力的事情，是不是你真认为重要的事？
- **文档/演讲层**：最长的那一段，是否对应最重要的论点？

常见陷阱：作家在没决定"关于什么"时就开写，结果是篇幅失衡——核心被次要淹没，作品"既不是这个也不是那个"。

**关键反例（库尔茨悖论）**：占据最多篇幅的人物不一定是主要人物——主要/次要由在作品中的重要性决定，而非篇幅。所以"篇幅=真实主题"不是机械等式，要看具体人物/元素对全局的牵引力。

---

## A1 — 书中的应用 (Past Application)

### 案例 1: 《黑暗的心脏》的库尔茨——篇幅最少却是主要人物 (c05)

- **问题**: 如何判定康拉德《黑暗的心脏》的"主要人物"是谁？按出场篇幅吗？
- **方法论的使用**: 卢克曼用库尔茨反证"主次不由篇幅决定"——库尔茨出场时间有限，却是整部作品的"主要人物"。其他人物都把他当做神话/上帝来对待；在道貌岸然的殖民者中，只有他突破了所有束缚。上下文赋予他远超出场篇幅的分量。
- **结论**: 主要/次要由人物在作品中的重要性、与其他人物的关系决定，而非出场篇幅。
- **结果**: 这一论点在第3章和第7章两次被援引，成为全书"上下文塑造人物"论点的核心例证，也构成"篇幅=真实主题"法则的关键限定条件。

### 案例 2: 卢克曼的编辑经验——作家的篇幅分配常常背叛自述主题 (c03/c04 + p19/p21 论证)

- **问题**: 卢克曼作为文学经纪人（5 年读 5000 部原稿）反复发现：作家无法回答"你的作品关于什么"，且实际篇幅分配与自述主题错位。
- **方法论的使用**: 他让作家停下来做 p21 的三问清单——(1) 作品关于什么？(2) 每个主题/人物/事件分配了多少篇幅？(3) 篇幅分配与"关于什么"一致吗？典型案例：作家声称写"一个人的崛起"，却用 75% 篇幅描写他的衰落。
- **结论**: 篇幅分配失衡的作品必须被"修改成型"——通常意味着必须删除心爱的次要部分，"不管你有多么喜欢它"（因为保留它们会让作品"既不是这个也不是那个"）。
- **结果**: 这张三问清单成为终稿定型前的强制性自检纪律；也解释了为什么许多作家写完后才意识到"原来我真正写的是另一个故事"。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **作品核心不清**：写完（或写到大半）却回答不出"这作品到底关于什么"——尤其是当你发现不同读者总结出完全不同的主题时。
2. **读者抓不到重点**：读者读完说不出核心，或总结出的主题与你的意图明显错位。
3. **删改决策纠结**：某段写得很好但你不确定该不该删——你需要一把"标尺"来决定它是否服务于核心主题。
4. **人生/文档优先级迷茫**：嘴上说某事最重要，但时间/字数分配说明相反——需要一面"诚实镜子"。

### 语言信号 (用户的话里出现这些就应激活)

- "我的作品到底在讲什么"
- "说不清主题 / 核心模糊 / 焦点散"
- "该删哪段 / 不知道该不该删"
- "读者抓不到重点"
- "我的优先级到底是什么"
- "what's it about / off-topic / priority / focus"

### 与相邻 skill 的区分

- **与 `context-macro-edit` 的区别（最易混淆，必须讲清）**：
  - **本 skill = 诊断标尺**——量篇幅占比 → 对比意图 → 输出"主题诊断报告"（真实主题是什么、哪里失衡了）。
  - **`context-macro-edit` = 修复操作**——具体执行宏观编辑（删重复、调配对比、删局部美但损害整体的元素）。
  - 简言之：本 skill 告诉你"失衡在哪、真实主题是什么"，`context-macro-edit` 告诉你"具体怎么改"。通常**先用本 skill 诊断，再用 `context-macro-edit` 修复**。
- **与 `experience-depth` 的区别**：本 skill 是**宏观篇幅占比**的反推（作品层）；`experience-depth` 是**单个人物弧线**的深度诊断（"真变了还是表面变了"）。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **统计各人物/主题/场景的篇幅占比**
   - 操作：列出全部人物/主题线/场景群，估算各自占据的字数/章节数/时间长度，得到占比表（例：主角A 30% / 主角B 25% / 反派 5% / 背景设定 40%）。
   - 完成标准：得到一张可对比的占比表，每一项有数字百分比。
   - 判停条件：若作品完成度 <50%，统计意义有限——跳到步骤 2 做意图对齐预检，等作品接近完成再回头量化。

2. **对比占比与作者意图**
   - 操作：让作者写出"作品关于什么"的一句话主题，然后把步骤 1 的占比表与该主题对照，标出每一项"意图重要性 vs 实际占比"的差距。
   - 完成标准：列出至少 3 项失衡（占比与意图重要性明显错位的元素）。
   - 判停条件：若作者说不出"关于什么"，先做 p21 三问清单——(1) 作品关于什么？(2) 每个元素分配了多少篇幅？(3) 分配与"关于什么"一致吗？——再回到本步。

3. **诊断真实主题 + 做增删决定**
   - 操作：基于占比表反推"篇幅意义上的真实主题"（例如：自述关于崛起，但 75% 写衰落 → 真实主题是衰落）。对失衡元素逐一做出增/删/压缩决定，并记录"真实主题"诊断结论。
   - 完成标准：产出一份"真实主题诊断报告" + 一份增删决定清单。
   - 注：具体的删改执行（重复检测、节奏调配、局部美但损害整体的元素删除等）交给 `context-macro-edit`。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **意识流/实验文本**——这些体裁刻意追求失衡、跳跃、碎片化，"篇幅=真实主题"的假设不成立。
- **短篇（300 页以下 / 2 小时以下）**——篇幅本就紧凑，统计粒度不足以稳定反推主题；短篇的诊断更适合用 `reading-psychology-curve` 或 `experience-depth`。
- **网文连载（边写边发）**——作者常常没有全局俯瞰机会，篇幅分配反映的是更新节奏/追读反馈的动态博弈，而非完整的创作意图；应先转为整稿再审计。

### 作者在书中警告的失败模式 (ce09 · 篇幅分配失衡)

- **失败模式**：在与核心目标无关的人物/话题/事件/主题上投入过多篇幅，作品失去平衡，读者无法判断"这到底是个什么故事"。
- **机制**：篇幅分配是作品"关于什么"的客观证据——比作者的自我陈述更诚实。一旦分配失衡，读者会**下意识地用篇幅推断主题**，结果推断出错误主题，与作者意图错位。删除心爱的次要部分是痛苦的，但保留它们会让作品"既不是这个也不是那个"。
- **警示信号**：作者说作品"关于 A"但 A 只占 20% 篇幅；一个次要人物占据不合比例的章节；读者读完说不出核心；作者拒绝删减"因为写得很好"的段落。

### 作者的盲点 / 时代局限

- **"篇幅=真实意图"假设源于传统作家"凭潜意识写作"的模式**。在 AI 辅助写作中，篇幅可能反映 AI 的展开习惯或上下文窗口，而非作者潜意识意图——需要先剔除 AI 生成的冗余段落再做审计。
- **在大纲驱动写作中可能失真**：篇幅分配可能在动笔前就已规划——此时篇幅反映的是大纲的结构意图，不一定是"潜意识的真实主题"。大纲驱动 ≠ 潜意识流露。
- **卢克曼假设作家有完整作品可被通读统计**。网文连载作者边写边发、按章追读反馈调整，篇幅分配是动态博弈结果，"作品关于什么"本身可能在连载中漂移——本 skill 应在完结或分卷后再用。
- **案例全是西方长篇文学/电影**（《黑暗的心脏》等），缺少对短媒介与东方叙事传统（章回体"欲知后事如何"的钩子机制）的篇幅反推验证。

### 容易混淆的邻近方法论

- **`context-macro-edit`（最易混）**——见 A2 区分。要点：本 skill 是诊断标尺，`context-macro-edit` 是修复操作。
- **`experience-depth`**——本 skill 反推作品层主题，`experience-depth` 诊断单个人物弧线的深度。

## 相关 skills

- **contrasts-with `context-macro-edit`**: 本 skill 是诊断标尺（量篇幅占比反推真实主题，输出"失衡在哪、作品真正关于什么"），context-macro-edit 是修复操作（具体执行重复检测、节奏调配、局部美但损害整体的删除）。诊断 vs 修复——典型顺序是先用本 skill 定位，再交给 context-macro-edit 改。
