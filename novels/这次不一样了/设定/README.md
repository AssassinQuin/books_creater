# 设定文件归属说明

> 本文档明确各设定文件的归属系统、加载方式和维护责任。
> 按「单源维护」原则，同一内容只在主文件描述完整，其他文件用指针引用。

| 文件 | 归属系统 | 用途 | 维护时机 |

## 迁移说明

### 1. 人物能力设定方案.md → novel-character skill

**迁移内容**: 能力体系设计规范、七阶等级、能力类型、代价设计原则
**迁移到**: `.claude/skills/abilitycraft/SKILL.md`（能力设计） + `.claude/skills/engines/ability.md`（能力描写）
**原因**: 能力设计是人物系统的核心环节，应在skill中统一规范
**原文件状态**: 保留作为项目历史参考，但不再主动维护
**加载方式**: 写作时通过动态加载协议 Tier 3 自动引用

### 2. 受伤恢复与物品消耗追踪.md → novel-chapter-writer skill

**迁移内容**: 受伤数据结构、恢复时间线、物品追踪规则、状态检查清单
**迁移到**: `.claude/skills/novel-chapter-writer/references/engine-status.md`
**原因**: 状态追踪是写作执行规范，应在写作skill中统一
**原文件状态**: 保留作为项目历史参考，但不再主动维护
**加载方式**: 写作时 Step 2 + Step 3 自动引用

## 数据来源分工（写作时）

| 内容 | 确定位置 | 记录位置 | 加载方式 |
|------|---------|---------|---------|
| **关系变化** | 大纲（卷/章节） | novel-db relation表 | DB查询 |
| **态度变化** | 人物系统 | `角色深化.md` | Tier 3 加载 |
| **能力变化** | 大纲（卷/章节） | `角色深化.md` + DB | Tier 3 加载 |
| **受伤状态** | 写作时确定 | DB status.injuries | engine-status.md |
| **物品状态** | 写作时确定 | DB status.inventory | engine-status.md |
| **世界观细节** | 世界观系统 | lorebook YAML | Tier 2 按需加载 |
| **不可变更规则** | 初始化确定 | `锁定设定.md` | Tier 4 校验 |

## 维护流程

### 每卷大纲规划时

1. 确定本卷**关系变化节点**（谁和谁的关系变了）
2. 确定本卷**能力变化节点**（谁的能力提升了/质变了）
3. 更新大纲文件，标注变化章节

### 每卷写作前

1. 更新 `角色深化.md` 中的态度矩阵（按大纲标注）
2. 更新 `角色深化.md` 中的能力弧线（按大纲标注）
3. 检查 `锁定设定.md` 是否有冲突

### 每章写作后（Step 3）

1. 同步受伤/物品状态到 DB
2. 同步关系变化到 DB
3. 更新角色蒸馏文件
4. 如态度有变化，更新 `角色深化.md`
