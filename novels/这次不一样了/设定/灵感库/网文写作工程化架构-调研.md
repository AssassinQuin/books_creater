## 一、网文写作工业化流程拆解

### 1.1 网文作者的实际写作流程

**三级前置体系（大纲→卷纲→章纲）**

多位日更作者的共识：
- 大纲至少花费一个月，确定全书走向和卷级目标
- 每卷卷纲三天起步，标注核心事件、人物出场、情绪基调
- 每章细纲至少半小时，写正文时"基本就是在做选择题"
- 关键：提前理顺所有逻辑，写正文不需要灵感，不管怎么写故事线都不会跑偏

**L1-L4四层写作模型**（来源：CSDN sanshanjianke）

| 层级 | 名称 | 产出 | 粒度 |
|------|------|------|------|
| L1 | 种子层 | 愿景/概念 | 一句话 |
| L1.5 | 卷纲层 | 每章1-3句方向描述（≤100字）+ 核心事件/人物/情绪/视角 | 卷级 |
| L2 | 章纲层 | 功能序列（场景节拍表） | 章级 |
| L3 | 叙事层 | 带标签草稿 | 段落级 |
| L4 | 渲染层 | 正文 | 句子级 |

卷纲模板字段：卷名-篇幅-时间跨度-主线-支线-本卷高潮-章节概要-卷末衔接（伏笔回收/遗留/情绪收束/下卷启动条件）

**爽点密度工程**

- 每章按"压抑→拉升→释放→留钩子"四步循环
- 开篇"黄金三章"：三章内立住主角人设、交代核心困境、抛出钩子
- 爽点四类型：逆袭爽、打脸爽、成长爽、情感爽
- 频率："开篇小爽吸引→中期大爽留住→后期高爽收尾"
- 情绪节奏"抑扬顿挫"：先抑后扬，情绪落差越大爽感越强

**百万字架构管理**

- 不做一口气捅到大结局的大纲，增量规划+卷级独立
- 每次至少覆盖5-10章的增量规划
- 支持断点续做和卷纲↔章纲反馈循环

### 1.2 编剧工程学方法论

**Save the Cat! 15-Beat 结构**（Blake Snyder）

15个节拍从Opening Image到Final Image，核心是对三幕式的进化：
```
Opening Image(1%) → Theme Stated(5%) → Setup(1-10%) → Catalyst(10%) →
Debate(10-20%) → Break into Two(20%) → B Story(22%) → Fun and Games(20-50%) →
Midpoint(50%) → Bad Guys Close In(50-75%) → All Is Lost(75%) →
Dark Night of the Soul(75-80%) → Break into Three(80%) → Finale(80-99%) → Final Image(100%)
```

**网文适配映射**：
- Fun and Games = 升级期/能力展示
- Bad Guys Close In = 卷末压力累积
- Midpoint = 假胜/假败转折（对应"十章一大爽"的中点）
- All Is Lost = 卷末低谷（下一卷钩子）

**Dan Harmon Story Circle（8步循环）**

```
You(舒适区) → Need(渴望) → Go(进入陌生) → Search(适应/试炼) →
Find(得到想要) → Take(付出代价) → Return(回归) → Change(改变)
```

关键洞察：
- 多尺度应用：微观（场景）→中观（单章）→宏观（卷）→元观（全书）
- Step 8的Change是下一个Step 1的You，形成"螺旋"而非"重复"
- A线和B线可各有自己的circle，在Step 5和Step 6交织
- Step 6（代价/后果）是连载故事最丰富的区域

**Robert McKee 三层冲突模型**

1. 超个人冲突（社会/环境/制度）
2. 人际冲突（关系/权力/情感）
3. 内在冲突（内心挣扎/道德抉择）

核心原则：**冲突是故事的引擎，没有冲突就没有故事**。"期望与结果之间的落差"是创造角色有意义变化的机制。

**CONCOCT系统**（EMNLP 2023论文）

训练"具体性评估器"判断事件的细节层次，用"最模糊优先展开"策略实现均匀节奏。人类评估CONCOCT的节奏一致性比基线高57%。可应用于AI辅助写作的节奏控制。

### 1.3 中西方法论对照

| 维度 | 中文网文传统 | 英文编剧工程 |
|------|------------|-------------|
| 结构分层 | 卷纲→章纲→正文 | Act→Sequence→Scene→Beat |
| 节奏设计 | 三章一小爽、十章一大爽 | Midpoint假胜/假败、All Is Lost |
| 开篇策略 | 黄金三章 | Catalyst(10%) + Break into Two(20%) |
| 结尾钩子 | 每章留钩子 | Dark Night of the Soul + Finale setup |
| 长篇管理 | 增量规划、卷级独立 | Arc architecture: micro-meso-macro |

## 二、AI长篇小说Agent架构

### 2.1 代表性开源项目

**InkOS**（6.3k stars，TypeScript）— 目前最成熟的AI小说写作Agent

架构：10个专职Agent管线
```
雷达(市场趋势) → 规划师(章节意图) → 编排师(上下文选择) → 写手(正文生成) →
观察者(9类事实提取) → 反射器(JSON delta+Zod校验) → 归一化器(字数治理) →
审计员(33维度检查) → 修订者(问题修复)
```

7个真相文件作为唯一事实来源：
- current_state.md（世界状态）
- particle_ledger.md（资源账本）
- pending_hooks.md（未闭合伏笔）
- chapter_summaries.md（各章摘要）
- subplot_board.md（支线进度板）
- emotional_arcs.md（情感弧线）
- character_matrix.md（角色交互矩阵）

实测：31章/452,191字/平均~14,500字/章/审计通过率100%

**NovelClaw**（320 stars，Python/FastAPI）— 华南理工大学

三层架构：Portal(公开入口) → MultiAgent(快速构思) → NovelClaw(主写作工作区)
- 可编辑的memory bank
- 可观测运行（progress.log、章节文件）
- 持续会话（conversation sessions保留写作语境）

**Morpheus**（30 stars，TypeScript+FastAPI）— 三层记忆+知识图谱

- L1/L2/L3文件记忆 + RUNTIME_STATE + OPEN_THREADS + L4角色档案
- consistency.py提供时间线/角色状态/关系/世界规则一致性检查
- 轨迹回放系统
- 知识图谱子系统

**AI-Novel-Writing-Assistant**（1.3k stars，TypeScript）— AI Native系统

端到端：从idea到full chapters，结构化规划+worldbuilding+agent-driven workflows+RAG

### 2.2 学术前沿

**DOME**（NAACL 2025，华南理工大学）
- 动态层次化大纲(DHO)：将规划和写作阶段融合
- 记忆增强模块(MEM)：基于时序知识图谱(Temporal Knowledge Graph)
- 实验表明在流畅性/连贯性/整体质量上显著优于SOTA

**ConStory-Bench**（ACL 2026，微软&新加坡科技设计大学）
- 一致性错误分类法：5大类19子类型
  - 事实错误(Factual)
  - 角色错误(Character) — 最常见（35%）
  - 时间线错误(Temporal) — 次常见（25%）
  - 世界规则错误(World Rule)
  - 逻辑矛盾(Logic)
- ConStory-Checker：4阶段自动检测管道
- 错误率随故事长度指数增长：5000字约3.2个错误/千字，50000字约7.8个错误/千字

**Agents' Room**（ICLR 2025，Google DeepMind）
- 受叙事理论启发，将叙事写作分解为子任务
- 规划Agent（故事骨架+章节结构+角色动机）和写作Agent（正文产出）
- Tell Me A Story数据集开源

**Pratilipi 4层记忆架构**（印度最大小说平台）
- Rolling Summary方案：每章结束后更新
- Continuity Agent追踪每个角色细节/地点描述/时间线事件
- Parallel Agent System并行处理不同一致性维度

### 2.3 记忆管理架构对比

| 项目 | 记忆方案 | 持久化 | 检索方式 |
|------|---------|--------|---------|
| InkOS | 7个真相文件(JSON+Zod) + SQLite时序DB | 文件+SQLite | 相关性检索+全量注入 |

### 2.4 关键技术趋势

1. **多Agent分工已成共识**：写作/审计/记忆/规划分离是主流模式
2. **结构化记忆 > 纯上下文窗口**：从全量prompt注入演进到JSON schema校验+知识图谱+向量检索
3. **伏笔追踪是长篇核心难题**：各项目均投入大量资源
4. **反AI检测从后置走向内置**：在写手agent prompt层就注入去AI味规则
5. **可观测性成为质量保证基础**：progress.log/轨迹回放/证据链

## 三、写作质量保证体系

### 3.1 传统出版业编辑流程

五层级严格顺序：
1. **Editorial Assessment**：入口诊断，判断手稿需要哪种编辑
2. **Developmental Editing**：大图关注——情节结构、人物弧线、节奏、主题
3. **Line Editing**：逐句逐段审视，涉及事实核查、结构调整和文体润色
4. **Copy Editing**：机械性错误（拼写、标点、人名一致性）
5. **Proofreading**：排版后最终校对，必须用不同的人（fresh eyes）

业界共识：**一致性(consistency)是最高优先级**。

### 3.2 修订清单标准化（Nathan Bransford）

五维度：
- **Storytelling Essentials**：钩子是否有效、冲突是否充分、情感弧线是否完整
- **Structure**：时间线逻辑、章节节奏、信息投放节奏
- **Characters**：每个角色是否有独特声音、动机是否清晰、是否有成长
- **Craft**：showing vs telling、对话自然度、意象使用
- **Brass Tacks**：字数、格式、开场页质量

### 3.3 网文平台审核机制

| 平台 | 签约门槛 | 核心推荐机制 |
|------|---------|-------------|
| 起点 | 最高 | 点击量+收藏+追读 → 编辑推荐位 → 分类榜 → 总榜 |
| 晋江 | 极高（编辑审稿制） | 文笔和剧情质量，偏向女频垂直 |
| 番茄 | 最低（开放式签约） | 算法推荐（完读率、互动率），数据驱动 |

共同关注：更新频率（日更稳定性）、读者互动（段评/月票）、续费转化率

### 3.4 AI项目中的QA体系对比

| 项目 | 审计维度 | 一致性检查 | 反AI检测 | 回归测试 |
|------|---------|-----------|---------|---------|
| InkOS | 33维度 | 7真相文件交叉验证 | 内置去AI味+anti-detect模式 | 状态快照+回滚 |
| Morpheus | 时间线/角色/关系/世界规则 | consistency.py | 未提及 | 轨迹回放 |
| ConStory-Bench | 5大类19子类 | ConStory-Checker(4阶段管道) | 否 | 基准测试 |
| **本项目** | **三视角审查+validate_chapter** | **novel-db+foreshadow_list** | **SENTENCE-PATTERNS.md(6种指纹)** | **health_check+C3级联** |

### 3.5 一致性守护者模式（CSDN）

7个Agent分工：世界观设定师 → 大纲规划师 → 卷级规划师 → 章节写作师 → **一致性守护者** → 质量评审 → 风格调整

核心创新：将一致性检查从事后审计变为**"写入时验证"(write-time validation)**。

## 四、反AI检测与去AI味

### 4.1 AI检测器原理

**两大核心指标**：
- **Perplexity（困惑度）**：衡量文本可预测性。AI文本困惑度低（高度可预测），人类文本困惑度高且多变
- **Burstiness（突发性）**：衡量文本节奏变化。人类混合长短句（高突发性），AI倾向均匀句式（低突发性）

GPTZero从2个指标进化到7层系统，在RAID基准测试中达到95.7%准确率。

**LLM风格指纹**（Copyleaks 2025论文）

- LLM存在独特的"风格指纹"，即使被要求以不同风格写作仍然保持一致
- Claude/Gemini/Llama/OpenAI四模型区分精确率达0.9988
- **关键发现**：同一模型的风格指纹无法通过换prompt规避

### 4.2 AI文本的六类可检测指纹

| 指纹 | 特征 | 人类对比 |
|------|------|---------|
| 困惑度分布 | 窄峰（集中在低值区） | 宽分布 |
| 词汇重复模式 | 过度使用"however/moreover/furthermore" | 自然变化 |
| 句式对称性 | 每句长度相似 | 长短交替 |
| 情感平淡性 | "安全"中性语气 | 强烈情感波动 |
| 段落结构模板化 | 段落长度高度一致 | 变化丰富 |
| 过渡词过度使用 | 机械连接 | 意义驱动连接 |

### 4.3 中文AI文特征（台湾数位时代）

五大可辨识特征：
1. 假真诚开场白（"在当今快速变化的世界中..."）
2. 心理咨询语气（过度共情）
3. 排版过度优化（完美的要点列表）
4. 句式单调（每句长度相似）
5. 词汇安全（避免有态度的表达）

去AI味4原则：
1. 善用动词，减少名词化
2. 刻意打破句式长度，创造节奏感
3. 加入具体感官细节而非抽象概念
4. 允许"不完美"的存在

### 4.4 系统级去AI味策略

不是简单替换词汇，而是重构信息投放节奏：
- **扩充策略**：1000字扩展到2000字，通过环境细节/内心活动/感官描写稀释AI味
- **重写策略**：5000字全文重写，可降低约70%的AI检测率
- **交替使用不同AI模型**：降低文本一致性特征
- **引入"认知不对称"**：让叙述者和读者之间存在信息差

### 4.5 本项目现有系统评估

本项目 SENTENCE-PATTERNS.md 已覆盖6种AI指纹：

| 指纹 | 本项目应对 | 覆盖度 |
|------|----------|--------|
| F1 句号切割 | 标点多样性引擎 | ✅ 完整 |
| F2 即释即解 | 三层信息投放 | ✅ 完整 |
| F3 对称结构 | 场景结构随机组合器(6×8×6) | ✅ 完整 |
| F4 否定泛滥 | 硬上限≤1/章+8种替代写法 | ✅ 完整 |
| F5 意象重复 | 意象梯度系统+替换库 | ✅ 完整 |
| F6 环境白噪 | 轮换库≤2同类型/章 | ✅ 完整 |

**新增发现**：Copyleaks论文证明风格指纹跨风格稳定，使用同一模型（Claude）写作时必须在句式/词汇/节奏层面系统性破解。可增加：
- "困惑度注入"引擎（通感/意象跳跃）
- "突发性增强"引擎（极端短句+极长句交替）

## 五、百万字长篇一致性管理

### 5.1 一致性错误分布（ConStory-Bench）

| 错误类型 | 占比 | 严重度 |
|---------|------|--------|
| 角色属性矛盾 | 35% | 高（外貌/性格前后不一致） |
| 时间线矛盾 | 25% | 高 |
| 空间/地理矛盾 | 15% | 中 |
| 因果逻辑矛盾 | 12% | 高 |
| 世界观规则矛盾 | 8% | 高 |
| 事件状态矛盾 | 5% | 中 |

错误率随长度指数增长：5000字约3.2个错误/千字 → 50000字约7.8个错误/千字

### 5.2 AI长篇三大痛点（腾讯云）

1. **记忆消失**：上下文窗口限制导致遗忘前文设定
   - 解决：三层记忆——工作记忆(当前章节) + 短期记忆(前3-5章摘要) + 长期记忆(全书设定数据库)
2. **风格漂移**：同一角色在不同章节中语言风格逐渐偏移
   - 解决：建立"角色声音锚点"(voice anchor)，每次生成前加载该角色的典型对话样本
3. **工作流断裂**：工具切换导致创作连贯性中断
   - 解决：多Agent协作机制，由编排器统一管理上下文传递

### 5.3 实用工具对比

| 工具 | 强项 | 适用场景 |
|------|------|---------|
| Aeon Timeline | 时间线追踪、多线叠加、角色年龄计算 | 史诗/奇幻 |
| Campfire Writing | 角色关系图、世界地图编辑器、家族树 | 群像小说 |
| 电子表格 | 自定义灵活度最高 | 所有类型 |
| Story Grid Spreadsheet | 场景编号/POV/字数/时间地点/情感弧线 | 结构化分析 |
| Claude 200K | 整本小说全局一致性检查 | AI辅助写作 |

### 5.4 本项目架构定位

本项目的 novel-db MCP（56工具）+ get_chapter_context 智能模式 + validate_chapter 硬约束 + writing_finish 状态管理，构成了业界领先的"写入时验证"架构。

**缺口与改进方向**：
1. 缺乏ConStory-Checker式的**自动矛盾配对检测**（跨章搜索矛盾）
2. 缺乏Proofread级别的**最终校对步骤**
3. 可增加**困惑度注入**和**突发性增强**引擎强化反AI检测
