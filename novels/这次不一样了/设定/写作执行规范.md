# 写作执行规范

> **本规范为最高优先级，后续所有章节写作必须严格遵守**
> **本文件只管小说特定规则**：字数、流程、人物规则、检查清单
> 通用规则不在本文件中重复定义，只指向权威文件：
> - AI指纹→`engines/anti-ai-patterns.md`
> - 对话规则→`engines/dialogue.md`
> - 场面搭建→`engines/scene-composition.md`
> - 场景深化→`engines/scene-deepening.md`
> - 硬约束（标点/违禁词/字数）→`engines/writing-constraints.md`
> - 风格节奏→`engines/writing-style.md`
> - 人物设计→`engines/character-design.md`
> - 世界观→`engines/worldbuilding.md`

---

## 一、字数要求

- **每章目标**：3000字以上
- **允许范围**：3000-5000字
- **最低门槛**：每章≥3000字
- **检查方式**：每章完成后立即用Python脚本统计字符数：`python3 -c "import sys; t=open(sys.argv[1]).read(); print(f'字符数: {len(t)}')" 文件路径`

### 偏差处理
- 低于3000字：**必须使用场景深化技法扩写**（→见`engines/scene-deepening.md`），让每句话同时做≥2件事
- 超过5000字：考虑分章

---

## 二、内容依据（严格执行）

### 大纲对照
- **必须包含大纲规定的所有场景碎片**
- 场景顺序严格对应大纲编排
- 伏笔埋设点必须对应大纲

### 数据一致性
- **novel-db为准**：角色能力、状态、关系必须与db一致
- 世界观设定：地名、人名、势力、物品名称统一
- 所有概念和设定来源于 DB 已注册数据

### 技能/能力使用
- **严格按照角色当前能力等级**描写
- 能力效果匹配角色当前觉醒/进阶状态——未觉醒时能力以"手感异常""直觉"方式暗示
- 能力使用代价必须展现
- 能力增长需要事件触发和代价展示，随状态变化递进

## 三、小说特定写作规则

### 🔴 角色智能底线（强制）
- [ ] **所有角色都没有蠢人**——错误判断必须基于信息不对称/利益冲突/情绪干扰，不是因为蠢
- [ ] 任何角色的"错误"都必须给出基于角色已知信息+立场的合理推理链
- [ ] 角色智能底线具体到每个角色→见设定/角色深化.md·各角色标注"🔴"的规则

### 🔴 世界势力存在感（强制）
- [ ] 大纲中出现的势力在对应场景中有自然存在形式——通过NPC行为/环境痕迹/对话提及展现
- [ ] 各势力在具体卷中的存在形式→见对应卷大纲
- [ ] 灵站必须同时展现正面和负面→见`engines/worldbuilding.md`·维度7残酷度
- [ ] 新引入的势力角色自带存在理由（利益/职责/信仰），从其自身立场出发行动

### 🔴 残酷度底线（强制）
→ 见 `engines/worldbuilding.md`·维度7: 残酷度
- [ ] 外围人不是"勉强糊口"——是饿着肚子等下一份活
- [ ] 水比食物贵。水霸控制水源，取水交水钱
- [ ] 冷季饿死人。这是算术题不是道德题
- [ ] 灵衰症晚期被"送灰"——扔出聚落
- [ ] 灵站治疗只对供体开放。教会"拿命换魂"
- [ ] 互助出于算计。人情债可以拿人抵
- [ ] 壁盾先守矿脉灵站，聚落排后面
- [ ] 冷漠不是性格——是生存策略。好人做不了好事

### 🔴 NPC互动真实性（强制）
- [ ] 陌生人NPC互动从戒备/试探/利益交换开始，信任通过事件逐步建立
- [ ] 只有长期熟人（阿婆/老陈/阿铁/阿公/方岩）可直接温情互动
- [ ] 沈念获取情报通过偷听/旁观/熟人转述/观察发现
- [ ] 陌生人主动透露敏感信息基于利益交换或误判前提——信息有来源和动机

### 🔴 角色行为一致性（强制）
- [ ] 角色行为必须与角色蒸馏/人物卡一致（写作前加载角色蒸馏文件）
- [ ] 角色特定习惯从角色蒸馏中读取，不硬编码

### 🔴 微动作泄露内心（强制）
- [ ] 离别/告别场景：角色必须有2-3个不舍微动作
- [ ] 隐藏情绪通过身体泄露，不用直白词
- [ ] 每个情绪转折点至少1个微动作，每个告别场景至少2个微动作

### 🔴 世界观与逻辑审计（强制）
- [ ] 新引入概念是否说清楚——读者能否不依赖外部知识就理解
- [ ] 世界观展开是否自然——通过场景/动作/对话带出，不是角色突然科普
- [ ] 事件因果逻辑是否清晰——角色决策符合已知信息，无逻辑跳跃
- [ ] NPC传授知识途径正确——老猎人教经验✅/路人突然科普❌/有利益交换才透露✅
- [ ] 信息释放节奏合理——不一次性倾倒

### 🔴 时间锚点（强制）
- [ ] 每章开头必须有明确时间标记（天数/时段/相对上章）
- [ ] POV切换时用环境光线/天气/人物作息锚定时段
- [ ] 事件弧内时间线连续，事件弧结束后允许时间跳跃
- [ ] 同一天不同时段用"傍晚""入夜""天亮了"等标记

### 🔴 第三人称叙事一致性（强制）
- [ ] **POV锁定**：每场场景锁定一个POV角色
- [ ] **信息边界**：叙述范围限定在当前POV角色的认知内
- [ ] **观察过滤**：POV角色的观察受其情绪、经验、关注点影响
- [ ] **价值判断用行为传递**：用角色行动/环境细节展示判断
- [ ] **POV切换信号**：切换POV时用明确信号引导读者
- [ ] **内心活动限第三人称**：不切换为第一人称内心独白

### 🔴 反AI指纹消除（强制）
→ 完整规则见 `engines/anti-ai-patterns.md`
→ 硬约束见 `engines/writing-constraints.md`
- [ ] 标点多样性：每段≥3种标点
- [ ] 否定转折句式（"不是X，是Y"）≤1次/章
- [ ] 场景结构不重复
- [ ] 段落长度变化：至少3个一句话段落+2个长段落（7+行）
- [ ] 无连续3句句号切割

### 🔴 环境先行设计（强制）
→ 完整策略见 `engines/scene-composition.md`
- [ ] 大事件开始前必须先设计所有涉及的环境框架
- [ ] 同一地点不同章节出现时，从环境快照加载核心特征保持一致
- [ ] 环境参与叙事——光线暗示时间、温度暗示危险、声音暗示接近

### 🔴 对话个性化（强制）
→ 完整规则见 `engines/dialogue.md`
- [ ] 对话基于角色档案设计，遮住名字能分辨谁在说话
- [ ] 同一角色对不同人说话方式不同
- [ ] 使用弦外之音：不说破、答非所问、话里有话、留白

### 🔴 人物外观一致性（强制）
- [ ] 人物外观/性别/标志性特征从人物描写库加载，跨章一致
- [ ] 网文旁白可以细腻但不啰嗦——每个描写细节至少承担两个功能

### 🔴 物品使用一致性（强制）
- [ ] 物品一旦出现过，外观/功能/使用方式即锁定
- [ ] 灵能残渣等关键物品有完整感官描写
- [ ] 物品状态追踪（谁持有/完好度/位置）

### 🔴 复杂场面生成（强制）
→ 完整策略见 `engines/scene-composition.md`
- [ ] 每章至少1个中量以上场面（≥2人互动≥800字）
- [ ] 3+人场景必须使用角色矩阵
- [ ] 场面密度匹配事件层级
- [ ] 关键对话有潜台词层
- [ ] 场景间过渡使用软过渡/零换行切换

## 四、章节完成检查清单（每章必查）

### 基础检查
- [ ] 字数达标（≥3000字）
- [ ] 场景完整（包含大纲要求的所有碎片）
- [ ] 文件命名正确：`第{NNN}章-{标题}.md`

### 反AI指纹检查
→ 见 `engines/anti-ai-patterns.md` 完整清单
→ 见 `engines/writing-constraints.md` 硬约束阈值

### 小说特定检查
- [ ] POV锁定：每场景仅一个POV，不越界
- [ ] NPC互动符合戒备规则
- [ ] 角色行为与角色蒸馏一致
- [ ] 所有角色误判基于信息不对称/利益冲突
- [ ] 微动作/情绪泄露到位
- [ ] 时间锚点明确
- [ ] 世界观展开自然
- [ ] 灵站同时展现正面和负面
- [ ] 残酷度底线达标
- [ ] 对话个性化：遮住名字能分辨谁在说话
- [ ] 环境一致性：同地点核心特征一致
- [ ] 人物外观一致
- [ ] 物品一致

### DB更新（强制）
- [ ] `writing_finish`已调用，更新摘要、事件、维度、时间线
- [ ] 伏笔状态正确（埋设/回收/待回收）
- [ ] 角色状态与当前章节一致

### 角色蒸馏（强制）
- [ ] 每章完成后创建`角色蒸馏/{角色名}-V{N}CH{N}.md`
- [ ] 包含：角色状态变化、写作规范符合度、伏笔/线索状态

### 伏笔/线索维护
- [ ] 本章埋设的伏笔已正确记录
- [ ] 本章回收的伏笔已正确标记
- [ ] 线索状态保持一致

### Memory 更新（推荐）
- [ ] 本章重要创作决策已存入 Memory（scope: project, type: decision）
- [ ] 新发现的写作技巧/经验存入 Memory（scope: shared, type: pattern）
- [ ] 角色关键行为/状态变化存入 Memory（scope: project, type: context）

## 五、重写标准

- 字数低于3000字
- 场景缺失或严重偏离大纲
- 违反禁止事项
- 存在注水段落
- 用户明确要求重写

## 六、执行纪律

1. 读取大纲对应场景
2. 读取get_chapter_context上下文
3. 按**正文生成加载协议**加载：卷级大纲→事件大纲→伏笔线索→世界观→地图→人物快照→环境快照→事件快照→前文回顾
4. 读 `engines/writing-style.md`（风格节奏）
5. 读 `engines/anti-ai-patterns.md`（AI指纹——必读）
6. 读 `engines/scene-composition.md`（场面搭建）
7. 读 `engines/scene-deepening.md`（场景深化）
8. 加载出场角色的**人物档案**
9. **环境先行设计**：为本章场景搭建环境框架
10. **事件场面搭建**：完成场面设计清单
11. 按本规范的小说特定规则生成内容
12. 自检：反AI指纹+小说特定规则+场面+密度+反注水+对话+外观+物品
13. 统计字数
14. 调用writing_finish更新DB
15. 创建角色蒸馏文档
16. 更新环境快照/物品状态
17. 检查所有检查清单
