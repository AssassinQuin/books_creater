# Lorebook 世界知识按需注入系统

> 借鉴 SillyTavern Lorebook 机制，将静态世界观设定转化为关键词触发的智能知识图谱。
> 写作时根据当前章节内容自动激活相关设定，实现 token 高效利用 + 精准设定投放。

---

## 一、条目格式规范

每个条目存储为独立 YAML 文件（`lorebook/entries/{id}.yml`），格式如下：

```yaml
# 条目ID（全局唯一）
id: LB-001
# 条目名称
name: 灵枢集团
# 主关键词（任一命中即触发）
keys: [灵枢, 灵枢集团, 钟衍, 韩朗, 柳陌, 枢都, 内环]
# 次关键词（选择性逻辑生效时使用）
secondary_keys: [经济控制, 灵晶经济, 供体]
# 选择性逻辑：0=AND_ANY, 1=NOT_ALL, 2=NOT_ANY, 3=AND_ALL
selective: true
selective_logic: 0
# 条目内容（被注入到prompt的文本）
content: |
  灵枢集团是灵能时代的核心经济实体...
# 是否常驻（始终激活，不受关键词限制）
constant: true
# 优先级（数字越小越优先）
priority: 10
# 注入位置：before_char=角色前, after_char=角色后, at_depth=指定深度, author_note=作者笔记
position: before_char
# at_depth 时的深度值
depth: 0
# 激活概率 0-100（100=必激活）
probability: 100
# 激活后持续章数（sticky）
sticky: 0
# 激活后冷却章数
cooldown: 0
# 前N章不激活
delay: 0
# 排他组名（同组只激活一个）
group: ""
# 排组内权重
group_weight: 100
# 是否忽略token预算
ignore_budget: false
# 备注/元信息
comment: 六大势力之首，常驻加载
# 关联条目ID（递归扫描用）
related: [LB-007, LB-031, LB-050]
# 分类标签
tags: [势力, 核心设定]
# 适用卷范围（留空=全书适用）
volume_range: ""  # 如 "V1-V4" 或 "V5,V8,V10"
```

## 二、选择性逻辑详解

```
selective: false  →  主关键词任一命中即激活（不检查次关键词）
selective: true   →  激活后还需通过次关键词检查

selective_logic:
  0 AND_ANY  →  主关键词命中 + (任一次关键词命中)
  1 NOT_ALL  →  主关键词命中 + (并非所有次关键词都命中)
  2 NOT_ANY  →  主关键词命中 + (没有次关键词命中)
  3 AND_ALL  →  主关键词命中 + (所有次关键词都命中)
```

**示例**：
- "剑圣" 条目：keys=[剑圣], secondary=[战斗, 对决], logic=AND_ANY
  - "剑圣拔出了剑准备战斗" → ✅ 激活（"战斗"命中）
  - "剑圣在村口做饭" → ❌ 不激活（"战斗""对决"都没命中）
- "灵站阴暗面" 条目：keys=[灵站], secondary=[供体, 疼痛, 偷偷], logic=AND_ANY
  - "他走进灵站，看到供体在排队" → ✅ 激活
  - "灵站今天天气不错" → ❌ 不激活

## 三、注入位置系统

| position | 注入位置 | 用途 |
|----------|---------|------|
| `before_char` | 角色档案之前 | 基础世界观、核心设定 |
| `after_char` | 角色档案之后 | 补充设定、势力详情 |
| `at_depth` | 章节内容中间 | 场景切换提示、氛围注入 |
| `author_note` | 作者笔记区 | 写作约束、风格提醒 |

## 四、Token 预算管理

```
总上下文预算
├── 角色档案（出场角色×人均~800token）
├── Lorebook 预算（总上下文的 20%，硬上限 4096 token）
│   ├── 常驻条目（优先加载，占 Lorebook 预算的 40%）
│   └── 按需条目（按优先级排序，占剩余 60%）
├── 当前章节大纲 + 事件快照（~500 token）
├── 伏笔/线索追踪（~300 token）
├── 写作规范/风格指令（~500 token）
└── 前文回顾（占剩余全部）
```

**裁剪规则**：
1. 常驻条目 + ignore_budget 条目 → 永不裁剪
2. 按需条目按 priority 排序，超出预算则从低到高裁剪
3. 同 group 条目只保留一个（按权重选）

## 五、时序控制

| 效果 | 行为 | 小说场景 |
|------|------|---------|
| **sticky** | 激活后持续N章 | 核心设定在某卷中保持活跃 |
| **cooldown** | 激活后冷却N章 | 避免同一设定反复出现 |
| **delay** | 前N章不激活 | 剧情推进后才揭示（伏笔/揭秘） |

**状态持久化**：每个条目的激活状态保存在 `lorebook/state.yml` 中，跨章节持续。

## 六、扫描范围

Lorebook 扫描的文本源（按优先级）：

1. **章节大纲**（当前卷事件大纲）
2. **章节前文回顾**（上一章结尾摘要）
3. **出场角色列表**（角色名作为关键词）
4. **地点/环境名**（场景设定中的地点关键词）
5. **已激活条目的 content**（递归扫描，发现关联条目）

---

## 七、加载流程

```
写作开始
  │
  ├─ Step 1: 加载常驻条目（constant=true）
  │   → 注入 before_char 位置
  │
  ├─ Step 2: 收集扫描文本（大纲+前文+角色+地点）
  │
  ├─ Step 3: 关键词匹配 → 候选激活列表
  │   ├─ 检查 selective + selective_logic
  │   ├─ 检查 delay（当前章是否允许激活）
  │   ├─ 检查 cooldown（是否在冷却中）
  │   └─ 检查 sticky（是否仍在上次激活持续期）
  │
  ├─ Step 4: 递归扫描
  │   → 新激活条目的 content 加入扫描文本，重新扫描
  │   → 发现关联条目（related 字段）
  │
  ├─ Step 5: 概率检查（probability）
  │
  ├─ Step 6: 包容组竞争（同 group 只保留一个）
  │
  ├─ Step 7: Token 预算裁剪
  │
  └─ Step 8: 按注入位置分配到 prompt
```

## 八、与现有系统的关系

| 现有系统 | Lorebook 定位 | 说明 |
|---------|-------------|------|
| `世界观/*.md` | **上游源文件** | Lorebook 条目从这里拆分，源文件保留完整版 |
| `人物/{角色}.md` | **独立系统** | 人物档案不放入 Lorebook，人物名作为扫描关键词触发相关设定 |
| `角色蒸馏/*.md` | **独立系统** | 章节级快照，与 Lorebook 互补 |
| `写作执行规范.md` | **独立系统** | 写作规范始终加载，不走 Lorebook |
| `novel-chapter-writer` | **消费方** | 写作 skill 按上述流程加载 Lorebook 条目 |
