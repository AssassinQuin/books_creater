# 项目工作流手册（这次不一样）

> 用途：本项目所有任务的**操作手册**——新会话/compact 后看这里知道"下一步该读什么、调什么 skill、产出落在哪"。
> 性质：流程规范（怎么干活），区别于设定（是什么）/ 大纲（写什么剧情）。
> 单一入口：本文件 + `0-项目/上下文.md` 是新会话唯二必读。其余按任务按需读。

---

## 〇、compact / 新会话恢复路径（首读此段）

```
1. 读 0-项目/上下文.md            ← 项目当前状态 v4 快照 + 权威文件指针
2. 读 0-项目/工作流.md（本文件）   ← 确认当前任务的 skill 与产出位置
3. 按任务类型，读对应权威文件（§三 入口规则）
4. 查 5-追踪/伏笔.md              ← 确认伏笔状态（commit 校验依据）
5. 查当前卷的 4-大纲/剧情线/      ← 确认剧情进度（已写到哪个 Beat）
6. 开工
```

**铁律**：步骤 1-2 必读，不可跳。步骤 3-5 按任务按需。

| **封面** | 书名 + `0-项目/题材定位.md` | `story-cover` | 封面图 |
| **逆向导入已有小说** | 外部小说文本 | `story-import` | 反向解析为项目结构 |
| **资料调研（题材/政策/技术）** | — | `web-research` | 调研报告 |

### 路由细则

- **剧情线是本项目的核心层**（介于卷纲与细纲之间）。写剧情线**不调用专用 skill**——它是本项目自定的规范层，由 `剧情线设计规范.md` 约束，用 `story-long-write` 的方法论支撑。
- **多 agent 协作**：写卷纲/剧情线时，`story-architect`（架构）+ `character-designer`（角色）+ `narrative-writer`（叙事）可并行 spawn；改设定时，先 `character-designer` 改，再 `consistency-checker` 验。
- **审查是双轨**：`story-review`（叙事/情感/节奏多视角）+ `consistency-checker`（事实/伏笔/时间线只读）——两轨不可互相替代。
- **brainstorm 触发**：写剧情线时如卡壳（某个 Beat 的"发展"段填不出），用 `brainstorm` 碰撞灵感，不硬编。

## 三、变更纪律（每次改动必做）

### 3.1 通用纪律

| 触发 | 必做检查 | 工具 |
|---|---|---|
| 改角色属性 | grep 角色名（正文+设定+伏笔）确认无矛盾；更新 `2-角色/_索引.md` 关系网；`0-项目/上下文.md` §七 记决策 | `Grep` + `Edit` |
| 改伏笔 | **保表头 + F 编号 + 状态格式**（commit 校验强阻断）；回收时更新状态 | `Edit`（严守 schema） |
| 新增角色 | 建 `2-角色/X.md`（按 8 段模板）+ 更新 `_索引.md` + `上下文.md` §七 记决策 | `Write` + `Edit` |
| 新增伏笔 | 在 `5-追踪/伏笔.md` 登记（F 编号 + 状态 + 真实答案 + 分层） | `Edit`（保 schema） |
| 改能力体系 | grep `1-世界观/男主能力进化体系.md` 术语；确认无旧"通灵玉鉴"残留；更新 `能力术语映射-v4.md` | `Grep` + `Edit` |
| 改世界观 | grep 相关规则在所有设定/大纲/正文的出现；更新 `0-项目/上下文.md` §五 仙侠原生机制 | `Grep` + `Edit` |

### 3.2 重构纪律（v4 第一准则）

- **refactor-over-patch**（独立设计禁补丁）：重构时从权威文件独立设计；不写"v4 vs v3 变更日志"；不标"保留"标记；该删删该重构重构。
- **禁锁章节数 / 字数**（卷纲/剧情线）：时序用相对锚（"转生第 N 日"），不用"第 N 章"。
- **单一来源**：设定只在一处写（角色在 `2-角色/`，世界观在 `1-世界观/`，伏笔在 `5-追踪/伏笔.md`）；其它文件只引用不重述。

### 3.3 命名纪律

- **反派全部原创中文化**（昊玄/殁殃/厄枭/江烬/薛恒/戌迦/玄冥/紫蘅/天枢）——禁西式名、禁勇者/召唤体系。
- **能力体系**：男主 = 灵觉敏锐极简——禁旧通灵玉鉴系（鉴映/鉴纳/鉴纹暴起/通灵鉴域/鉴连网络外挂义）。
- **共和 Show 不 Tell**：和邦扩展通过事件 show，不写议会辩论/制度建设长戏。

## 五、跨会话上下文交接

### 5.1 compact 前
- 把当前进度（写到哪个 Beat/哪个章节/哪个角色正在拆）记到 `0-项目/上下文.md` §七"下次继续的起点"
- 把未完成的 `[待设计]` 占位清单记到 §七
- 把本会话的设定决策记到 §七"最近决策"

### 5.2 新会话首条消息
- 报告"我读了上下文.md，当前进度是 X，下一步打算做 Y"——让用户确认起点正确
- 如发现死链/矛盾，先报告再动手

### 5.3 关键文件保护（不可误改）
- `5-追踪/伏笔.md`：表头受 `.claude/hooks/lib/foreshadow_schema.py` 校验，改伏笔必保 schema
- `.claude/rules/story-consistency.md` / `story-outline.md` / `story-narrative.md`：写作红线，不擅自改
- `6-方法论/重构总纲-v4.md`：v4 全书脊柱，改动需用户拍板
