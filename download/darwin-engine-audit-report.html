全局问题（按严重度排序）
P0
零 Frontmatter 覆盖 — 系统性发现瘫痪
39个引擎文件中仅1个(three-perspective.md)有YAML frontmatter，覆盖率 2.6%。skill-loader 无法自动发现、索引、版本管理、依赖解析。所有引擎沦为"隐式知识"，只能靠人工记忆调用。
影响: 38/39 文件 (97.4%)
P0
硬编码小说名 — 丧失复用性
loading.md、battle.md、dialogue.md、environment.md、author-voice.md、snapshot.md、item.md、ability.md、world-element-registry.md 共9个引擎硬编码 novel_name="这次不一样了"。换书需手动修改9+处源码，违反"引擎应是通用组件"原则。
影响: 9/39 文件 (23.1%)
P0
writing-constraints.md 断链 — F级致命缺陷
engines/writing-constraints.md 是符号链接断裂文件（指向本地路径），当前环境完全不可访问。上层 skills/ 目录有同名文件但未建立引用。引用此文件的skill会静默加载失败。
影响: 引用方全部失效
P1
边界条件系统空白 — 异常场景无降级策略
仅 three-perspective.md 有异常处理表。其余38个引擎对加载失败、数据冲突、超出能力边界等场景几乎无覆盖。Agent执行遇到异常时只能"猜测"或"静默跳过"。
影响: 38/39 文件 (97.4%)
P1
检查点设计不足 — 质量无法自动化验证
仅 outline-review.md(9/10)、battle.md(8分)、dialogue.md(14项QA)、author-voice.md(10项校验) 有合格的检查点设计。25个引擎（64%）缺乏质量门控机制，产出质量完全依赖执行者自觉。
影响: 25/39 文件 (64.1%)
P1
职责重叠三重奏 — 多处重复定义维护
"降AI率"在 platform.md/writing-style.md/anti-ai-patterns.md 三处重复定义；"风格分析"在 book-analysis.md 和 corpus-style.md 重叠；"合规红线"在 platform.md 和 review-checklist.md 重叠。三处维护容易不同步。
影响: 6个文件至少
P1
author-voice 专精层整体过薄 — 独立引擎深度不够
battle(37行)、emotion(38行)、daily(59行)、mystery(61行) 均不足百行，作为独立引擎深度不够。其中 emotion 和 battle 尤其单薄，缺少情感强度梯度映射和具体操作示例。
影响: 4个文件
P2
存储架构不一致 — 三种存储并行无统一规范
loading.md 声明"DB优先"，但 world-element-registry.md 用文件系统注册，corpus-style.md 用Memory MCP，brainstorm.md 结果存Memory。三种存储引擎并行运行但无统一数据治理规范。
影响: 架构级
P2
三视角Agent同质化 — 差异化不足
reader/author/character 三个Agent引擎高度对称（101-104行），结构完全一致但缺乏各自视角独有的分析维度。三个Agent的输出缺少冲突仲裁机制。
影响: 3个文件
P2
test-prompts.json 覆盖率极低 — 无法验证引擎质量
仅包含skill级别测试prompt（2条），引擎级别测试覆盖率为0%。outline-review.md(60分最高)和 writing-style.md(核心标准源)等关键引擎完全无测试用例。
影响: 质量保障
