全局 跨 Skill 系统性问题

1. novel_name 硬编码 "这次不一样了" - 影响全部 Skill

novel-writer、novel-setup、novel-character、novel-chapter-writer 等多个 Skill 在代码示例中硬编码了小说名。一旦切换项目或新增项目，状态查询、DB 操作全部失效。应在项目层统一定义变量，各 Skill 引用而非硬编码。

2. abilitycraft 与 novel-ability-designer 功能严重重叠

两个 Skill 核心理念、流程、术语替换表几乎完全一致，造成三重冗余（加上 lorecraft 的术语表）。AI 无法判断该触发哪个。建议废弃 novel-ability-designer，将独有内容合并入 abilitycraft。

3. Skill 间数据交接协议缺失

novel-qa 输出的审阅报告格式未定义，novel-reviser 不知道如何解析；novel-planner-volume 的大纲输出与 novel-chapter-writer 的输入缺乏 schema 验证；writing_finish 元数据与审阅输入的对应关系不明确。

4. 引擎加载方式不一致

有的用 skill_loader()、有的用 Read() 直接路径、有的用相对路径。三种方式混用增加维护成本，可能导致文件路径变更时遗漏。

5. 质量断层危险 - 入口薄弱但子系统精良

novel-writer (5.3) 作为总路由器分数最低，但下游的 chapter-writer (8.6)、planner-volume (8.4) 质量很高。薄弱的入口导致意图识别和路由可靠性不足，高质量子系统可能因错误路由而无法触发。
