> 根据 novel-planner 确定的"每卷做什么"，设计"每章发生什么"。**把握脉络，不追求细节**。世界元素注册、感官5要素、微事件多样性等留给正文写作阶段(novel-chapter-writer)。

## 强制流程

```
Step 0: 增量检测 → 加载框架+数据采集
  ↓
Step 1: Agent — 事件架构师 → 因果链+人物弧光+悬念锚点

Step 2: Agent — 章节设计师 → 逐章大纲+伏笔节奏+声音适配

Step 3: 卷级验证 → 三视角审查(读者/作者/人物)
```

## Step 0: 增量检测与数据采集

### 0.1 增量检测（核心优化）

```python
# 检查是否存在上次的审计报告
audit_report = "novels/{小说名}/审阅报告/V{N}-卷级审计.md"

if audit_report exists:
    # 计算自上次审计以来的变更量
    git_diff = git diff --stat <last_audit_commit> -- "novels/{小说名}/设定/大纲/V{N}-*.md"
    changed_ratio = changed_lines / total_lines

    if changed_ratio < 0.3:
        mode = "增量审计"
        # 只审查变更的章节 + 前后各1章（因果链影响）
        scope = "变更章节及其邻章"
    else:
        mode = "全量审计"
        scope = "全部章节"
else:
    mode = "全量审计"
    scope = "全部章节"

# 展示给用户
print(f"审计模式: {mode} | 范围: {scope}")
```

**增量审计规则**：
- 变更<30%：只审变更章+邻章，复用上次未变更部分的审查结果
- 变更≥30% 或新增卷：全量审计
- 上次审计报告不存在：全量审计
- **强制全量触发**：用户明确要求、卷目标/核心设定变更、新增/删除整章

## Step 1: Agent — 事件架构师

### 输入
- 本卷大纲 + 全书骨架
- 本卷活跃角色（character_list，按需character_get重点角色）
- 未回收伏笔
- 卷定位（起/承/转/合）

### 职责
**把握脉络**——不追求逐场景细节，回答三个核心问题：
1. 这卷的情感曲线是什么？（从哪到哪）
2. 因果链怎么走？（因为A所以B逼出C）
3. 谁变了？怎么变的？

### 输出
- **卷级起承转合**（四段概要，每段1-3句话）
- **因果链**（关键事件，每事件3要素）：
  - 因为：[前因]
  - 所以/逼出：[后果/选择]
  - 雪球：[连锁反应]
- **人物弧光**：本卷谁变了、什么事件触发的、变到什么状态
- **悬念锚点**：本卷回答了什么、新提出了什么

### 输出验证
- [ ] 因果链从头到尾无断裂
- [ ] 每个主要角色有明确的卷内变化（或"不变"有理由）
- [ ] 与上下卷衔接自然

## 🔒检查点A: 确认事件架构

编排器展示：

```
【V{N}《{卷名}》事件架构】

情感曲线: {起点} → {转折} → {终点}

起承转合:
  起(Ch?): {概要}
  承(Ch?): {概要}
  转(Ch?): {概要}
  合(Ch?): {概要} → 下卷钩子: {类型}

因果链: {事件1} → {事件2} → ... → {终点}

人物弧光:
  {角色A}: {起点状态} → {触发事件} → {终点状态}
  {角色B}: 不变（理由：{ }）

悬念: 回答了[?] / 新提出[?]

确认后进入章节设计。输入"OK"或修改意见。
```

## Step 2: Agent — 章节设计师

### 输入
- 确认后的事件架构
- 现有逐章大纲（如有）
- 上一卷末角色状态
- 增量模式下的变更范围

### 职责
**逐章大纲**——每章只写核心，不展开细节。参考实际大纲的写作风格（叙事性描述 > 表格清单）。

### 输出
- **逐章大纲**（每章）：
  - 标题
  - 核心事件（1-3句话，叙事性描述）
  - 参与角色
  - 伏笔操作（埋/提/收，简单标注）
  - 章节节奏标记（紧/中/慢）
- **声音适配总图**：每章的声音层（battle/emotion/daily/mystery）
- **伏笔节奏概览**：全卷伏笔埋/提/收一览（不是逐章检查表）

### 增量模式
如果增量检测发现只改了部分章节：
- 只重新设计变更的章节
- 标注受影响的邻章（因果链/伏笔可能需要联动调整）
- 未变更章节保持原样

### 输出验证
- [ ] 每章有明确核心事件
- [ ] 因果链无断裂（章与章之间有过渡逻辑）
- [ ] 伏笔不积压（不连续3章无伏笔操作）

## Step 3: 卷级验证（三视角审查）

### 增量 vs 全量

| 模式 | 范围 | 三视角 | 交叉检查 |
|------|------|--------|---------|
| 增量 | 变更章+邻章 | 只审变更部分 | 只检查变更部分与未变更部分的接口 |
| 全量 | 全卷 | 三个视角完整审查 | 完整交叉检查 |

### 三视角审查（3个Agent并行）

- **读者视角**: 追读体验（钩子/悬念/爽点间隔/信息投放/情感共鸣）
- **作者视角**: 结构工艺（起承转合/因果链/伏笔管理/节奏控制）
- **人物视角**: 角色一致性（行为符合性格/动机充分/选择必然/OOC检测）

**核心原则**：人物 > 读者 > 作者

### 问题分级
- **P0**: 三视角冲突 / 角色OOC / 因果链断裂
- **P1**: 单视角严重问题
- **P2**: 微调建议

### 🔒检查点B: 确认验证通过

P0→必须修复（回到对应Step）。无P0→进入保存。

## Step 4: 保存

### 文件落盘
```
novels/{小说名}/设定/大纲/V{N}-{卷名}.md          # 更新逐章大纲
```

大纲风格：**叙事性描述为主**。参考《01-兽潮.md》的写法——用故事化的语言描述事件，不用表格堆砌。叙事动作注释用 `**叙事动作**:` 标记。

### 审计报告保存
```
novels/{小说名}/审阅报告/V{N}-卷级审计.md          # 审计结果持久化
```

审计报告格式：

## 与上下层的关系

- **上层：novel-planner**：提供"每卷做什么"（卷目标/核心事件类型/钩子设计）
- **本层：novel-planner-volume**：设计"每章发生什么"——**把握脉络，不注册细节**
- **下层：novel-chapter-writer**：根据本层大纲生成正文。**世界元素注册在正文写作阶段完成**（Ch9-2老猎人事件后才会出现"源质分级名单"这种具体元素，卷级大纲无法预知具体描写）

## 本层不做的事（明确边界）

| 不做 | 原因 | 谁做 |
|------|------|------|
| 世界元素注册 | 卷级只知道"老猎人死了"，不知道"采购单上写什么"——具体感官/功能/外观是正文写作时才确定的 | novel-chapter-writer (Agent 2 Creative Director) |
| 感官5要素分配 | 每个场景的视觉/听觉/嗅觉在正文写作时才有意义 | novel-chapter-writer (Agent 3 Engine Coordinator) |
| 微事件多样性检查表 | "费笔≥2/日常≥2"是正文质量指标，不是大纲指标 | novel-chapter-writer + validate_chapter |
| 逐章字数预估 | 大纲阶段无法预估正文实际字数 | 写作时按 writing-constraints.md 控制 |

## 声音适配规则

Agent 2（章节设计师）为每章标记声音层，写入大纲供正文写作时加载：

| 章节事件类型 | 加载声音层 |
|-------------|-----------|
| 战斗/动作 | author-voice-battle |
| 情感高潮/离别/重逢 | author-voice-emotion |
| 日常/世界呼吸/荒诞 | author-voice-daily |
| 悬疑/揭秘/伏笔回收 | author-voice-mystery |
| 混合类型 | 主类型+辅助声音层 |

## 增量审计设计

### 为什么需要增量
百万字小说14卷，每卷15-20章。每次改几章就全量审计 = 浪费context和时间。

### 增量检测依据
- `git diff --stat` 计算变更比例
- 变更<30% → 增量（只审变更章+邻章）
- 变更≥30% → 全量
- 审计报告持久化在 `审阅报告/` 目录

### 审计报告的作用
- **断点续传**：下次审计时读取上次结果，未变更部分直接复用
- **变更追溯**：`修改记录` 表记录每次变更
- **问题追踪**：P0/P1问题的修复状态持续跟踪
