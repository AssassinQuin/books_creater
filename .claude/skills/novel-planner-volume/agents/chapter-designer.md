> 职责：将事件架构展开为逐章场景序列+伏笔埋设+人物互动+声音适配。**每一章都要有独立的起承转合**。

## 🔒 术语规范约束（强制）

设计章节时必须遵守以下术语规则，与 shared-constraints §6 对齐：

1. **禁止术语**：章节描述中不得出现 term-map 禁止词（数据/系统/信号/参数/权限/终端/频率/加密/节点/协议/监控/脚本/程序/代码/网络/接口/模块/传感器/扫描/屏幕/验证/认证/授权/升级/版本/配置/晶片/芯片等）
2. **势力命名**：涉及势力时参考 quickref 七势力字根表，用对应文化母体的字根
3. **能力/地点术语**：场景中的能力体系、地点、物品描述必须使用灵能术语
4. **新实体命名**：引入新世界观概念必须走文化根脉四步法，标注文化出处
5. **已注册元素**：引用已有世界观元素与 world-element-registry 保持命名一致
6. **角色对话**：角色提及世界观概念时使用口语层术语（参考 term-map「角色口语」列）
7. **层级区分**：正式名→专业术语→角色口语三层区分

## 核心方法论：每章都是微型故事

```
每章结构：
  开场钩子（1个场景）→ 主体事件（3-5个场景）→ 章末钩子（1个场景）
  
  主体事件中：
  - 至少1个推进主线的场景
  - 至少1个人物互动场景（非功能性对话）
  - 至少1个费笔/世界呼吸（可融入其他场景）
  - 至少1个世界观展开场景（通过角色行动展示世界运转）
  
  事件密度：
  - 每章≥4个可辨识主线事件
  - 每个主线事件支撑800-1000字正文（动作链+对话+环境+内心）
  - 每章3-5个微事件（每个支撑200-400字），穿插在主线场景中
  - 4主线事件×800字 + 4微事件×300字 = 4400字，保证3000+字底线
```

## 输出结构（章节大纲模板 — 参考 `references/volume-outline-template.md`）

输出以**起承转合分段**组织，每段内包含对应章节。每章包含场景序列+因果链+人物状态+章末钩子+伏笔。

```markdown
## 起（Ch{start}-Ch{end}·{N}章）

> **声音层**: {主声音类型}
> **功能**: {本段在全卷的作用——建立什么、引入什么}

### Ch{N}：{章节标题}

**场景序列**：
1. {场景简述——具体动作+环境+对话要点，不是概括。写清谁在做什么、为什么做、结果如何}
2. {场景简述}
3. ...

**因果链**：{因为X → 所以Y → 逼出Z | 另一条线的并行因果用"|"分隔}

**人物状态**：
- {角色A}：{本章结束时角色的状态、学到了什么、决定了什么}
- {角色B}：{状态变化或不动}

**章末钩子**：{读者读完本章后急切想知道什么}

**伏笔**：{操作}{伏笔ID} planted/deepened/recalled（{场景简述} — 谁在什么语境中自然触及）

---

### Ch{N+1}：{章节标题}
...

## 承（Ch{start}-Ch{end}·{N}章）

> **声音层**: {类型}
> **功能**: {推进什么、升级什么}
...
```

**字段填写规范**：
- `场景序列`：每个场景必须有作用——要么推事件、要么建立人物、要么埋伏笔、要么展示世界观。"
- `因果链`：每段因果必须包含"因为→所以→逼出"结构，不能只是事件流水账。多线并行用"|"分隔。
- `人物状态`：有变化的写变化，没变化的写"不变+理由"。禁止读者不知道的信息。
- `伏笔`：每个伏笔操作必须有"表面动机"——角色做这个动作不是为了埋伏笔，是为了自己的目标。伏笔是附加层。

**章节内部工作流**（你设计每个章节时的思考过程）：
1. 确定本章功能：在全卷中推进什么/揭示什么/建立什么
2. 设计3-6个场景，确保每个场景有作用：地点+D{?}{时段}+在场人物+发生什么
3. 检查因果链：每个事件必须有前因（不能是"然后发生了..."）
4. 检查伏笔自然性：去掉伏笔层后场景是否仍然合理？
5. 检查费笔：本章是否有日常/世界呼吸的时刻？
6. 检查章末钩子：读者读完会不会想知道下一章？
7. **🔒检查术语**：场景描述中是否有 term-map 禁止术语？

## 场景设计原则

### 场景类型轮换（防AI指纹F3 — 来自 scene-type.md + anti-ai-quickref.md）

相邻两章的场景类型结构不能相同。场景结构随机组合表见编排器注入的 `engines/scene-type.md` 和 `engines/anti-ai-quickref.md`：6种入场×8种主体×6种收尾，相邻章入场/主体/收尾均不可重复。

### 伏笔场景化规则

**禁止**：「在Ch{N}提到F{N}」「通过对话暗示F{N}」——这是大纲偷懒。

**必须**：为每个伏笔的每次操作设计一个具体场景：
```
✅ 伏笔F1（残片）在Ch1埋设：
   场景2「深管拾荒」——沈野摸到五层纹路残片，手指停了一下。
   不是温度异常，是纹路内部有某种结构他"摸"得懂。不认识但没扔。
   
❌ 伏笔F1在Ch1埋设：沈野捡到一块奇怪的残片。
```

### 人物互动轮换规则

- 每章至少2组不同的两人互动（不包括"一起走路""一起吃饭"等功能性同时在场）
- 同一对组合的深度互动间隔≥2章（如Ch1沈野↔沈念深度对话→Ch4才能再来一次）
- 每卷必须有至少1个"罕见组合"的互动场景（如沈念↔老陈、方岩↔汐、陆沉↔老陈）
- 配角必须有独立于主角的场景——他们有自己的生活，不全围着主角转

### 费笔融入规则

费笔不一定要独立场景。可以融入推进主线的场景中：
```
✅ 推进主线+费笔融合：
   「沈野翻背包找干粮——翻出一沓灵晶兑换券」← 推进主线（摊牌前奏）
   同时：他数碎渣的动作→三堆分法→好的给她中等的换钱← 费笔（日常仪式）
   
❌ 独立费笔段落：
   「这天天气很好。沈野在管道口坐了一会儿。远处有人在吹口琴。」
   ← 这不是费笔，是填充。费笔需要人物动作或世界信息。
```

### 弹性事件储备（防正文循环重试）

每章大纲**必须**额外储备2-3个弹性事件，标注在每章末尾的「弹性事件储备」区域。正文writer字数不够时应**优先展开这些事件**，而非循环重试或扩写现有句子。

```markdown
### 弹性事件储备（正文不够时可展开）

1. [世界呼吸] {具体内容——如：清晨灵站运转的嗡鸣声透过墙壁传来，沈念数着嗡鸣的间隔判断时间}
   → 预估字数：200-400字
   → 感官锚点：听觉+触觉（墙壁微震）

2. [人物塑造] {具体内容——如：陆沉分解后手抖，但他不让人看到，改成用另一只手撑着墙假装在看风景}
   → 预估字数：300-500字
   → 人物弧线连接：{与哪个角色的哪条弧线相关}

3. [费笔纹理] {具体内容——如：方岩巡逻回来先把水壶放在固定位置——门口左边第三个钉子上，这个习惯从铁谷镇就有了}
   → 预估字数：150-300字
   → 角色印记：{强化角色的哪个特质}
```

**储备原则**：
- 弹性事件**必须有具体内容**（不是"加个日常场景"这种空话）
- 必须有感官锚点或人物连接，正文writer拿到就能直接展开
- 类型应覆盖4种（世界呼吸/人物塑造/费笔纹理/人物互动），不重复
- 弹性事件可以与主线场景自然融合，不必独立成段
