# 卷级大纲设计 — 共享约束（供编排器注入Agent）

> 本文档是 novel-planner-volume 的共享约束标准源。所有 Agent 和 SKILL.md 引用此文件。
> **禁止复制约束内容到其他文件**。如需修改，只改本文件一处。
> 编排器通过 `skill_loader` 加载本文件，注入对应 Agent 上下文。

## 1. 事件驱动节奏铁律

1. **章节 = 事件单元**：章节由事件密度和情感张力驱动，不由日历驱动。一个精彩事件可占多章（如兽潮夜拆成兽潮前兆→降临→突围→善后），多天无聊日常可压缩成一章甚至一段过渡。
2. **非主角场景 = 暗面**：非主角视角场景必须标注"此时主角在做什么"。读者看到的是"主角不知道的暗面"。平行叙事（多POV同一时间）是合法且鼓励的叙事手法。
3. **时间跳跃 = 正常叙事**：事件弧结束后的时间跳跃是标准叙事手法（如"两周后""入冬了"）。同事件弧内（高潮/危机期间）时间线保持连续。跳跃超过1天需在章首用1-2句交代过渡，但不需要每章交代。
4. **场景时间标注**：每个场景必须写明"D{N}{时段}"，时段：凌晨/上午/中午/下午/傍晚/夜晚。时间标注服务于叙事清晰度，不是约束叙事节奏。
5. **主角戏份保底**：主角在场场景≥60%。主角缺席的场景必须有叙事功能。主角连续缺席超过2章需有叙事理由（如"支线视角章"），但不能超过3章。

## 2. 内容密度规则

1. **事件→字数映射**：每个可辨识事件支撑800-1000字正文。
2. **每章事件数下限**：≥4个主线事件。
3. **微事件**：每章3-5个，穿插在主线场景中。类型包括：日常仪式、角色特点变化、角色成长信号、支线伏笔、因果微链、世界呼吸真实感、配角专场。
4. **世界观展开**：每章至少1个场景通过角色行动展示世界运转。禁止设定旁白。
5. **伏笔因果逻辑**：每个伏笔操作必须回答"为什么这个角色在这个场景中自然接触到这个信息"。
6. **弹性事件储备（防正文循环重试）**：每章大纲必须额外储备2-3个**弹性事件**，标记为「正文不够时可展开」。类型涵盖：
   - **世界呼吸**：环境变化/天气/灵能异动/路人日常/城镇运作声/灵站运转细节（通过感官描写自然展开，每处支撑200-400字）
   - **人物塑造**：角色独处时的习惯动作/对某事物的独特态度/回忆碎片/生理反应（不推进主线但深化人物，每处支撑300-500字）
   - **费笔纹理**：看似无用但建立真实感的细节——整理背包的方式/数碎渣的手势/走路时踢石子/发呆时的视线落点（每处支撑150-300字）
   - **人物互动微场景**：非功能性对话——闲聊/争论小事/分享食物/抢被子/沉默中的默契（每处支撑400-600字）

   弹性事件**不是备选**，是大纲的正式组成部分。正文writer字数不够时优先展开这些事件，**不应重试生成或循环调用Agent**。

## 3. 伏笔自然设计规则（冰山理论）

**核心**：伏笔事件先有独立的表面动机（角色的自有目标），伏笔是附加层。

**方法**（先果后因）：
- 当前章节：事件自然发生，有充分的表面动机（拾荒换面/递水因为渴/看公告栏因为无聊）
- 后续章节：揭示更深层的原因，读者回看才发现铺垫

**三禁止转为正向指令**：
1. 角色每个动作源于角色自身目标——角色不知道自己是伏笔的载体
2. 通过角色行动和反应展示信息，作者不在旁白中替角色"解读"
3. 伏笔事件的表面动机必须独立自洽——去掉伏笔层后场景仍然合理

**自检**：如果去掉伏笔层，这个场景/事件是否仍然合理？是→伏笔是自然的附加层。否→伏笔是硬塞的。

## 4. 人物互动规则

1. 每个主要角色在卷内至少与2个不同角色有独立互动场景。
2. 禁止任何角色连续3章无出场或无独立动作。
3. 每卷至少1个"罕见组合"互动（如沈念↔老陈、方岩↔汐）。
4. 配角（老陈级及以上）至少1个独立于主角的场景。
5. 费笔配额 ≥ 总章数×1.0处（费笔=配角独立场景/世界呼吸/日常仪式/情绪留白）。

## 5. 巧合计规则

- 巧合计 ≤1次/卷，且必须有伏笔支撑。
- 所有"巧合"必须在发生后提供解释（此前埋过伏笔）。
- 角色关键行动必须是主动选择，非偶然相遇/巧合发现。

## 🔒 6. 术语规范约束（强制——所有Agent输出必须遵守）

本约束与以上1-5条同级，**不可跳过**。与 `lorecraft/SKILL.md`、`lorecraft/references/term-map.md`、`lorecraft/references/quickref.md`、`engines/world-element-registry.md` 配合使用。

### 6.1 禁止术语

所有产出中不得出现以下现代术语（含变体）：

| 类别 | 禁止术语 |
|------|---------|
| 计算机/IT | 数据/系统/信号/参数/权限/终端/频率/加密/解密/节点/协议/监控/脚本/程序/代码/网络/接口/模块/传感器/扫描/屏幕 |
| 行政/流程 | 验证/认证/授权/升级/版本/配置/注册/登录/注销/同步/异步 |
| 硬件/电子 | 晶片/芯片/处理器/存储/内存/带宽/传输/接收/发射 |
| 通用科技 | 分析/检测/记录/统计/数据库/文件/目录/路径/链接 |

完整映射表见 `lorecraft/references/term-map.md`（~60+条）。以上仅列常见项，Agent 必须加载完整映射表逐条核对。

### 6.2 替换对照

常见替换：数据→灵册、系统→灵枢体系、信号→灵能动静、权限→灵契、终端→灵枢、频率→灵息、加密→密纹、节点→灵枢/灵枢点

完整替换对照见 `lorecraft/references/term-map.md`。

### 6.3 势力字根

灵枢（官制+道家）、壁盾（兵家+墨家）、教会（拜占庭）、研究院（希腊+格物）、星火社（刺客+帮会）、猎人（市井+狩猎）、遗脉（巫祝+图腾）——详见 `lorecraft/references/quickref.md`

### 6.4 新术语流程

如需引入新世界观概念，必须走文化根脉四步法：
1. 概念解构：拆解概念的核心功能
2. 文化映射：寻找对应的文化母体（道家/兵家/墨家/巫祝/市井/拜占庭/希腊）
3. 组合筛选：用字根组合出候选名称
4. 验证测试：与已有术语无冲突、易读易记、有文化出处

### 6.5 已注册元素

引用已有世界观元素必须与 `engines/world-element-registry.md` 索引保持命名一致。不得对已有元素使用不同名称。

### 6.6 层级区分

正式名（道痕/灵契）→ 专业术语（道痕辨识/灵契准入）→ 角色口语（"他的印子"/"灵站的锁"），详见 `lorecraft/SKILL.md` 层积命名法。

### 6.7 写后自检

每个Agent输出前必须执行术语扫描：
1. 逐条扫描 §6.1 禁止术语清单
2. 检查势力描述是否使用 §6.3 字根
3. 检查新术语是否完成 §6.4 四步法
4. 检查已有元素是否与 world-element-registry 一致
5. 检查角色对话是否使用口语层术语
6. 发现违规立即替换，不得保留

**术语违规 = P1 问题**，必须在本轮验证结束前修复。
