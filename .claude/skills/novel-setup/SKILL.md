# 项目创建与世界观构建

## 触发
用户说"新建小说""建世界观""加设定""加物品"。

## 模式（问用户）
1. **新建项目** — 从零创建小说项目
2. **建世界观** — 为已有项目构建世界观维度
3. **加设定/物品** — 追加单个设定条目

## 约束层级（从高到低）

```
L0 基调锚（5轴）          ← 不可覆盖，所有内容的最高约束
L1 行为映射规则            ← 受L0约束，下游skill的执行标准
L2 氛围DNA（道德层+感官层）  ← 受L0约束，写作风格指导
L3 世界观维度              ← 受L0+L1约束
L4 品类规则                ← 受L0约束，不可覆盖L0
L5 写作执行规范             ← 受L0-L4约束
```

下游 skill 加载方式：
- `novel-write`：`get_chapter_context` 自动获取 L0-L2，L1 行为映射作为角色互动约束
- `novel-character`：`character_create` 的 decision_engine 字段获取 L1
- `novel-plan`：`world_query(category='core_setting')` 获取 L0-L1

## 新建项目

### Step 1: 项目创建
1. `novel_create(novel_name)` 建项目
2. 逐问深挖（画面/主角/情绪/对立面/独特规则，每次只问一个）
3. 用户确认决策卡 → `novel_update(status="worldbuilding")`

### Step 2: 创作宪法（可选但推荐）

在基调锚之前，明确 3-5 条**不可违反的创作铁律**。这些是比基调锚更高层的创作约束。

逐问用户（每次只问一条）：
- "这部小说绝对不能出现什么？"（如：主角无理由的英雄行为）
- "读者读完必须记住什么？"（如：代价永远是不可逆的）
- "什么类型的情节在这部小说中是禁忌？"（如：机械降神式解围）

用户确认后写入：
```
world_upsert(category='writing_spec', name='创作宪法', priority=100, is_constant=1,
  data={"rules": [...铁律列表...]})
```

`get_chapter_context` 自动加载 writing_spec 类别的 world_settings，下游 skill 无需额外修改。

### Step 3: 世界基调锚定（强制，氛围 DNA 的前置条件）

#### 2.1 逐轴确认（5 个道德维度）

按顺序逐轴向用户提问，每轴给出选项 + 具体含义 + 表现示例：

| 轴 | 选项 | 含义 | 表现示例 |
|----|------|------|---------|
| **道德底色** | 利他 / 中立 / 利己 | 多数人默认帮人还是害人？信任免费还是奢侈品？ | 利己：陌生人可能抢劫，商人能骗就骗 |
| **暴力密度** | 无 / 低 / 中 / 高 | 暴力是禁忌/工具/日常/生存必需？ | 高：杀人像吃饭一样普通 |
| **安全感** | 安全 / 脆弱 / 残酷 | 好人有好报吗？努力能改变命运吗？ | 残酷：穷人永无翻身之日 |
| **代价尺度** | 免费 / 等价 / 不对等 | 获得力量/知识/关系需要什么代价？ | 不对等：为了一点力量要付出一切 |
| **救赎弧线** | 必有 / 可选 / 罕见 / 不可能 | 坏人能变好吗？ | 不可能：死也不会改 |

**执行规则**：
- 每次只问 1 个轴，等用户选择后才问下一个
- 用户可以选选项之间的值（如"中偏高"），追问确定最接近选项
- 5 轴全部确认后，反问确认完整基调画像：列出所有轴选择，描述这组合意味着什么世界
- 用户确认后，立即写入 DB（不可跳过）

**DB 写入**：
```
world_upsert(category='core_setting', name='世界基调锚', priority=100, is_constant=1,
  data={moral_baseline, violence_density, safety, cost_scale, redemption})
```

#### 2.2 基调锚 → 行为映射规则（自动推导 + 用户确认）

基于 5 轴选择，自动推导行为映射规则表。此表是所有下游 skill 的**强制约束**。

**推导逻辑**：

| 基调轴 | 推导出的行为约束 |
|--------|----------------|
| 道德底色=利己 | NPC默认不帮陌生人，除非有利可图；互助行为必须附带动机 |
| 道德底色=中立 | NPC可帮可不帮，取决于利益计算；互助需要最小信任门槛 |
| 暴力密度=高 | 暴力是解决冲突的常规手段，非暴力解决需解释原因 |
| 暴力密度=低 | 暴力事件是重大转折，每次使用需充分铺垫 |
| 安全感=残酷 | "努力就能成功"叙事不可用；角色成功需解释额外因素 |
| 代价尺度=不对等 | 获得重要东西必须描写代价，代价远超常规预期 |
| 救赎弧线=不可能 | 反派立场不可逆，"被感动就改变"情节禁止使用 |

**每条规则格式**：
```
规则 {N}: {行为描述}
  条件: {触发条件}
  禁止: {什么写法与基调矛盾}
  示例: {符合基调的写法}
  违反: {违背基调的写法}
```

用户确认后写入 DB：
```
world_upsert(category='core_setting', name='行为映射规则', priority=99, is_constant=1,
  data={"rules": [...规则列表...]})
```

同步写入校验规则（供 `validate_chapter` 校验）：
```
writing_rule_upsert(rule_type='absence_check', name='基调一致-行为映射',
  category='world_tone', severity='warning',
  pattern='基调锚道德底色=利己时，正面行为必须附带动机或代价',
  message='行为与基调矛盾：在利己世界中，正面行为需要合理动机')
```

### Step 4: 氛围 DNA（基于基调锚构建）

基调锚确认后，分三层构建氛围：

**Layer 1 — 道德层（从基调锚推导，不可跳过）**
- 从5轴组合推导3-5个道德基调词（如"残酷""冷漠""丛林法则"）
- 硬校验：推导结果与基调锚矛盾时强制重推
- 用户确认 → `world_upsert(category='core_setting', name='氛围DNA-道德层')`

**Layer 2 — 感官层（在道德层框架内展开）**
1. 问用户：你的世界什么感觉？（时代/温度/参考作品）
2. 提取感官标签 → 对比道德层校验（温暖标签在残酷道德层下被拒绝）→ 用户确认
3. 基于基调锚生成1-2个感官锚点（基调锚自动约束感官方向）
4. 写1个参考片段（100-200字）→ 检查是否违反行为映射规则 → 用户确认 → 再写下一个（共2-3个）

**Layer 3 — 禁忌+词汇**
5. 生成禁忌清单 + 词汇色彩 → 用户确认
6. 汇总写入 `novels/{小说名}/设定/写作/world-atmosphere.md`

氛围DNA全部存DB（`world_upsert(category='core_setting')`），含道德层和感官层分离存储。

### Step 5: 世界观维度

逐维度展开，每维度用户确认后才继续：
种族 → 势力 → 地理 → 能力 → 经济 → 日常 → 历史 → 物品

**每个维度的生成都受基调锚约束**：
- 种族：不同种族间的偏见/冲突/等级是真实存在的
- 势力：势力的自私动机必须显式写出
- 经济：资源分配不公是常态，不是意外
- 日常：普通人的生存压力必须体现，不是背景板

每维度：`world_upsert` → 用户确认 → 下一维度。

### Step 6: 交叉验证

全部维度完成后跑 7 项验证：
1. **锚点稳固** — 核心锚点是否被后续设定动摇？
2. **稀缺真实** — 资源/能力/信任的稀缺性是否被合理维持？
3. **涟漪完整** — 每个改变是否都有涟漪效应？
4. **价值一致** — 所有价值观是否与基调锚一致？
5. **术语合规** — 是否违反术语规范？
6. **基调一致** — 所有设定是否与基调锚5轴矛盾？发现矛盾时输出具体矛盾描述
7. **行为映射覆盖** — 行为映射规则是否覆盖了所有主要场景？

验证不通过 → 逐项列出问题 → 用户确认修复方向 → 修改 → 重新验证。

### Step 7: 品类规则注入

根据小说品类，`writing_rule_upsert` 注入品类默认约束。这些规则可被小说级规则覆盖。

## 加设定/物品

`world_upsert` 写入 DB → `sync_db_to_files`。新设定必须与基调锚一致，不一致时警告用户。

## 约束
从 `world_settings` 和 `writing_rules` 加载当前小说的约束。高层覆盖低层。
- 基调锚是最高层约束，所有设定/人物/大纲必须遵守
- 基调锚的道德五轴在 `writing_rule_upsert` 中同步写入，供 `validate_chapter` 校验

## 完成后
问用户：设计人物 / 规划大纲 / 其他。
