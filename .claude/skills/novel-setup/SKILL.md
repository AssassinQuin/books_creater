# 项目创建与世界观构建

## 触发
用户说"新建小说""建世界观""加设定""加物品""继续""恢复""接着来""设定""世界观""新项目"。

## 恢复检测（所有模式的第一步）

触发时**必须先执行状态检测**，再决定路由：

```
检测序列（按顺序，全部只读）：
1. novel_get(novel_name) → 项目是否存在
2. world_query(novel_name, category='core_setting') → 世界原则/创作宪法/品类感知
3. world_query(novel_name, category='writing_spec') → 写作规范
4. 如文件存在：Read novels/{小说名}/设定/世界观/重构进度.md → 获取进度描述
```

**Step→DB 映射表**（判定哪些步骤已完成）：

| DB 条目 name | 对应 Step | 完成判定 |
|-------------|----------|---------|
| `品类感知` | Step 0 | 存在且 `data.genre_sense` 非空 |
| （项目 status='worldbuilding'） | Step 1 | novel_get 返回有效项目 |
| `创作宪法` | Step 2 | 存在且 `data.rules` 非空 |
| `世界原则` | Step 3 | 存在且 `data.principles` 非空 |
| `行为映射规则` | Step 3 | 存在（与世界原则同步写入） |
| `氛围DNA-道德层` | Step 4 Layer 1 | 存在 |
| `氛围DNA-感官层` | Step 4 Layer 2 | 存在 |
| `氛围DNA-禁忌与词汇` | Step 4 Layer 3 | 存在 |
| 各维度（ability/faction/location/...） | Step 5 | 逐条检查 name 是否存在 |

**断点定位**：扫描映射表，找到最后一个完成判定的条目 → 从下一个 Step 恢复。

**边界处理**：
- DB 条目存在但 `data` 为空 → 视为未完成，该步骤需重做
- Memory `flow-state` 与 DB 不一致 → **DB 为权威源**
- 项目不存在 → 进入新建项目模式

## 模式路由（状态检测后）

| 模式 | 触发词 | 路由逻辑 | 上下文注入 |
|------|--------|---------|-----------|
| **恢复** | "继续""恢复""接着来" | 状态检测 → 定位最高完成步骤 → 从下一步继续 | 已完成步骤 DB 数据摘要 + 重构进度.md 进行中段落 |
| **新建项目** | "新建小说" | 状态检测 → 项目不存在 → Step 0 | 无 |
| **建世界观** | "建世界观" | 状态检测 → **跳到首个未完成 step**（非固定 Step 3） | 已有 step 的 DB 数据；无世界原则则 Step 3，有部分维度则 Step 5 对应维度 |
| **加设定/物品** | "加设定""加物品" | 状态检测 → 快捷路径（始终可用） | 世界原则 + 行为映射 + 品类感知 |

## 上下文注入协议

恢复时**按断点 step 精准加载 DB 数据**，转化为精准引导语（非泛化问题）：

| 恢复到 | 必须加载 | 转化为 |
|--------|---------|--------|
| Step 3 | 品类感知 + novel_get | 排除与品类矛盾的探索方向 |
| Step 4 | 世界原则 + 行为映射 + 品类感知 + 参考研究（如有） | 衔接映射表预填充 + 参考模式预加载 |
| Step 5 | 世界原则 + 氛围DNA三层 + 品类感知 + 重构进度.md + 参考研究（如有） | 核心驱动已知时跳过 5A；讨论中内容直接唤醒；已有参考研究注入维度讨论 |
| Step 6 | 全部 core_setting + world_settings + 参考研究（如有） | 质疑点从已有数据推导 |
| Step 7 | 同 Step 6 | 验证清单预标注通过项 |

**首次 vs 恢复差异**（Step 5 示例）：
- 首次：`"你的世界，最核心的一个机制是什么？"`
- 恢复：`"以太作为核心驱动已确认。能力体系讨论中——你已确认魔晶经济和全职法师元素体系方向。上次你说'现在这个有点奇怪'，从哪个点继续调整？"`

**未写入 DB 的信息处理**：重构进度.md 中"已确认但未写入 DB"的决策视为有效约束注入上下文；"讨论中"段落直接作为恢复起点。

**断点持久化**：每步骤完成后**双写** — DB（权威源）+ 重构进度.md（人可读 + git 可跟踪）。Memory flow-state 仅作会话内辅助。

## 约束层级（从高到低）

```
L0 世界原则（推导得出）     ← 从用户愿景推导的不可违反原则
L1 行为映射规则            ← 从L0推导的写作约束
L2 氛围DNA（道德层+感官层）  ← 从L0推导的风格指导
L3 世界观维度              ← 从核心驱动辐射
L4 品类词汇                ← 词汇/风格参考，不限制可能性
L5 写作执行规范             ← 受L0-L4约束
```

## 全局保障：错误恢复协议

用户在任意步骤给出矛盾回答时，执行**矛盾处理三步法**：

**第一步：标记矛盾**
```
[矛盾] 新回答: "{用户当前回答}"
       已确认: "{先前确认的内容}"（Step {N}, 原则/维度: {名称}）
       冲突点: {具体矛盾}
```

**第二步：呈现选项**（三选一，不替用户决定）：
- A. 用新回答覆盖旧内容（列出受影响的下游设定）
- B. 保留旧内容，放弃新回答（说明放弃原因）
- C. 两者共存作为世界张力（说明张力如何运作）

**第三步：追溯修复**：若选 A（覆盖），列出所有受影响的下游设定，用户确认后执行。

**其他信号处理**：

| 信号 | 检测方式 | 恢复动作 |
|------|---------|---------|
| **用户不确定** | "不知道""没想好" | 回退到锚定问题 → 用场景替代抽象问题 |
| **用户拒绝所有** | "都不对""不是这样" | 确认反对范围 → 反对框架则切换探索角度；反对所有方向则暂停，建议用户先自由描述 |
| **提取歧义** | 同一句话推导出两条方向相反的原则 | 两条都展示 → 用户选择/合并/否定 → 不自行取舍 |

## 全局保障：参考作品研究协议（PP-3）

**核心规则：用户在任意步骤提到参考作品/设定时，必须主动执行研究流程，不得口头确认后跳过。**

### 触发检测

```
IF 用户说"参考{具体作品名}"（如"参考全职法师""像权游那样"）
  → 搜索模式
ELIF 用户说"参考我写的{文档/设定}"或提供了文件路径
  → 文件读取模式：Read 工具读取 → 提取结构模式
ELIF 用户说"参考{概念/体系}"（如"参考元素体系""类似升级体系"）
  → 知识蒸馏模式：基于已有知识提取概念的结构模式
ELSE 无法判断
  → 追问："你说的参考是指——A.一部具体作品 B.你自己写的设定文档 C.某个概念框架？"
  → 追问一次后用户仍未明确 → 默认走"知识蒸馏模式"并标注 verified: false
```

### R1: 信息获取（仅搜索模式触发）

优先 URL 模板（按顺序尝试，首个返回非空可解析内容即停）：
1. `ctx_fetch_and_index(url="https://zh.wikipedia.org/wiki/{作品名}")`
2. `searxng_web_search(query="{作品名} 设定 世界观 结构")` → `web_url_read` 前三个结果
3. `searxng_web_search(query="{作品名} novel setting analysis")` → 取最详细结果

**降级链**：
- 搜索无结果/不可靠 → 要求用户："请提供该作品最吸引你的3个结构特点（叙事/设定/氛围/角色/节奏），至少补充2个"
- 用户无法提供 → 标记 `verified: false`，后续仅作方向参考

### R2: 结构模式提取

从获取信息中提取 3-5 个结构模式：

```
模式 {N}: {模式名称}
  类型: 叙事节奏 | 氛围手法 | 设定结构 | 对话风格 | 能力体系 | 世界呈现
  描述: {一句话描述核心特征}
  原作例子: {具体表现}
  可迁移性: 高 | 中 | 低 — {原因}
```

**禁止提取**：角色名、数值体系、具体地名、关系网
**必须提取**：结构性的、可跨作品复用的模式

### R3: 变形适配

逐条检查模式与已确认的世界原则/品类感知的兼容性：

```
模式: {模式名}
  矛盾检测:
    - 与世界原则"{原则名}": 矛盾 / 兼容 / 需调整 — {依据}
    - 与品类感知: 矛盾 / 兼容 / 需调整 — {依据}
  变形决策:
    原作模式: {描述} → 变形方向: {如何适配}
    适配原因: {为什么这样变形}
    风险点: {可能的问题}
```

**变形原则**：矛盾时保留内核（结构原理），改变方向（具体实现）。与创作宪法矛盾 → 直接标记"不可采用"。

### R4: 独立验证（三项硬校验）

| # | 校验项 | 执行方法 | 通过标准 |
|---|--------|---------|---------|
| IV-1 | 认知独立 | 删除所有参考作品名后重读变形描述 | 不出现"像XX一样"等依赖原作认知的表述 |
| IV-2 | 名词独立 | 搜索变形描述中的专有名词 | 所有名词要么是本作已有设定，要么在本句内给出定义 |
| IV-3 | 自洽完整 | 移除参考来源标注后独立阅读 | 该维度设定完整、逻辑自洽 |

任一校验失败 → 返回 R3 重新变形，直到三项全部通过。

### R5: 持久化

```python
world_upsert(category='core_setting',
  name='参考研究-{作品名}',
  priority=80, is_constant=0,
  data={
    "type": "作品参考|文件参考|概念参考",
    "source": "{原始来源}",
    "verified": True|False,
    "patterns": [
      {"name": "模式名", "type": "类型", "description": "描述",
       "adaptation": "变形适配说明", "iv_status": "通过|失败"}
    ],
    "independent_check": {
      "cognitive": True|False,   # IV-1
      "nomenclature": True|False, # IV-2
      "self_contained": True|False # IV-3
    }
  }
)
```

后续步骤通过 `world_query(category='core_setting')` 自动加载，不重复研究。

### 多参考冲突检测

当用户提到多个参考作品时，提取所有模式后执行：

```
对每对参考(A, B)：
  IF A的模式与B的模式在核心结构上矛盾
    → 列出矛盾点 → 用户选择：
      1. 以A为主，B仅取不矛盾的局部
      2. 以B为主，A仅取不矛盾的局部
      3. 两者融合（用户描述融合方式）
      4. 只用一个
```

### 协议调用时机

| 步骤 | 触发时机 | 输出注入点 |
|------|---------|-----------|
| Step 1 | 愿景深挖时用户提到参考 | 蒸馏结果注入后续深挖 |
| Step 3 | 原则推导时用户提到参考 | R3矛盾检测用世界原则；如世界原则未确认→R3推迟到Step 4 |
| Step 4 Layer 2 | 感官层讨论 | 已有研究→复用模式；无则触发完整协议 |
| Step 5 | 核心驱动描述或维度展开时 | DB中参考模式注入维度讨论 |
| 快捷路径 | 用户提到参考作品/设定来源 | 触发协议后继续因果链校验 |

### 禁止行为

- 收到参考作品名后只回复"收到""好的"而不执行 R1-R5
- 跳过蒸馏(R2)直接进入适配(R3)
- 研究完成后不持久化到 DB
- 将未验证的参考(verified:false)当作可靠约束使用

## 会话预算

| 步骤 | 简短对话 | 深度构建 | 断点建议 |
|------|---------|---------|---------|
| Step 0 品类感知 | ~2K | ~4K | 品类确认后 |
| Step 1 项目创建 | ~2K | ~6K | 决策卡确认后 |
| Step 2 创作宪法 | ~1K | ~3K | 每条铁律确认后 |
| Step 3 世界基调 | ~4K | ~12K | 3A/3B/3C/3D 各子步骤 |
| Step 4 氛围DNA | ~3K | ~8K | Layer 1/2/3 各层 |
| Step 5 维度展开 | ~4K | ~15K | 每个维度确认后 |
| Step 6 创造性对抗 | ~2K | ~5K | 每项质疑后 |
| Step 7 交叉验证 | ~2K | ~6K | 每组验证后 |

单步骤超过 8 轮对话 → 输出状态摘要 → 暂停。断点已由顶部"恢复检测"协议管理（DB 权威 + 重构进度.md 双写）。会话内可写 Memory flow-state 作为快速恢复辅助，但 DB 是唯一权威断点源。

## 新建项目

### Step 0: 品类感知（前置，仅做词汇参考）

**品类不限制世界可能性，只提供词汇和风格参考。**

1. 根据用户描述感知品类方向（玄幻/仙侠/都市/西幻/末日/科幻/混搭/其他）
2. 告知用户："我感知到这偏向{品类}方向。这个品类的常见词汇风格是{概述}——但你可以完全打破它。"
3. 用户确认品类方向或修正 → 写入 DB：
   ```
   world_upsert(category='core_setting', name='品类感知', priority=50, is_constant=0,
     data={"genre_sense": "...", "vocabulary_style": "...", "user_stance": "遵循/颠覆/混搭"})
   ```
4. 后续生成中：品类词汇用于替换不合适的表达（如玄幻不说"数据库"），但不用于限制世界观的可能性

### Step 1: 项目创建

1. `novel_create(novel_name)` 建项目
2. **用开放式问题深挖**（每次只问一个，追问到有画面感为止）：
   - "闭上眼睛——你最先想到的画面是什么？谁在做什么？"
   - "这个画面里最让你不舒服/不安的是什么？"（找到张力）
   - "如果读者只能记住这个世界的**一件事**，你希望是什么？"
   - "这个世界的规则里，有什么是'理所当然'但其实很残酷的？"（找到暗面）
   - "你想写的这个故事，核心矛盾是什么——谁和谁之间，因为什么？"
   - "有没有哪部作品让你觉得'我想写的就是这种感觉'？"（捕获参考信号）
3. **参考研究拦截**：深挖中用户提到参考作品/设定时 → 触发"参考作品研究协议"→ 蒸馏结果注入后续愿景深挖
4. 用户确认决策卡 → `novel_update(status="worldbuilding")`

### Step 2: 创作宪法（可选但推荐）

3-5 条不可违反的创作铁律。

逐问（每次一条）：
- "这部小说绝对不能出现什么？"
- "读者读完必须记住什么？"
- "什么类型的情节是禁忌？"

用户确认后写入：
```
world_upsert(category='writing_spec', name='创作宪法', priority=100, is_constant=1,
  data={"rules": [...铁律列表...]})
```

### Step 3: 世界基调发现（核心步骤——发现，不是选择）

**这个步骤的目的是从用户的描述中推导出世界原则，不是让用户从菜单中选择。**

**参考研究拦截**：用户在原则推导中提到参考作品时 → 触发"参考作品研究协议"。如世界原则尚未确认，R3(变形适配)推迟到 Step 4，将 R2 蒸馏结果暂存。

#### 3A: 自由探索（3-5个开放式问题）

用这些问题引导用户表达他们心中的世界（不是所有问题都问，选最相关的3-5个）：

| 问题 | 目的 | 捕获什么 |
|------|------|---------|
| "这个世界最让你着迷的一点是什么？" | 核心吸引力 | 世界的独特卖点 |
| "普通人早上醒来最怕什么？" | 生存压力 | 安全感/权力结构 |
| "这个世界的'不可能'是什么？" | 边界和禁忌 | 什么绝不能发生 |
| "如果用一种味道形容你的世界？" | 感官基调 | 氛围方向 |
| "什么东西在这里是奢侈品？" | 稀缺性 | 经济/资源逻辑 |
| "两个陌生人相遇，第一反应是什么？" | 人际信任 | 道德底色 |
| "获得力量的代价是什么？——真的值得吗？" | 获得成本 | 代价尺度 |
| "一个人能真正改变自己吗？" | 救赎可能 | 人物弧线空间 |
| "这个世界的'理所当然'里，哪个其实最不合理？" | 隐藏矛盾 | 深层张力 |

#### 3B: 原则提取（从描述中推导）

从用户的回答中提取 3-7 条世界原则。**每条原则必须有来源和原因，不能凭空生成。**

```
原则 {N}: {一句话陈述}
  来源: "用户说了'{原文引用}'"
  推导: {从原文怎么推导出这个原则}
  含义: {这个原则对写作意味着什么}
  禁止: {什么写法违反这个原则}
  因果类型: 物理规则 | 社会规则 | 心理机制
```

**因果类型分类标准**：
- **物理规则**：世界的基础物理/自然规律（如"灵气浓度决定修炼上限"）
- **社会规则**：由社会结构/文化/权力产生的规则（如"强者垄断修炼资源"）
- **心理机制**：由人性/心理产生的规则（如"恐惧催生服从"）
- 一条原则可标注多个类型，但要标注主类型

**提取规则**：
- 不要从预设的5轴（道德/暴力/安全/代价/救赎）出发，而是从用户描述中自然涌现
- 用户说"弱肉强食"→ 提取"力量决定地位"原则，标注因果类型=社会规则，不要贴"道德底色=利己"标签
- 用户说"修炼要付出代价"→ 提取"力量有价"原则，因果类型=物理规则+心理机制
- 如果用户描述中有矛盾（"大家互相帮助"但"弱肉强食"），触发错误恢复协议

#### 3C: 挑战与矛盾检测（创造性对抗）

对提取的原则逐一检查：

**矛盾检测**：
- 原则之间是否矛盾？（"信任靠长期积累" vs "世界充满背叛"）
- 与品类惯例是否矛盾？（用户说颠覆但没说怎么颠覆）
- 与创作宪法是否矛盾？

**偷懒检测**：
- 这个原则是从用户描述推导的，还是从品类默认设定照搬的？
- "因为{品类}都是这样"不是理由。用户有独特表达吗？

**挑战格式**：
```
发现: {矛盾/偷懒/模糊}
  原则A: {描述}
  原则B: {描述}
  张力: {两者如何共存？需要用户解释}
  或者: {替代方案，不一定要矛盾}
```

用户决定：解释共存逻辑 / 修改其中一条 / 接受矛盾作为世界张力

#### 3D: 确认定锚

所有原则经过挑战后，用户最终确认 → 写入 DB：
```
world_upsert(category='core_setting', name='世界原则', priority=100, is_constant=1,
  data={"principles": [
    {"name":"...", "source":"用户说了...", "implies":"...", "forbids":"...", "causal_type":"..."},
    ...
  ]})
```

同步写入行为映射规则（供 `validate_chapter` 使用）：
```
world_upsert(category='core_setting', name='行为映射规则', priority=99, is_constant=1,
  data={"rules": [...从原则推导的行为约束...]})
```

### Step 4: 氛围 DNA（从世界原则显式映射）

**Step 3→4 衔接规则**：氛围DNA不是凭空创作，必须从已确认的世界原则逐条映射。

**衔接映射表**（Step 4 开始前**必须**填写，未填写不可进入 Layer 1）：

| 世界原则（Step 3） | 氛围DNA层 | 推导方向 |
|-------------------|-----------|---------|
| {原则1名称} | Layer 1 道德层 | 该原则暗示什么道德基调？ |
| {原则2名称} | Layer 2 感官层 | 该原则暗示什么感官体验？ |
| {原则N名称} | Layer 3 禁忌+词汇 | 该原则暗示什么禁止表达？ |

**硬校验**：如果某条世界原则无法映射到任何氛围层 → 标记为"未落地原则" → 用户决定：补充映射 or 删除该原则

#### Layer 1 — 道德层（从世界原则推导）
- 从映射表中逐条推导道德基调词
- 推导格式：`基调词 ← 原则{N}({原则名})，因为{推导逻辑}`
- 硬校验：推导结果与世界原则矛盾时强制重推
- 用户确认 → `world_upsert(category='core_setting', name='氛围DNA-道德层')`

#### Layer 2 — 感官层
1. 问用户："用一种味道/温度/颜色形容你的世界？"
2. 从回答提取感官标签 → 与道德层交叉校验（温暖标签在残酷道德层下需解释）
3. **参考研究处理**：
   - 如 DB 中已有参考研究（前序步骤触发过协议）→ 加载蒸馏结果 → 复用模式，仅做本层适配验证
   - 如无但用户在本步骤提到参考作品 → 触发"参考作品研究协议"完整执行 R1-R5
   - 参考片段（100-200字）必须使用 R3 变形后的模式（非原作模式）
4. 检查参考片段是否违反行为映射规则 → 用户确认 → `world_upsert(category='core_setting', name='氛围DNA-感官层')`

#### Layer 3 — 禁忌+词汇
4. 生成禁忌清单 + 词汇色彩 → 每条禁忌标注违反哪条世界原则
5. 汇总写入 `novels/{小说名}/设定/写作/world-atmosphere.md`

### Step 5: 世界观维度（从核心驱动辐射）

**不是8个独立决策表，而是从核心驱动向外辐射的有机网络。**

#### 5A: 核心驱动识别

问用户：
- "你的世界，最核心的一个机制/规则/力量是什么？其他所有东西都围绕它转。"
- 这个核心驱动是所有维度的锚点

**参考研究拦截**：如用户描述核心驱动时引用参考作品（如"参考全职法师的元素体系"）→ 触发"参考作品研究协议"→ 蒸馏结果用于维度展开的灵感参考

确认核心驱动后，**用它推导维度优先级**：

| 核心驱动类型 | 最先展开的维度 | 为什么 |
|-------------|--------------|--------|
| 力量/能力体系 | 能力 → 势力 → 经济 | 能力是核心，决定势力格局 |
| 种族矛盾 | 种族 → 势力 → 地理 | 种族对立决定势力分布 |
| 资源稀缺 | 经济 → 势力 → 日常 | 资源分配驱动一切 |
| 环境压力 | 地理 → 能力 → 经济 | 环境决定生存方式 |
| 信息不对称 | 势力 → 能力 → 历史 | 谁控制信息谁掌权 |

#### 5B: 辐射式展开（每个维度四轮循环）

对每个维度执行：

**前置：参考模式复用检查**
- `world_query(novel_name, category='core_setting')` 检索参考研究条目
- 如有相关参考模式 → 注入上下文，标注可借鉴的模式及变形适配说明
- 如有 `verified: false` 条目 → 标注"参考意图未验证，仅作方向参考"

**第一轮：从核心驱动推导**
- "如果{核心驱动}存在，那{维度}会怎样？"
- 找出核心驱动对该维度的直接影响

**第二轮：与已完成维度交叉**
- "这和{已完成的维度}有什么矛盾？有什么强化？"
- 发现维度间的有机联系

**第三轮：挑战与确认**
- 质疑："这是从核心驱动自然推导的，还是品类默认设定？"
- 挑战："{维度}的设定会不会让{核心驱动}变得不合理？"
- 挑战："有没有更极端/更有趣的可能性？"

**第四轮：参考适配检查（仅当参考研究已执行时）**
- 从 DB 加载的参考模式中，找出与本维度相关的模式
- 逐条检查：维度设定是否体现了变形后的模式方向？未体现是刻意避开还是遗漏？
- 如发现新矛盾 → 触发"多参考冲突检测"重新评估

用户确认 → `world_upsert` → 下一维度

#### 5C: 维度间健康检查

全部维度完成后：
- 画因果图：核心驱动→各维度→维度间影响，标注每条边的因果类型
- 找孤立维度：有维度与核心驱动无关吗？为什么？
- 找冲突：维度A的推论和维度B的推论矛盾吗？

#### 5D: 维度自检（每维度写入 DB 前必输出具体证据）

- 因果链：列出"{核心驱动}→{维度}的影响路径"，至少1条，标注因果类型
- 基调一致：逐条对照Step 3世界原则，哪条通过/需调整
- 题材词汇：检查了X处术语，Y处替换为品类词汇
- 参考独立：如有参考，执行 R4 的 IV-1/IV-2/IV-3 三项校验，输出通过/失败状态
- 参考适配度：如有参考研究与本维度相关，逐条标注已变形/未变形/已删除

### Step 6: 创造性对抗（全局）

**在交叉验证前执行。挑最相关的1-2个质疑点。**

| # | 检查项 | 示例 |
|---|--------|------|
| 1 | 原则内部矛盾 | 用户说了A也说了B——这两者如何共存？ |
| 2 | 维度缺失 | 哪些维度过于单薄无法支撑后续写作？ |
| 3 | 便利设定 | "为了让剧情方便"而非从核心驱动推导的设定？ |
| 4 | 核心驱动漏洞 | 核心驱动有被轻易绕过的路径吗？ |
| 5 | 惯性复制 | 有设定是从品类/参考作品照搬而非用户独特愿景？ |
| 6 | 参考可靠性 | 是否有未验证的参考(verified:false)被当作可靠约束使用？参考研究是否过度依赖导致世界观不自洽？ |

**对抗输出**：
```
质疑: {具体质疑}
  原因: {为什么可能是问题}
  替代方案: {1-2个改进方向}
  保留理由: {如果保留，需要什么条件来让自洽}
```

用户选择：采纳 / 保留+补充理由 / 驳回

### Step 7: 交叉验证

| # | 验证项 | 检查内容 | 失败动作 |
|---|--------|---------|---------|
| 1 | 原则稳固 | 世界原则是否被后续设定动摇？ | 修改动摇设定 |
| 2 | 核心驱动贯穿 | 核心驱动是否辐射到所有维度？ | 补充辐射路径 |
| 3 | 因果完整 | 每个关键设定是否有充分前因？标注因果类型？ | 补充因果链 |
| 4 | 维度联动 | 维度间是否有有机联系而非独立？ | 补充联动 |
| 5 | 品类词汇 | 是否有不符合品类风格的表述？ | 替换词汇 |
| 6 | 参考独立 | R4 的 IV-1/IV-2/IV-3 是否全部通过？ | 返回 R3 重新变形 |
| 7 | 参考冲突 | 所有参考研究的冲突是否已解决？变形适配是否与所有维度一致？ | 重新执行冲突检测 |
| 8 | 参考完整性 | 所有提到的参考作品是否都完成了蒸馏+适配？ | 补充研究 |
| 9 | 宪法一致 | 是否违反创作宪法？ | 修正 |
| 10 | 稀缺真实 | 核心稀缺是否被合理维持？ | 补充稀缺机制 |
| 7 | 宪法一致 | 是否违反创作宪法？ | 修正 |
| 8 | 稀缺真实 | 核心稀缺是否被合理维持？ | 补充稀缺机制 |

验证不通过 → 逐项列出问题 → 用户确认修复方向 → 修改 → 重新验证。

## 加设定/物品（快捷路径）

**前置条件**：目标小说已存在且有世界原则。

1. 加载世界原则 + 行为映射 + 品类感知 + 参考研究（如有）（`world_query`）
   - `world_query` 返回空 → 提示用户先执行 Step 3 建立世界原则，或确认极简模式（直接写入，标注 `priority: 10`）
2. 收集用户要加的设定/物品信息
3. **参考研究拦截**：用户提到参考作品/设定来源时 → 触发"参考作品研究协议"
4. **因果链校验**（逐项检查，标注因果类型）：
   - **物理规则一致**：设定是否违反已确认的物理规则？（如灵气体系下不能出现无灵气的科技）
   - **社会规则一致**：设定是否违反社会结构推论？（如弱肉强食世界不应有无条件慈善组织且无解释）
   - **心理机制一致**：设定是否违反人物心理预期？（如恐惧催生服从的世界不应有大量无畏牺牲而无动机）
5. 每项校验输出：`{校验项}: {通过/失败} ({因果类型}) — {具体说明}`
6. 不一致时列出具体矛盾（引用违反的原则+因果类型） → 用户决定覆盖还是调整
7. 新设定覆盖已有设定 → 展示新旧对比，触发矛盾处理三步法
8. `world_upsert` 写入 → `sync_db_to_files`

## 约束
从 `world_settings` 和 `writing_rules` 加载当前小说的约束。高层覆盖低层。
- 世界原则是最高层约束，所有设定/人物/大纲必须遵守
- 每条约束都有来源（从用户描述推导），不是预设标签
- 品类是词汇参考，不限制世界观可能性
