# 项目创建与世界观构建

## 触发
用户说"新建小说""建世界观""加设定""加物品"。

## 模式路由

| 模式 | 触发词 | 起始步骤 | 跳过 |
|------|--------|---------|------|
| **新建项目** | "新建小说" | Step 0 | 无 |
| **建世界观** | "建世界观" | Step 0（仅品类）→ Step 3 | Step 1-2 |
| **加设定/物品** | "加设定""加物品" | 快捷路径 | 全部 |

## 约束层级（从高到低）

```
L0 基调锚（5轴）          ← 不可覆盖，所有内容的最高约束
L1 行为映射规则            ← 受L0约束，下游skill的执行标准
L2 氛围DNA（道德层+感官层）  ← 受L0约束，写作风格指导
L3 世界观维度              ← 受L0+L1约束
L4 品类规则                ← 受L0约束，不可覆盖L0
L5 写作执行规范             ← 受L0-L4约束
```

下游 skill 加载方式：
- `novel-write`：`get_chapter_context` 自动获取 L0-L2，L1 行为映射作为角色互动约束
- `novel-character`：`character_create` 的 decision_engine 字段获取 L1
- `novel-plan`：`world_query(category='core_setting')` 获取 L0-L1

## 新建项目

### Step 0: 品类识别（前置，强制）

**在世界观构建之前先确定品类。品类约束贯穿后续所有步骤。**

1. 根据用户描述判断品类（玄幻/仙侠/都市/西幻/末日/科幻/其他）
2. 注入品类默认约束：`writing_rule_upsert` 注入品类默认规则（可被小说级规则覆盖）
3. 向用户展示品类典型惯例清单，逐条确认保留/修改/抛弃：
   - "这个品类读者通常期待什么？"
   - "你想遵循哪些惯例，颠覆哪些？"
4. 用户确认后写入 DB：
   ```
   world_upsert(category='core_setting', name='品类', priority=95, is_constant=1,
     data={"genre": "...", "conventions_kept": [...], "conventions_subverted": [...]})
   ```
5. 输出品类约束摘要，后续每步开始时展示品类约束提醒

**为什么前置**：品类决定维度优先级和展开方式。仙侠优先能力体系，西幻优先种族势力。后置会导致世界观维度缺乏品类约束，产生现代感。

### Step 1: 项目创建
1. `novel_create(novel_name)` 建项目
2. 逐问深挖（画面/主角/情绪/对立面/独特规则，每次只问一个）
3. 用户确认决策卡 → `novel_update(status="worldbuilding")`

### Step 2: 创作宪法（可选但推荐）

明确 3-5 条**不可违反的创作铁律**。比基调锚更高层的创作约束。

逐问用户（每次只问一条）：
- "这部小说绝对不能出现什么？"（如：主角无理由的英雄行为）
- "读者读完必须记住什么？"（如：系统比任何人都大）
- "什么类型的情节在这部小说中是禁忌？"（如：机械降神式解围）

用户确认后写入：
```
world_upsert(category='writing_spec', name='创作宪法', priority=100, is_constant=1,
  data={"rules": [...铁律列表...]})
```

### Step 3: 世界基调锚定（强制，氛围 DNA 的前置条件）

#### 3.1 逐轴确认（5 个道德维度）

按顺序逐轴向用户提问，每轴给出选项 + 具体含义 + **品类适配示例**：

| 轴 | 选项 | 含义 | 玄幻示例 | 都市示例 | 西幻示例 |
|----|------|------|---------|---------|---------|
| **道德底色** | 利他/中立/利己 | 默认帮人还是害人？ | 利己：宗门内斗抢资源 | 中立：帮人有条件 | 利己：异族之间零信任 |
| **暴力密度** | 无/低/中/高 | 暴力是禁忌/工具/日常？ | 高：杀妖兽像吃饭 | 低：暴力是重大转折 | 中：战斗是职业 |
| **安全感** | 安全/脆弱/残酷 | 好人有好报吗？ | 残酷：底层永无翻身 | 脆弱：努力有机会但代价大 | 脆弱：秩序表面下暗流涌动 |
| **代价尺度** | 免费/等价/不对等 | 获得力量需要什么？ | 不对等：突破要付出寿元 | 等价：交易公平 | 不对等：魔法消耗生命力 |
| **救赎弧线** | 必有/可选/罕见/不可能 | 坏人能变好吗？ | 罕见：心魔难除 | 可选：人有复杂性 | 不可能：阵营不可逆 |

**执行规则**：
- 每次只问 1 个轴，等用户选择后才问下一个
- 用户可选选项之间的值，追问确定最接近选项
- 5 轴全部确认后，反问确认完整基调画像
- 用户确认后立即写入 DB

**DB 写入**：
```
world_upsert(category='core_setting', name='世界基调锚', priority=100, is_constant=1,
  data={moral_baseline, violence_density, safety, cost_scale, redemption})
```

#### 3.2 基调锚 → 行为映射规则（自动推导 + 用户确认）

基于 5 轴选择，自动推导行为映射规则表。

**推导逻辑**：

| 基调轴 | 推导出的行为约束 |
|--------|----------------|
| 道德底色=利己 | NPC默认不帮陌生人，除非有利可图；互助行为必须附带动机 |
| 道德底色=中立 | NPC可帮可不帮，取决于利益计算；互助需要最小信任门槛 |
| 暴力密度=高 | 暴力是解决冲突的常规手段，非暴力解决需解释原因 |
| 暴力密度=低 | 暴力事件是重大转折，每次使用需充分铺垫 |
| 安全感=残酷 | "努力就能成功"叙事不可用；角色成功需解释额外因素 |
| 代价尺度=不对等 | **仅限**核心获得（力量突破/关键情报/重要关系建立）必须附带代价。**代价分级**：A级（不可逆损失）用于重大突破，B级（长期负担）用于中等获得，C级（即时痛苦）用于小额获得。**不适用于**日常交易/地理环境/种族特征/历史背景。 |
| 救赎弧线=不可能 | 反派立场不可逆，"被感动就改变"情节禁止使用 |

**每条规则格式**：
```
规则 {N}: {行为描述}
  条件: {触发条件}
  作用域: {适用哪些场景/维度} | {排除哪些场景/维度}
  禁止: {什么写法与基调矛盾}
  示例: {符合基调的写法}
  违反: {违背基调的写法}
```

用户确认后写入 DB：
```
world_upsert(category='core_setting', name='行为映射规则', priority=99, is_constant=1,
  data={"rules": [...规则列表...]})
```

同步写入校验规则（供 `validate_chapter` 校验）：
```
writing_rule_upsert(rule_type='absence_check', name='基调一致-行为映射',
  category='world_tone', severity='warning',
  pattern='基调锚道德底色=利己时，正面行为必须附带动机',
  message='行为与基调矛盾：在利己世界中，正面行为需要合理动机')
```

### Step 4: 氛围 DNA（基于基调锚构建）

#### Layer 1 — 道德层（从基调锚推导，不可跳过）
- 从5轴组合推导3-5个道德基调词
- 硬校验：推导结果与基调锚矛盾时强制重推
- 用户确认 → `world_upsert(category='core_setting', name='氛围DNA-道德层')`

#### Layer 2 — 感官层（在道德层框架内展开）
1. 问用户：你的世界什么感觉？（时代/温度/参考作品）
2. 提取感官标签 → 对比道德层校验 → 用户确认
3. 基于基调锚生成1-2个感官锚点

**参考作品处理（用户提到参考作品时，强制3步）**：

| 步骤 | 操作 | 输出 |
|------|------|------|
| **提取模式** | 从参考作品提取3-5个结构模式（叙事节奏/氛围手法/设定结构/对话风格），**不提取具体名称/数值/关系网** | 模式列表 |
| **变形适配** | 逐条检查模式是否与基调锚5轴矛盾 → 矛盾的变形保留内核改方向 → 兼容的直接采用。输出：`原作模式 → 变形方向 → 适配原因 → 风险点` | 变形方案 |
| **独立验证** | 三项检查：① 不依赖读者对原作认知 ② 不引用原作特有名词而未重新定义 ③ 删除参考作品名后本作设定仍完整自洽 | 通过/打回重变形 |

4. 写1个参考片段（100-200字）→ 检查是否违反行为映射规则 → 用户确认
5. 再写下一个（共2-3个）

#### Layer 3 — 禁忌+词汇
6. 生成禁忌清单 + 词汇色彩 → 用户确认
7. 汇总写入 `novels/{小说名}/设定/写作/world-atmosphere.md`

氛围DNA全部存DB（`world_upsert(category='core_setting')`），含道德层和感官层分离存储。

### Step 5: 世界观维度（8张决策表 + 四步循环）

**维度优先级由 Step 0 品类决定**：

| 品类 | 优先展开 | 原因 |
|------|---------|------|
| 仙侠/玄幻 | 能力 → 势力 → 种族 | 能力体系是核心爽点 |
| 西幻 | 种族 → 势力 → 能力 | 种族矛盾通常是主线 |
| 都市 | 势力 → 经济 → 日常 | 社会结构决定冲突形态 |
| 科幻 | 能力 → 经济 → 历史 | 技术决定社会形态 |
| 末日 | 地理 → 能力 → 经济 | 环境决定生存方式 |
| **其他** | **动态推断 → 向用户确认** | **无法归类时，根据用户描述推断最相关维度，向用户确认推断结果和优先级** |

**四步循环（每个维度通用）**：

| 步骤 | 动作 | 输出 |
|------|------|------|
| 1. 先问 | 向用户提出该维度的核心问题（见下表） | 用户回答 |
| 2. 生成 | 基于回答+基调约束+品类约束，执行4步方法论（见下），生成维度设定 | 维度设定草稿 |
| 3. 质疑 | 主动列出潜在矛盾（与基调/行为映射/其他维度），问用户是否接受 | 质疑清单+用户决策 |
| 4. 确认 | 用户确认 → `world_upsert` 写入 → 下一维度 | DB记录 |

**维度生成4步方法论（Step 2 内部执行，每个维度必做）**：

| # | 步骤 | 操作 |
|---|------|------|
| 1 | **因果构建** | 该维度的核心因果关系是什么？（如：因为资源稀缺→所以势力争夺→所以普通人被压榨） |
| 2 | **相互影响** | 该维度如何影响/受影响于已完成的其他维度？（如：能力体系受经济制约，势力分布受地理决定） |
| 3 | **题材适配** | 生成内容是否符合品类词汇和风格？（如：玄幻不说"数据库"，科幻不说"灵气"） |
| 4 | **基调校验** | 该维度设定是否与基调锚5轴一致？（如：安全感=残酷时，不能生成"人人平等"的经济体系） |

**各维度核心问题表**：

| 维度 | 核心问题 | 基调锚约束要点 |
|------|---------|--------------|
| 种族 | 种族之间为什么有矛盾？资源/信仰/历史/生理差异？ | 不同种族间的偏见/等级是真实存在的 |
| 势力 | 每个势力真正想要什么？（不是"为了正义"） | 自私动机必须显式写出 |
| 地理 | 地理环境如何影响势力分布和资源分配？ | 地理与能力/经济必须有因果关系 |
| 能力 | 力量的边界是什么？什么代价？（仅代价尺度≠免费时追问） | 能力边界必须有物理/逻辑限制 |
| 经济 | 谁有资源？谁没有？为什么不公平？ | 资源分配不公是常态不是意外 |
| 日常 | 普通人的一天是什么样的？他们害怕什么？ | 生存压力必须体现，受品类词汇约束 |
| 历史 | 什么事件塑造了现在的世界格局？ | 重大历史事件必须有因果链 |
| 物品 | 稀有物品为什么稀有？谁控制流通？ | 物品与经济/能力/势力体系一致 |

**维度自检清单（每维度写入 DB 前必查，每项必须输出具体证据）**：
- 题材词汇合规：检查了 X 处术语，Y 处替换为品类词汇
- 因果链完整：列出"因为→所以"链条（至少1条），不能是孤立设定
- 基调锚一致：逐轴检查，哪轴通过/哪轴需要调整
- 参考作品独立：如有参考，列出通过/未通过的检查项

### Step 6: 创造性对抗（反驳机制）

**在交叉验证前执行一次全局对抗。**

目的：主动质疑用户决策中的潜在问题，避免线性模式导致的浅薄结果。

**对抗执行规则**：
- 对抗不是否定用户，而是提供替代视角
- 每次只挑 1-2 个最有价值的质疑点
- 质疑必须有建设性替代方案，不能只说"这样不行"

**对抗检查清单**（选择最相关的 1-2 条）：

| # | 检查项 | 示例 |
|---|--------|------|
| 1 | 基调内部矛盾 | 安全感=残酷 但 救赎弧线=必有——如何自洽？ |
| 2 | 维度缺失 | 哪些维度过于单薄无法支撑后续写作？ |
| 3 | 品类违和 | 灵气复苏中出现魔法学院？ |
| 4 | 便利设定 | "为了让剧情方便"而非从基调推导出的设定？ |
| 5 | 稀缺性漏洞 | 核心稀缺资源有轻易绕过的路径？ |

**对抗输出格式**：
```
质疑: {具体质疑点}
  原因: {为什么这可能是问题}
  替代方案: {1-2个改进方向}
  保留理由: {如果用户选择保留，需要什么条件来让其自洽}
```

用户选择：采纳替代方案 / 保留+补充自洽理由 / 驳回质疑。

### Step 7: 交叉验证

全部维度完成后跑 8 项验证：

| # | 验证项 | 检查内容 | 失败动作 |
|---|--------|---------|---------|
| 1 | 锚点稳固 | 核心锚点是否被后续设定动摇？ | 修改动摇锚点的设定 |
| 2 | 稀缺真实 | 资源/能力/信任的稀缺性是否维持？ | 补充稀缺机制 |
| 3 | 涟漪完整 | 每个改变是否都有涟漪效应？ | 补充连锁反应 |
| 4 | 价值一致 | 所有价值观是否与基调锚一致？ | 修正矛盾价值观 |
| 5 | 术语合规 | 是否违反术语规范？ | 替换术语 |
| 6 | 基调一致 | 所有设定是否与基调锚5轴矛盾？ | 修正矛盾设定 |
| 7 | 行为映射覆盖 | 行为映射规则是否覆盖所有主要场景？ | 补充规则 |
| 8 | **品类一致** | 所有设定是否符合品类词汇和风格？ | 替换违和元素 |

验证不通过 → 逐项列出问题 → 用户确认修复方向 → 修改 → 重新验证。

## 加设定/物品（快捷路径）

1. 加载基调锚 + 行为映射 + 品类规则（`world_query`）
2. 收集用户要加的设定/物品信息
3. 校验3项：基调一致 / 因果链 / 品类合规
4. 不一致时列出具体矛盾 → 用户决定覆盖还是调整
5. `world_upsert` 写入 → `sync_db_to_files`

## 约束
从 `world_settings` 和 `writing_rules` 加载当前小说的约束。高层覆盖低层。
- 基调锚是最高层约束，所有设定/人物/大纲必须遵守
- 品类规则在基调锚框架内生效，不可覆盖基调锚
- 代价规则仅作用于其作用域内，不辐射其他维度

## 完成后
问用户：设计人物 / 规划大纲 / 其他。
