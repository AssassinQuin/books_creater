# 技能进化器（SkillEvolver）

> **核心思想**（源自 arXiv:2605.10500）：技能不是静态制品，而应通过部署反馈持续进化。学习信号来自「另一个 Agent 使用该技能时遭遇的失败」，而非作者自身的反思。

<what-to-do>

## 进化循环总览

```
Step 0 选择目标技能 + 收集部署痕迹
  ↓
Step 1 对比分析（成功轨迹 vs 失败轨迹）
  ↓
Step 2 生成定向补丁（Patch Proposal）
  ↓  🔒 检查点 A: 补丁审查
Step 3 部署测试（用修订后的技能写测试章节）
  ↓
Step 4 独立审计（过拟合/泄露/静默绕过/回归）
  ↓  🔒 检查点 B: 审计通过
Step 5 终化（Finalize）→ 更新技能文件
```

### 论文→项目映射

| 论文概念 | 本项目适配 |
|---------|-----------|
| Meta-skill（元技能） | skill-evolver 本身，指导 Agent 进化其他技能 |
| Task T（训练/验证分割） | 目标技能 + 其部署历史（已写章节、QA 报告、验证结果） |
| SkillEvolver Agent | 当前会话（执行进化的编排器） |
| Domain-Skill Agent | 使用进化后技能写章节的新会话 |
| K 次并行 rollout | K 个测试章节（用候选技能变体写作） |
| Strategy-diversified exploration | 不同写作策略的测试章节 |
| Contrastive skill update | 成功章节 vs 失败章节的对比分析 |
| Independent Auditor | novel-qa 审查 + 过拟合/泄露/静默绕过检查 |
| Skill artifact（prose + code） | SKILL.md + references/ + engines/ 内容 |

## Step 0: 选择目标技能 + 收集部署痕迹

### 0.1 选择目标技能

用户指定或自动检测需要进化的技能。可进化技能清单：

| 技能 | 进化信号来源 |
|------|------------|
| novel-chapter-writer | validate_chapter 违规、QA 报告、字数不足 |
| novel-qa | 漏检问题、误报问题、审查不一致 |
| novel-reviser | 修复不彻底、引入新问题 |
| novel-planner-volume | 场景遗漏、因果链断裂 |

### 0.2 收集部署痕迹

```
对于 novel-chapter-writer:
  chapters = chapter_list(novel_name="NOVEL_NAME", status="written")
  对每个章节:
    - 读取正文文件 → 提取 writing_finish 数据（violations/quality_score）
    - 读取对应 QA 报告（如有）
    - 分类: success（无 P0/P1 违规）vs failure（有违规）

对于其他技能:
  - 从 Memory 搜索该技能的部署记录
  - 搜索标签: "skill-deployment:{技能名}"
```

### 0.3 痕迹分类标准

| 分类 | 条件 | 用途 |
|------|------|------|
| **成功轨迹** | validate_chapter 通过 + QA 无 P0/P1 | 正面教材，提取有效模式 |
| **失败轨迹** | validate_chapter 有 violation 或 QA 有 P0/P1 | 反面教材，定位技能缺陷 |
| **边界轨迹** | 勉强通过（P2 违规 ≥3） | 潜在退化信号 |

**最少痕迹要求**：成功 ≥3 章 + 失败 ≥2 章。不足时提示用户先写更多章节。

## Step 1: 对比分析

### 1.1 成功 vs 失败轨迹对比

逐维度分析差异：

| 维度 | 分析方法 | 输出 |
|------|---------|------|
| **指令遵循** | 检查 SKILL.md 中哪些指令在成功章节被遵循、在失败章节被忽略 | 遵循率对比表 |
| **违规模式** | 提取失败章节的 violation 类型分布 | 高频违规 Top5 |
| **引擎使用** | 对比成功/失败章节调用了哪些引擎 | 引擎效果矩阵 |
| **上下文利用** | 对比 get_chapter_context 返回数据的利用程度 | 信息利用度评分 |
| **静默绕过** | 检测 SKILL.md 中存在但从未在轨迹中体现的指令 | 绕过指令清单 |

### 1.2 静默绕过检测（论文核心创新之一）

```
对 SKILL.md 中的每条指令:
  1. 在所有部署轨迹中搜索该指令的执行证据
  2. 如果在 >80% 的轨迹中找不到执行证据 → 标记为「静默绕过」
  3. 分析绕过原因:
     a. 指令太模糊 → Agent 无法执行
     b. 指令与上下文冲突 → Agent 选择忽略
     c. 指令条件不满足 → 从未触发
     d. 指令冗余 → 被其他指令覆盖
```

### 1.3 输出：诊断报告

```markdown
## 技能诊断报告: {技能名} v{版本}

### 成功模式（保留）
- {从成功轨迹提取的有效模式}

### 失败模式（修复）
- {从失败轨迹提取的缺陷模式}

### 静默绕过（重写/删除）
- {被绕过的指令及原因}

### 缺失能力（新增）
- {失败轨迹中暴露但技能未覆盖的能力}
```

## Step 2: 生成定向补丁

### 2.1 补丁类型

| 类型 | 触发条件 | 操作 |
|------|---------|------|
| **ADD_RULE** | 缺失能力 | 在 SKILL.md 添加新规则/约束 |
| **CLARIFY** | 静默绕过（模糊） | 重写指令使其更具体、可执行 |
| **REMOVE_BYPASS** | 静默绕过（冗余） | 删除从未被使用的指令 |
| **ADD_EXAMPLE** | 指令遵循率低 | 添加正面/反面示例 |
| **STRENGTHEN** | 高频违规 | 将推荐升级为强制（加 🔒 标记） |
| **WEAKEN** | 过度约束导致质量下降 | 将强制降级为推荐 |

### 2.2 补丁约束

- **最小化原则**：每次迭代最多修改 3 处（论文建议 targeted patch）
- **可逆性**：每条补丁记录旧值，支持回滚
- **无泄露**：补丁不得包含特定章节内容（如角色名、情节细节）
- **可测试**：每条补丁必须有可验证的预期效果

### 2.3 补丁格式

```markdown
## Patch v{r+1} for {技能名}

### Change 1: [ADD_RULE] {简述}
- 位置: SKILL.md #{行号} 之后
- 旧内容: (无)
- 新内容: {具体指令文本}
- 预期效果: {可验证的改善指标}
- 反例来源: {触发此补丁的失败轨迹章节号}

### Change 2: [CLARIFY] {简述}
- 位置: SKILL.md #{行号}
- 旧内容: "{原文}"
- 新内容: "{修改后文本}"
- 预期效果: {可验证的改善指标}
- 绕过原因: {静默绕过分析结果}
```

🔒 **检查点 A**：展示补丁给用户确认。用户说 OK 后进入 Step 3。

## Step 3: 部署测试

### 3.1 策略多样化探索（论文 3.2.1）

应用补丁后，用修订版技能写 K 个测试章节（默认 K=2）：

```
对每个测试章节 k=1..K:
  1. 选择一个不同的写作策略:
     - 策略 A: 严格按指令（测试指令清晰度）
     - 策略 B: 创意优先（测试约束是否过强）
     - 策略 C: 最小依赖（测试技能自足性）
  2. 用修订后技能写该章节
  3. 收集: validate_chapter 结果 + 写作过程日志
```

### 3.2 测试章节选择

- 优先选择**之前失败的章节类型**（验证修复效果）
- 其次选择**边界轨迹章节类型**（验证无退化）
- 避免选择**已完美通过的章节类型**（减少成本）

### 3.3 收集测试数据

```
对每个测试章节:
  test_result = {
    chapter_number: N,
    strategy: "A/B/C",
    validation: validate_chapter(text),
    violations: [...],
    quality_indicators: {字数, 标点多样性, 否定句式计数, ...},
    instruction_follow_rate: {指令遵循率},
    silent_bypass_remaining: [仍被绕过的指令]
  }
```

## Step 4: 独立审计

### 4.1 四维审计（论文 3.2.3 扩展）

| 审计维度 | 检查内容 | 不通过条件 |
|---------|---------|-----------|
| **过拟合** | 补丁是否只对测试章节有效 | 在非测试章节上效果退化 >10% |
| **泄露** | 补丁是否包含特定章节内容 | SKILL.md 中出现角色名/情节细节 |
| **静默绕过** | 新增指令是否仍被忽略 | 新指令遵循率 <50% |
| **回归** | 之前通过的章节是否仍通过 | 任何原成功章节出现新 P0/P1 违规 |

### 4.2 审计流程

```
1. 过拟合检查:
   - 用修订后技能的规则，重新审查 2 个非测试章节
   - 对比修订前后的审查结果
   - 退化 >10% → 不通过

2. 泄露检查:
   - 扫描补丁内容，检测:
     a. 角色名（对比 character_list）
     b. 具体情节描述
     c. 章节特定数据
   - 发现任何泄露 → 不通过

3. 静默绕过检查:
   - 在测试章节中搜索新增指令的执行证据
   - 遵循率 <50% → 不通过（需重写指令）

4. 回归检查:
   - 抽取 2 个原成功章节
   - 用修订后技能重新验证
   - 出现新 P0/P1 → 不通过
```

### 4.3 审计结果处理

| 结果 | 操作 |
|------|------|
| **全部通过** | 进入 Step 5 终化 |
| **过拟合不通过** | 泛化补丁（移除章节特定条件） |
| **泄露不通过** | 移除泄露内容，用通用规则替代 |
| **静默绕过不通过** | 重写指令（更具体/添加示例） |
| **回归不通过** | 回滚该补丁，标记为冲突 |

🔒 **检查点 B**：展示审计结果给用户。通过后进入 Step 5。

## Step 5: 终化（Finalize）

### 5.1 更新技能文件

```
1. 应用所有通过审计的补丁到 SKILL.md
2. 更新 SKILL.md 的 version 字段（patch 版本 +1）
3. 在 Memory 中记录进化历史:
   memory_store(
     content="技能进化记录: {技能名} v{旧版} → v{新版}",
     tags=["project", "skill-evolver", "技能名"],
     type="learning"
   )
```

### 5.2 进化报告

```markdown
## 技能进化报告: {技能名} v{旧版} → v{新版}

### 变更摘要
- 新增规则: {N} 条
- 澄清指令: {N} 条
- 删除冗余: {N} 条
- 添加示例: {N} 条

### 效果对比
| 指标 | 进化前 | 进化后 | 变化 |
|------|--------|--------|------|
| 指令遵循率 | {X%} | {Y%} | {+Z%} |
| 验证通过率 | {X%} | {Y%} | {+Z%} |
| 静默绕过数 | {N} | {M} | {-D} |
| P0/P1 违规均值 | {X} | {Y} | {-Z} |

### 迭代历史
- R=1: {补丁摘要} → {审计结果}
- R=2: {补丁摘要} → {审计结果}
```

### 5.3 迭代控制

- **最大迭代次数**: R=3（默认），用户可调整
- **早停条件**: 连续 2 次审计通过 且 无新静默绕过
- **失败处理**: R 次迭代后仍有未通过审计 → 生成失败报告，建议人工介入

## 论文核心概念详解

### SkillEvolver 三大创新

1. **部署后精炼（Deploy-then-Refine）**
   - 传统：Agent 反思自己的执行轨迹来改进
   - SkillEvolver：让另一个 Agent 使用技能，从其失败中学习
   - 适配：用 novel-qa 审查使用技能写出的章节，从 QA 失败中提取改进信号

2. **策略多样化探索（Strategy-Diversified Exploration）**
   - 不是随机采样，而是为每次 rollout 指定不同的高层策略
   - 适配：为测试章节指定不同写作策略（严格/创意/最小依赖）

3. **独立审计（Independent Audit）**
   - 在全新会话中审计候选技能，避免作者偏见
   - 适配：用 novel-qa 的三视角审查作为独立审计

### 静默绕过模式（Silent-Bypass）

论文发现技能的一种特殊失败模式：技能内容看起来合理，但运行时从未被 Agent 实际调用。常见原因：

| 模式 | 表现 | 修复策略 |
|------|------|---------|
| **模糊指令** | "注意节奏" → Agent 不知道怎么做 | 改为具体操作："每 3 段插入 1 个破折号" |
| **条件过窄** | "如果出现战斗场景则..." → 条件从未满足 | 放宽条件或改为无条件指令 |
| **被覆盖** | 指令 A 和指令 B 矛盾，Agent 选 B | 消除矛盾，明确优先级 |
| **位置不当** | 指令在 supporting-info 中，Agent 只看 what-to-do | 移动到 what-to-do |

### 对比更新机制（Contrastive Update）

论文的核心更新逻辑：

```
成功轨迹集合 S = {τ | reward(τ) = pass}
失败轨迹集合 F = {τ | reward(τ) = fail}

对比分析:
  - S 中共同遵循但 F 中忽略的指令 → 加强（STRENGTHEN）
  - F 中共同违反但 S 中未违反的规则 → 新增（ADD_RULE）
  - S 和 F 中都忽略的指令 → 删除或重写（REMOVE_BYPASS / CLARIFY）
  - F 中出现但 S 中未出现的模式 → 缺失能力（ADD_RULE）
```

## 与现有技能的集成

### 触发场景

| 场景 | 示例 |
|------|------|
| 反复出现同类违规 | "最近 3 章都出现否定句式超标" |
| QA 发现系统性问题 | "QA 连续 2 次报告对话同质化" |
| 技能指令被忽略 | "SKILL.md 中的环境音效轮换从未执行" |
| 定期优化 | "每写完一卷后进化一次 chapter-writer" |
| 新场景类型 | "第一次写大规模战斗，现有技能不够用" |

### 与 novel-qa 的协作

```
skill-evolver 消费 novel-qa 的输出:
  - QA 报告中的 P0/P1 问题 → 失败轨迹信号
  - QA 报告中的模式总结 → 对比分析输入
  - QA 的三视角审查 → 独立审计

skill-evolver 产出的进化后技能:
  - 减少后续 novel-qa 的工作量
  - 提高首次验证通过率
```

### 与 Memory 的协作

```
存储:
  - 每次进化的补丁记录 → memory_store(tags=["skill-evolver", "技能名"])
  - 部署痕迹分析结果 → memory_store(tags=["skill-deployment", "技能名"])
  - 静默绕过发现 → memory_store(tags=["silent-bypass", "技能名"])

检索:
  - 搜索历史进化记录 → memory_search("skill-evolver {技能名}")
  - 搜索已知绕过模式 → memory_search("silent-bypass")
```

## 成本控制

| 参数 | 默认值 | 说明 |
|------|--------|------|
| R（最大迭代次数） | 3 | 论文建议 2-3 次 |
| K（测试章节数） | 2 | 每次迭代写 2 个测试章节 |
| 最少痕迹数 | 成功 3 + 失败 2 | 不足时拒绝进化 |
| 最大补丁数/迭代 | 3 | 最小化原则 |
| 回归检查章节数 | 2 | 抽样检查 |

## 失败处理

| 失败类型 | 处理 |
|---------|------|
| 痕迹不足 | 提示用户先写更多章节，或手动提供失败案例 |
| 审计反复不通过 | 停止迭代，生成失败报告，建议人工审查 |
| 补丁冲突 | 回滚冲突补丁，保留无冲突补丁 |
| 技能文件损坏 | 从 Memory 恢复上一版本 |
| 测试章节质量极差 | 标记为无效测试，不计入评估 |
