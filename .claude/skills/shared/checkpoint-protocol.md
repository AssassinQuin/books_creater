# 检查点确认协议

## 适用场景
任何 skill 在关键步骤完成后，需要用户确认才能继续时使用。

## 核心原则
- 展示完整输出 → 等用户确认 → 才写入
- 每个检查点独立确认
- 用户说"OK"才继续，否则按修改意见修改后重新展示

## 执行步骤

1. 展示当前步骤的完整输出
2. 等待用户输入
3. 用户说"OK" → 继续
4. 用户提修改意见 → 修改 → 重新展示 → 回到步骤2

## 流程图

```
展示输出 → 用户确认
  ↓ OK           ↓ 修改意见
继续下一步      修改内容 → 重新展示 → 用户确认
  ↓                                    ↓ OK
写入文件                            写入文件
```

## 检查点类型

| 类型 | 标记 | 说明 |
|------|------|------|
| 事件架构确认 | 🔒检查点A | 确认事件架构+因果链+人物弧光 |
| 逐章大纲确认 | 🔒检查点A2 | 确认逐章大纲+硬约束自检 |
| 验证通过确认 | 🔒检查点B | 确认审查无P0问题 |
| 创意蓝图确认 | 🔒检查点A | 确认场面设计+因果链+角色弧线 |
| 正文完整性确认 | 🔒检查点B | 确认字数达标+反AI自检通过 |

## 问题分级（检查点B专用）

| 级别 | 判定标准 | 处理 |
|------|---------|------|
| P0 | 三视角冲突/角色OOC/因果链断裂 | **必须修复**，阻断保存 |
| P1 | 单视角严重问题/术语违规 | **本轮内修复** |
| P2 | 微调建议 | **下一轮前修复** |

## 修改循环

- 最多3轮修改循环
- 超过3轮 → 升级为用户决策：①接受 ②回退 ③手动修复
- 每轮修改后重新展示完整输出
