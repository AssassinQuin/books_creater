# 三视角审查协议

## 适用场景
大纲或正文完成后，需要从读者/作者/人物三个独立视角审查时使用。

## 核心原则
- 人物 > 读者 > 作者
- 三个视角独立并行，互不依赖
- 交叉检查发现冲突

## 执行步骤

1. 编排器打包审查数据（逐章大纲/正文 + 角色信息 + 术语精简摘要）
2. 3个审查 Agent 同时启动（并行）
3. 等待全部返回
4. 交叉检查
5. 输出审计报告

## 视角分工

| Agent | 审查维度 | 所获数据 |
|-------|---------|---------|
| 读者视角 | 开篇钩子/信息层级/悬念分布/爽点节奏/弃文风险 | 大纲/正文 + 角色出场表 |
| 作者视角 | 起承转合/因果链穿透/伏笔层级/主题一致性 | 大纲/正文 |
| 人物视角 | 弧光对齐/动机充分/选择必然/代价明确/OOC检测 | 大纲/正文 + 角色蒸馏卡 |

## 交叉检查

- 读者 vs 作者：结构是否服务读者体验？
- 读者 vs 人物：人物选择是否有动机？
- 作者 vs 人物：人物逻辑是否优先于结构需求？

## 术语精简分发

编排器预提取 `lorecraft/references/quickref.md` 中的：
- 需替换术语清单（§6.1）
- 势力字根表（§6.3）

作为字符串直接注入 Agent 指令。审查 Agent **不自主加载**任何引擎或 lorecraft 文件。

## 问题分级

| 级别 | 判定标准 | 处理 |
|------|---------|------|
| P0 | 三视角冲突/角色OOC/因果链断裂 | 必须修复，阻断保存 |
| P1 | 单视角严重问题/术语违规 | 本轮内修复 |
| P2 | 微调建议 | 下一轮前修复 |

## 红蓝对抗增强（可选）

在标准三视角基础上，可启用红蓝对抗模式：
- 蓝队：创作者视角（尽力辩护当前设计）
- 红队：破坏者视角（主动找破绽、找弃文理由、找反派更优选择）
- 红队发现的问题标记为 P0-red，优先级高于普通 P0
