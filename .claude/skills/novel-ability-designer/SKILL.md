# 能力设计引擎 (Ability Designer)

> **核心原则**: 能力不是从"设定框架"出发，是从"这人的经历+性格"出发
> **文化根脉**: 所有能力名称必须遵循 lorecraft 文化根脉法
> **参考文件**: `engines/ability.md`（七问框架设计规范）

---

## 前置加载

在执行任何能力设计之前，加载以下参考：

1. `engines/ability.md` — 七问框架基准规范
2. `lorecraft` — 术语命名引擎（能力名必须经过文化根脉检查）
3. `设定/人物能力设定方案.md` — 项目已有能力设计
4. `设定/世界观/能力体系.md` — 项目已有能力体系记录
5. 对应角色的档案文件 — `设定/人物/{名}.md`

---

## Step 1: 能力诊断（对新能力跳过）

读取目标角色的现有能力设置，回答：

- [ ] 能力是否从"角色经历+性格"出发？（来源合理性）
- [ ] 能力名称是否含有现代术语？（频率/权限/数据/系统/感知/掌控/结构等）
- [ ] 能力是否有明确的"代价"？（不是概念词，是具体身体反应）
- [ ] 能力是否有"做不到的事"？（限制即深度）
- [ ] 能力在团队里是什么位置？（不能所有人都是输出）

> ⚠️ **检查点**: 诊断结果展示给用户确认后再进入 Step 2

---

## Step 2: 七问框架设计

为每个角色回答这七个问题（使用 `engines/ability.md` 的七问框架）：

```
1. 经历里有什么特殊之处？   → 能力来源的合理性（不是天然就该有）
2. 性格会怎么"用"能力？    → 使用风格（换个人用法完全不同）
3. 能力有什么代价？        → 具体身体反应（不是概念词）
4. "做不到"什么？          → 限制即深度（不能无敌）
5. 能力怎么随时间变化？    → 成长弧线（1-3个阶段即可）
6. 在团队里是什么位置？    → 群像差异化（感知/输出/控制/辅助）
7. 没有能力还有啥价值？    → 去能力化认同（不是只有能力时重要）
```

**输出格式**:

```yaml
core:
  name: 能力名称          # 见 Step 3 命名规范
  direction: 感知型/操控型/强化型/解构型/编织型/分析型  # 七选一
  level: 初觉/通感/凝相/回响/化生/自成/归源
  description: "一句话描述"
stages:
  - stage: 1
    volume: "V1-V3"
    trigger: "触发条件"
    limits: "核心限制"
    description: "能力在这个阶段的具体表现"
  - stage: 2        # 配角1-2阶段，核心配角3-4阶段
    ...
essence:            # 能力的"内核"——换掉能力名仍然不变的本质
  core_identity: "一句话说清能力本质"
  design_philosophy: "从角色经历出发的一句话"
  unchangeable: "这个能力绝对做不到的事"
global_limits:
  - "第一条上限"
  - "第二条上限"
```

> ⚠️ **检查点**: 七问回答 + 格式输出展示给用户，确认后才进入命名 Step 3

## Step 3: 能力命名（文化根脉检查）

**禁止术语清单**（来自 lorecraft，违反必须替换）：

| 禁止词 | 替换示例 |
|--------|---------|
| 掌控/控制 | 驭/御/役/锁/镇 |
| 系统/体系 | 脉/路/网/枢 |
| 数据/信息 | 册/录/纹/痕 |
| 扫描/检测 | 探/感/听/嗅 |
| 模式/状态 | 势/相/态（有文化根脉的态） |
| 分析/计算 | 辨/读/识/断 |
| 频率/信号 | 脉/韵/息/颤 |
| 权限/授权 | 契/令/牒/印 |
| 结构 | 纹/络/脉/骨 |
| 拟态/模仿 | 化形/印刻/承影 |

**命名四步法**:

1. **概念解构**: 把能力拆解为 2-4 个本质要素
   - 例："火焰掌控" → (1) 火 (2) 役使/驱动 (3) 源自本能
2. **文化映射**: 从道教/佛教/中医/历史/民俗根脉选对应字
   - 火→炎/燚/炽，役使→驭/役/御，本能→本能/野性/原始
3. **组合筛选**: 音韵感 + 陌生化 + 体系一致性
   - 火驭（简洁）> 炎役（拗口）> 火焰役使（太长）
4. **验证测试**: 角色在对话中会这么说吗？读者能懂吗？
   - "火驭" ✓（猎人会说"那家伙能驭火"）
   - "掌控火焰" ✗（掌控是现代官腔）

**文化根脉映射表**（快速查表）：

| 概念域 | 可用字根 | 来源 |
|--------|---------|------|
| 灵能 | 气/脉/韵/息/纹/痕 | 道教/中医 |
| 灵站 | 枢/窍/眼/门/关 | 建筑/历史 |
| 控制/约束 | 锁/镇/封/禁/缚 | 民俗/军事 |
| 感知/察觉 | 听/嗅/探/感/察 | 中医/民俗 |
| 力量/强化 | 骨/体/筋/息/力 | 中医/武术 |
| 创造/建造 | 铸/锻/编/织/构 | 工匠/民俗 |
| 毁灭/分解 | 碎/拆/裂/断/蚀 | 民俗/历史 |
| 火焰 | 炎/燚/炽/灼/焚 | 历史/文学 |
| 防御 | 壁/盾/甲/垒/屏 | 军事/历史 |
| 印记/痕迹 | 印/痕/纹/记/迹 | 民俗/道教 |

> ⚠️ **检查点**: 最终名称需用户确认

## Step 4: 能力档案写入

将设计结果写入两个位置：

### 4.1 角色档案

更新 `设定/人物/{名}.md` 的 `ability_level` 字段：
```yaml
## 基本信息
- **ability_level**: {能力名} {等级}({卷范围})
```

### 4.2 能力体系文档

新增/更新 `设定/世界观/能力体系.md` 条目：
```yaml
## ability: 能力_{名}
- **类型**: {方向}（{能力名}）
- **阶位**: {等级}
- **核心机制**: 一句话
- **限制**: ["限制1", "限制2"]
- **代价**: 具体身体反应
- **成长路径**: 阶段变化描述
```

### 4.3 能力设计文档

在 `设定/人物能力设定方案.md` 中添加能力描述（叙事性）：

```
### {名} — {能力名}

[1-3段能力叙事，从角色经历出发说明能力来历、使用方式、限制、成长]
```

---

## Step 5: 命名审计（最终检查）

逐条审计能力名称：

- [ ] 名称不含任何禁止术语？（对照 lorecraft 禁止清单）
- [ ] 名称有文化出处？（用了哪个根脉的字）
- [ ] 名称在对话中自然？（角色会这么说吗）
- [ ] 名称与根隐喻一致？（灵能=活的力量，不能叫"系统"）
- [ ] 同势力的能力名风格一致？（灵枢人名多用"印/刻/固"，研究院多用"册/录/析"）

---

## 边界条件

| 场景 | 处理方式 |
|------|---------|
| 角色本身无能力 | 跳过 Step 2-3，补充"无能力价值"描述（沈念/江屿模式） |
| 修改已有能力 | 先 Step 1 诊断，只修问题，不重写完整的（幅度控制） |
| 新增角色 | 从 Step 2 开始，先回答七问再写档案 |
| 主角团 vs NPC | 主角团完整设计，NPC 只给 1-2 句核心机制（不浪费 token） |
| 名字改后出戏 | 保留原名，加括号注文化根脉版（如：火焰掌控→火驭） |
| 与 lorecraft 冲突 | lorecraft 禁止术语清单为硬约束，必须遵守 |

## 角色能力阶段分配参考

| 角色类型 | 阶段数 | 示例 |
|---------|--------|------|
| 主角（沈野/汐/蔓/陆沉） | 3-5 阶段 | V1-V3→V4-V6→V7-V9→V10-V12→V13-V14 |
| 核心配角（赵铁山/林原/柳陌） | 1-2 阶段 | 一个阶段贯穿全书 |
| 功能性配角（钟衍/陈启明） | 1 阶段 | 能力即人设，不成长 |
| NPC 觉醒者（异灵） | 0 阶段 | 只写核心机制 |
| 无能力者（沈念/江屿） | 不适用 | 写"无能力价值" |
