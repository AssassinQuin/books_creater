# 剧情工坊

## 触发
用户说"讨论剧情""设计线索""伏笔规划""推演剧情""剧情工坊""剧情讨论""线索管理""what if""如果XX会怎样"。

## 核心理念
这是**工作坊**，不是生产线。目标是人和 AI 在世界观约束内反复讨论，找到最合理的剧情走向。讨论过程中 AI 必须持续校验世界观约束，不一致立即指出。

## 前置加载（每次触发必须执行）
1. 加载世界观核心：`world(action="query")` → 能力体系/势力/地理/历史/魔物/社会文化
2. 加载已有线索：`foreshadow(action="list")` → 全部线索状态（planted/partially_resolved/resolved）
3. 加载氛围 DNA：`Read novels/{小说名}/设定/世界观/世界基石.md`（基调+行为映射+氛围DNA）
4. 加载角色列表：`character_list` + 主要角色的 `character_detail`
5. 加载现有大纲：`Glob novels/{小说名}/设定/大纲/*.md` → 读取已有卷级大纲
6. 加载创作宪法：`Read novels/{小说名}/设定/写作/创作宪法.md`（如存在）

加载完成后向用户简报当前状态：
- 已有几条活跃线索（列出名称+状态）
- 当前进度（已写到第几卷/第几章）
- 哪些世界观约束与本轮讨论最相关

## 模式选择（问用户）

| # | 模式 | 适合场景 |
|---|------|---------|
| 1 | **线索工坊** | 设计/修改单条线索（主线/暗线/支线）的完整生命周期 |
| 2 | **假设推演** | "如果X发生了会怎样"——探索可能性，校验约束 |
| 3 | **伏笔链设计** | 设计跨章节/跨卷的伏笔→揭示链 |
| 4 | **线索审计** | 检查线索健康度（遗漏/断裂/积压） |
| 5 | **自由讨论** | 开放式聊天，AI 持续校验世界观 |

用户选哪个做哪个。也可以不选直接说想法，AI 根据内容自动选择最合适的模式。

## 模式 1：线索工坊

### 1.1 确定线索对象
- 新建线索：用户描述线索概念 → AI 追问线索的驱动力、涉及角色、预期揭示卷
- 修改现有线索：`foreshadow(action="list")` → 用户选一条 → 展示当前状态

### 1.2 线索五维分析（AI 输出，用户确认）

对每条线索，AI 必须从五个维度分析：

```
| 维度       | 内容                                         |
|-----------|----------------------------------------------|
| 源头      | 这条线索的根因是什么？（必须在世界观/历史/角色动机中有根基） |
| 驱动力    | 谁在推动？为什么推动？（不可是"剧情需要"）            |
| 约束校验  | 与哪些世界观规则碰撞？能力体系/势力逻辑/历史设定是否允许？ |
| 信息层级  | 读者目前知道多少？角色知道多少？叙事者隐瞒了多少？      |
| 终局走向  | 可能的收束方式（至少2种），各自的代价              |
```

**世界观碰撞必须显式标注**：
- ✅ 完全兼容
- ⚠️ 需要调整（具体说明哪条规则冲突）
- ❌ 不可行（给出原因，建议替代方案）

### 1.3 线索节奏设计

基于 `engines/spiral-structure.md` 的三层信息矩阵：

```
| 阶段     | 章节范围 | 读者视角           | 角色视角           | 叙事者操作        |
|---------|---------|-------------------|-------------------|-----------------|
| 种植期   | Ch??-?? | 注意到异常但不理解   | 完全不知/隐约感觉   | 埋细节，不给解释    |
| 发育期   | Ch??-?? | 拼图逐渐成型        | 发现部分真相        | 给碎片，制造误导    |
| 揭示期   | Ch??-?? | 预感到但不确定       | 关键发现            | 揭示，翻转认知      |
| 余波期   | Ch??-?? | 回看前面全懂了       | 面对后果            | 补充细节，不改事实   |
```

### 1.4 输出
- 用户确认后：`foreshadow(action="plant")` 或 `foreshadow(action="update")` 写入 DB
- 线索卡写入 `novels/{小说名}/设定/大纲/线索/{线索名}.md`

## 模式 2：假设推演

### 2.1 用户提出假设
用户说"如果X发生了会怎样"。

### 2.2 约束推演（AI 必须执行）

```
推演链：
假设事件 → 世界观约束过滤 → 势力反应推演 → 角色反应推演 → 连锁反应 → 结果

每一步必须标注约束来源：
- [能力体系] 以太浓度法则 → ...
- [势力逻辑] 学塔不会坐视 ... → ...
- [历史设定] 上一次类似事件 ... → ...
- [角色性格] XX的性格不会 ... → ...
```

### 2.3 多结局展示

```
| 路径 | 触发条件        | 代价               | 对主线影响     | 可行度 |
|-----|----------------|-------------------|--------------|-------|
| A   | ...            | ...               | ...          | 高/中/低 |
| B   | ...            | ...               | ...          | 高/中/低 |
| C   | ...            | ...               | ...          | 高/中/低 |
```

AI 给出推荐路径 + 理由。用户选择或提出修改。

### 2.4 采纳决策
- 用户选了某条路径 → 记录为"已采纳假设"，写入灵感库
- 不采纳 → 只做讨论记录，不写入大纲

## 模式 3：伏笔链设计

### 3.1 确定目标
用户指定要设计的伏笔目标（例如"第三卷末揭示XX的真实身份"）。

### 3.2 反向设计链

从揭示点往回推导：

```
揭示点（Ch??）: [描述读者最终得知的真相]
  ↑ 揭示前的最后一层误导（Ch??-??）
  ↑ 关键线索碎片（Ch??, Ch??, Ch??）— 至少3个碎片散布在不同场景
  ↑ 首次暗示（Ch??）— 读者会忽略的细节
```

### 3.3 伏笔质量检查

每条伏笔必须通过：

| 检查项 | 标准 |
|--------|------|
| 自然度 | 植入时是否有合理理由出现？（不是"突然提到"） |
| 隐蔽度 | 读者第一次能猜到吗？至少要过30章才可回看发现 |
| 回收度 | 揭示时读者能回溯到所有碎片吗？碎片是否足够？ |
| 约束一致 | 植入的信息是否与世界观/角色能力/已知事实一致？ |
| 非机械性 | 植入方式是否多样？（对话/环境/行为/物品/旁白 混合使用） |

### 3.4 输出
- 伏笔链图表写入 `novels/{小说名}/设定/大纲/伏笔/{伏笔名}-链.md`
- `foreshadow(action="plant")` 每个碎片分别入库

## 模式 4：线索审计

### 4.1 加载全部数据
`foreshadow(action="list")` + 所有已有正文 + 大纲

### 4.2 审计维度

| 维度 | 检查内容 |
|------|---------|
| 孤儿线索 | 已种下但超过15章没推进的线索 |
| 断裂因果 | 线索的推进缺乏因果链支撑 |
| 积压问题 | 同一卷内未回收线索 > 5 条 |
| 遗忘伏笔 | 已规划但正文中从未植入的碎片 |
| 时间窗口 | 某些线索的最佳揭示窗口已过或快到 |
| 角色记忆 | 角色是否"忘记"了自己应该知道的信息 |

### 4.3 输出
审计报告写入 `novels/{小说名}/审阅报告/线索审计-{日期}.md`，格式：
```
| 线索 | 状态 | 问题 | 严重度 | 建议处理 | 建议章节 |
|------|------|------|--------|---------|---------|
```

## 模式 5：自由讨论

### 5.1 规则
- 用户自由发言，可以是想法、片段、问题、吐槽
- AI 每次回复必须包含两部分：
  1. **回应**：对用户想法的回应和展开
  2. **约束校验**：如果涉及世界观要素，显式检查是否合规

### 5.2 约束校验格式（轻量）
```
🔍 约束检查：
- [能力体系] ✅/⚠️/❌ {具体说明}
- [势力逻辑] ✅/⚠️/❌ {具体说明}
- [历史设定] ✅/⚠️/❌ {具体说明}
- [角色性格] ✅/⚠️/❌ {具体说明}
```
只有涉及到的维度才需要标注，不用全列出。

### 5.3 讨论沉淀
每轮讨论结束前，AI 主动总结：
- 本轮产生了哪些有价值的想法？
- 哪些可以转化为具体线索/伏笔？
- 询问用户是否要保存到灵感库

## 全局约束

### 世界观红线（任何模式下都不可违反）
所有讨论中的剧情点必须通过以下检查：

1. **能力体系合规**：觉醒者的行为不超以太六准则（感受/浓度/元素/趋异/代价/强者法则）
2. **势力行为自洽**：每个势力的行动符合其利益和性格，不为剧情需要做OOC行为
3. **历史因果链**：不与三纪简史冲突，历史事件不可被角色行为随意改变
4. **经济逻辑**：涉及金钱/资源/贸易的情节符合已建立的经济体系
5. **角色性格守恒**：人物行为符合角色档案中的性格内核，改变需要充分动机
6. **日常即世界观**：世界观呈现通过日常细节，不通过说明文

### 交互铁律
- **讨论优先，生成在后**：先充分讨论再写文件
- **冲突显式化**：发现约束冲突立即告知用户，不自行解决（R7）
- **不替用户决定**：多选项时列出优缺点让用户选，AI 只推荐不代劳
- **追溯已讨论内容**：对话内已达成共识的点不重新讨论（R4）

### 与其他 Skill 的关系
- 讨论结果 → `novel-plan` 消费（线索/伏笔写入大纲结构）
- 伏笔碎片 → `novel-write` 消费（正文植入时读取）
- 线索审计 → `novel-review` 消费（审查时检查伏笔健康度）
- 假设推演 → `novel-plan` 的事件架构师 Agent 消费
