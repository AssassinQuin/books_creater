# 能力世界观根植设计引擎

> **范围边界**：本技能只处理**能力设计层**——从角色经历到能力定义到三视角命名。**描写层**（能力展示/代价表达）→ `engines/ability.md`，**命名词汇层**（AI味消除/字根多样性）→ `lorecraft` + `SENTENCE-PATTERNS.md`。三者协同：本技能确保能力从世界观里长出来，ability engine 确保写正文时不写成技能面板，lorecraft 确保能力名不贡献AI指纹。

---

## 核心原则

### 四根隐喻（本项目世界观）

| 根隐喻 | 设计约束 |
|--------|---------|
| **灵能是环境，不是工具** | 能力不是"选择"的，是环境塑造的。西部荒原觉醒的人灵能偏编织——不是因为他选了编织，是那里的灵能稀薄让他本能学会拼凑 |
| **觉醒是被动事件，不是升级** | 能力设计第一步不是"这个角色需要什么能力"，而是"这个角色经历过什么，灵能为什么会这样回应他" |
| **能力是身体的方言** | 能力的"口音"来自成长地。方岩的感知带"矿味"，不是因为作者安排，是他在北方矿区活了二十年 |
| **限制比能力更重要** | 能力设计的核心不是"他能做什么"，而是"他做不到什么，以及他选择为此付出什么" |

### 能力设计五标

| 标准 | 通过条件 | 判断方法 |
|------|---------|---------|
| **经历根系** | 去掉角色背景，能力不成立 | "如果他没有这段经历，能力还会是这个吗？"→"不会" |
| **机制唯一** | 核心操作动词不可被另一个角色复用 | 用3个动词概括核心操作，换个人能否套用？ |
| **代价即身份** | 代价改变了角色的生活方式 | 钟衍关不掉听诊→失眠→远离人群。代价定义了他的社交 |
| **命名即画面** | 闭上眼能生成画面（声音/触感/味道） | "叩铁"→有声音、有触感。"灵能凝固"→什么都没有 |
| **成长有弧线** | 每阶段有事件触发 | 能说出角色能力3个转折点分别由什么事件触发 |

## 六步设计法

能力不是"从类型表选"的。以下六步严格按序执行：

### Step 1: 经历回溯

> 问：这个角色的人生中，哪段经历最有可能让灵能"选择"他？

🔒 **输出确认**：用一句话说清"他的能力来自______"
- ❌ "他是 soldier → 强化体质"（类型关联，非经历根系）
- ✅ "他在废墟里捡了二十年灵能碎片，手指碰过成千上万块灵能物品的断面"（经历根系）
- 无觉醒者（约占人口绝大多数）→ 跳过 Step 2-6，输出"无觉醒"及不可替代价值

### Step 2: 七问框架（经历+性格→能力）

回答以下七个问题，用角色经历和性格"长出"能力，而非从类型表选：

| # | 问题 | 回答目标 | 
|---|------|--------|
| 1 | 经历里有什么特殊之处？ | 能力来源的合理性（不是天然就该有） |
| 2 | 性格会怎么"用"能力？ | 使用风格（换个人用法完全不同） |
| 3 | 能力有什么代价？ | 具体身体反应（不是概念词） |
| 4 | "做不到"什么？ | 限制即深度（不能无敌） |
| 5 | 能力怎么随时间变化？ | 成长弧线（1-3个阶段即可） |
| 6 | 在团队里是什么位置？ | 群像差异化（感知/输出/控制/辅助） |
| 7 | 没有能力还有啥价值？ | 去能力化认同（不是只有能力时重要） |

🔒 **来源必须具体到场景**（问1的回答标准）：
- ❌ "他在战斗中觉醒了"
- ✅ "深夜潜伏在敌壁外，手掌贴着冷石判断墙厚，忽然'看见'了石料的纹路和应力走向——那是他第一次知道自己的手不只会摸，还会看透"

> ⚠️ **检查点**：七问回答展示给用户确认后，才进入 Step 3

### Step 3: 机制定义

基于七问之3-6的回答：运作机制 + 代价 + 做不到什么 + 成长线 + 团队位置。

🔒 **机制必须有三条明确的"不做什么"约束**：
- 必须物理接触（不能远程）
- 只对无机物生效（读不了活体）
- 深度使用后手指触觉钝化数小时

### Step 4: 代价设计

每个能力必须有代价。代价不是"减血条"——**是角色因此改变了什么**。

代价类型参考（不用抽象词，用身体感受）：

| 类型 | 正文表达 |
|------|---------|
| 生命力消耗 | "他又老了一点——头上一根黑发从根上白了"（陆沉） |
| 身体反应 | "做到后来头疼、鼻血、手抖，眼睛花得看不清"（沈野） |
| 不可控 | "关不掉，听到不想听的，彻夜失眠"（钟衍） |
| 情感负担 | "听到几百年的恐惧和绝望"（沈鹤） |

🔒 **代价检查**：代价用身体感受/行为变化表达？有累积效果？影响生活方式？

**代价表达规范**：
- 不应该使用"代价/反噬/寿命折损/精神崩溃"等抽象概括词——这些词汇将身体感受压缩成概念标签，读者无法感知角色的真实痛苦。应该用具象的身体反应替代：白发、鼻血、手抖、失眠、幻听。
- 不应该让代价停留在"设定说明"层面——代价必须在正文中反复出现，改变角色的日常选择（远离人群、拒绝深夜任务、随身携带药物）。应该让代价成为角色行为的可见驱动力。

### Step 5: 三视角命名（参考 lorecraft）

一个能力有三个名字，对应三种"谁在叫它"：

| 视角 | 命名逻辑 | 字根来源 | 字数 |
|------|---------|---------|------|
| **自述名**（主线用） | "我管它叫什么"——来自身体感受 | 个人经历+感官动词 | ≤4 |
| **登记名**（设定用） | "灵枢/研究院管它叫什么"——官方分类 | 势力文化母体 | ≤6 |
| **外号**（对话用） | "别人怎么叫它"——社会/圈内称呼 | 市井口语/行业黑话 | ≤4 |

🔒 **命名检查**：三视角至少输出2个？闭上眼有画面？字根不冲突？正式名≤4字？

### Step 6: 多样性检查

- [ ] **前缀碰撞**：核心字与已有能力名是否共享同一前缀（"灵能XX"还在增加？）
- [ ] **构词模式**：最近的3个能力名构词是否重复？
- [ ] **机制差异化**：核心操作动词是否与已有能力重复？
- [ ] **类型分布**：是否过于偏向某一种能力类型？
- [ ] **代价差异化**：代价类型是否与已有能力过度雷同？
- [ ] **字数约束**：正式名≤4字

检查不通过 → 回到 Step 5 重新命名。连续2次不通过 → 回到 Step 3 重新检视机制。

## 势力能力命名文化母体

命名差异来自 **"谁在描述 + 他关心什么"**，不是给同一个能力起多个名字。

| 势力 | 命名哲学 | 字根 | 示例 |
|------|---------|------|------|
| **灵枢** | 管理视角——能力当资源编号 | 录/册/枢/牒/值 | 灵能拓录、巡息值 |
| **壁盾** | 战术视角——能力当战场定位 | 阵/垒/锋/哨/盾/壁 | 垒阵术、锋哨岗 |
| **教会** | 信仰视角——能力当恩赐/试炼 | 圣/辉/戒/颂/祭/净 | 辉戒术、颂灵仪 |
| **研究院** | 分析视角——能力当研究现象 | 测/谱/析/验/辨/证 | 灵能测谱、纹路辨 |
| **猎人** | 生存视角——能力当工具/累赘 | 探/嗅/走/老/刀/闻 | 嗅痕、走窝术 |
| **星火社** | 工具视角——能力当渗透手段 | 暗/线/刺/密/信/哨 | 暗刺、线通术 |
| **遗脉** | 血脉视角——能力当祖先回响 | 脉/承/祖/骨/野/渊 | 承脉术、祖骨吟 |

**跨势力场景规则**（视角D）：同一能力跨势力时只保留一个名。各角色用自己势力的语法风格**描述**它，而不是给同一能力起不同名。


## 工作流（在 novel-character Step 2 中触发）

```
Step 0: 🔒 前置判断 → 有觉醒？否→输出"无觉醒+不可替代价值"
Step 1: 经历回溯 → 输出一句"他的能力来自______"
Step 2: 来源+机制 → 输出能力卡片（来源+机制+3条约束+成长线+定位）
Step 3: 🔒 代价设计 → 代价必须5项检查全通过（无抽象词）
Step 4: 🔒 命名+多样性 → 自述名+登记名+外号，6项多样性检查
Step 5: 写入DB → character_update_by_name(novel_name="NOVEL_NAME", character_name={character_name}, ability_system=JSON)，同步写文件
Step 6: 🔒 质量检查 → 11项清单全通过
```

**能力命名修复流程**（已有能力名发现AI味时）：
```
诊断AI味类型 → 生成三视角候选 → 多样性检查 → 替换
每写1章最多替换1个旧能力名（避免读者认知断裂）
```

## 边界条件

| 场景 | 处理 |
|------|------|
| 角色无觉醒（约占人口绝大多数） | 跳过六步法，输出"无觉醒"，设计不可替代价值（技能/知识/人脉/性格） |
| 血脉/远古存在类 | 不走灵能觉醒框架，走追溯记忆/血脉记忆路径 |
| 写作中能力自然涌现 | 写完后做回顾性设计，补完整角色卡 |
| 旧能力名发现AI味 | 走命名修复流程，每章最多替换1个，不批量改写已写章节 |
| 能力库为空（首次设计） | 免多样性检查，标注"首次设计"，后续新增时补查 |
| 成长阶段的事件触发缺失 | 回到卷大纲事件清单找，找不到→能力不应在这个阶段突破 |
| 无经历对应 | 找不到""他的能力来自______"的完整句子→角色不应有觉醒能力 |

## 质量检查

### 能力设计（每章写完检查，不通过不存盘）

- [ ] 每个觉醒者能力都有明确的"经历→来源"链路
- [ ] 每个能力有 3 条明确的"做不到什么"约束
- [ ] 代价用身体感受表达（不应该使用抽象概括词，应该用具象身体反应替代）
- [ ] 命名通过多样性检查（前缀/构词/机制/类型/代价/字数）
- [ ] 三视角没有变成三个不同能力名（主线用自述名，外号只出现在对话）
- [ ] 无能力者有不可替代价值
- [ ] 能力成长有事件触发

### 能力描写（详见 `engines/ability.md` + 反AI系统）

- [ ] 无"催动灵能"等万能起手式
- [ ] 能力展示包含感官细节（视觉/听觉/触觉/嗅觉）
- [ ] 无"缓缓/淡淡/微微"模糊状态副词

## DB写入格式

```json
{
  "name": "拓印",
  "official_name": "灵能拓录",
  "nickname": "抄手",
  "type": "解构型",
  "level": "凝相级",
  "source": "拾荒者长期接触灵能碎片的觉醒",
  "mechanism": "触碰灵能结构时能读出底层路数，能铸造新灵能物品",
  "constraints": ["必须物理接触", "读不了碑文", "复制不了有代价的能力"],
  "cost": "连续铸造导致头痛/鼻血/手抖",
  "stages": [
    {"stage": 1, "trigger": "V1矿区被碎片割伤", "description": "基础拓印"},
    {"stage": 2, "trigger": "V4获得第一块好材料", "description": "模拟他人灵能结构雏形"}
  ],
  "team_position": "辅助/后勤/装备制造"
}
```

> stages 的 trigger 字段必须填写事件触发，不能写"修为到了自然变强"。

**YAML 扩展格式**（适用于复杂能力，可与上面 JSON 互转）：

```yaml
core:

  direction: 解构型       # 感知/操控/强化/解构/编织/分析 七选一

  - stage: 2

  - "必须物理接触（不能远程）"
```

### 角色能力阶段分配参考

| 角色类型 | 阶段数 | 示例 |
|---------|--------|------|
| 主角（沈野/汐/蔓/陆沉） | 3-5 阶段 | V1-V3→V4-V6→V7-V9→V10-V12→V13-V14 |
| 核心配角（赵铁山/林原/柳陌） | 1-2 阶段 | 一个阶段贯穿全书 |
| 功能性配角（钟衍/陈启明） | 1 阶段 | 能力即人设，不成长 |
| NPC 觉醒者（异灵） | 0 阶段 | 只写核心机制 |
| 无能力者（沈念/江屿） | 不适用 | 写"无能力价值" |
