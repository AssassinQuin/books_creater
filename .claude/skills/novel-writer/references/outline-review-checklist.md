# 大纲审查引擎 v2.0

> **本文件功能**: 卷级大纲的多维度并行审计+修复闭环。融合达尔文评分迭代与女娲创造修复流程。
> **触发时机**: novel-planner 每卷大纲创建后/全书大纲完成后/重大修改后。
> **执行方式**: Phase 1 达尔文评估（10维度并行Agent）→ Phase 2 女娲修复（多Agent并行修复）→ Phase 3 验证评分（迭代直到达标）。
> **核心原则**: 不只查当前卷——必须与前后卷大纲、角色蓝图交叉比对。不只发现问题——必须创造修复方案。

---

## 三阶段强制流程

```
Phase 1 达尔文评估: 10维度Agent并行 → 评分卡 → 问题清单(P0-P3) → 🔒评分确认
Phase 2 女娲修复: P0/P1自动进入修复 → 每问题3方案 → 交叉验证 → 🔒修复确认
Phase 3 验证迭代: 修复后重评 → 对比前后分 → 达标则通过 / 不达标则回到Phase 2
```

---

## Phase 1: 达尔文评估（10维度并行Agent）

> **目标**: 多维度独立审计，每维度量化评分（0-100），输出结构化问题清单。
> **执行方式**: 启动最多10个独立Agent并行，每个Agent只读大纲+相关设定，独立产出报告，互不影响。
> **Agent选取规则**: 全书级审计启动全部10维度；单卷审计根据卷特点选取5-7个最相关维度。

### 10维度审计矩阵

| 编号 | 维度 | Agent专注点 | 核心输出 | 读取文件 |
|------|------|------------|---------|---------|
| A | 叙事节奏 | 张力曲线、高低潮交替、钩子强度、节奏标签验证 | 张力走势图 + 节奏标签验证表 | 大纲 |
| B | 因果逻辑 | 因果链完整性、设定矛盾、信息对称、时间线逻辑 | 因果链追踪图 + 矛盾清单 | 大纲 + 世界观 + 线索追踪 |
| C | 角色弧线 | Ghost→Lie→Want→Need验证、配角弧线、角色消失检测 | 弧线评分表 + 消失热力图 | 大纲 + 角色深化 |
| D | 商业性 | 爽点分布、弃文风险、黄金三章、终卷回报 | 爽点分布图 + 弃文风险评估 | 大纲 + 灵感库方法论 |
| E | 世界观一致性 | 能力体系、组织架构、纪元设定、经济体系 | 一致性验证表 | 大纲 + 世界观 + 地图 |
| F | 信息流伏笔 | 伏笔回收率、间距风险、传播链、公平线索 | 伏笔全清单 + 传播链追踪 | 大纲 + 线索追踪 |
| G | 时空观 | 季节连续、气候一致、平行时间线、时间跳跃 | 季节验证表 + 时间跨度追踪 | 大纲 + 地图 |
| H | 角色关系 | 信任进展、摩擦考验、关系不对等、断裂修复 | 关系进展表 + 不对等检测 | 大纲 + 角色深化 |
| I | 反派体系 | 反派存在感、动机一致性、主角-反派互动、独特性 | 反派行动线追踪 + 存在感分布图 | 大纲 + 世界观 + 角色深化 |
| J | 地理行动 | 移动路线、旅行时间、空间压缩、地理独特性利用 | 角色移动追踪 + 瞬移检测 | 大纲 + 地图 + 世界观 |

### 每个Agent的标准输出格式

```
# Agent {X}: {维度名}审计报告

## 评分: {N}/100

## {维度特有分析内容}

## 问题清单
### P0 致命问题 ({N}个)
### P1 严重问题 ({N}个)
### P2 中等问题 ({N}个)
### P3 轻微问题 ({N}个)

每条问题格式：
**[{级别}-{编号}] {位置}-简述**：问题描述 + 影响分析 + 建议修复方向

## 亮点
## 总评
```

### Agent选取规则

**全书级审计**（14卷全部完成后）: 启动全部10维度。
**单卷审计**（每卷规划完成后）: 按卷类型选取：

| 卷类型 | 必选维度 | 可选维度 |
|--------|---------|---------|
| 开篇卷(V1) | A B C D F | G J |
| 过渡卷 | A B C F | H J |
| 高潮/推翻卷 | A B C D F | E I |
| 多线并行卷 | B C F G H | J |
| 终卷/尾声 | A C D F | H I |
| 暴露/分裂卷 | B C H I | F |

### 🔒评分确认

所有Agent完成后，汇总评分卡：

```
## 达尔文评分卡 v2.0

| 维度 | 评分 | P0 | P1 | P2 | P3 | 趋势 |
|------|------|----|----|----|----|------|
| A 叙事节奏 | {N} | {N} | {N} | {N} | {N} | {首次/↑/↓/→} |
| B 因果逻辑 | {N} | {N} | {N} | {N} | {N} | ... |
| ... | ... | ... | ... | ... | ... | ... |
| 综合 | {加权均分} | {总计} | {总计} | {总计} | {总计} | — |
```

**确认规则**：
- 综合分≥85 → 直接通过，进入Phase 2仅修复P0
- 综合分70-84 → 进入Phase 2修复P0+P1
- 综合分<70 → 进入Phase 2修复P0+P1+P2
- 任何维度≤60 → 该维度强制进入Phase 2

展示评分卡给用户确认。用户可选：
- "通过，进入修复" → Phase 2
- "某维度需要补充分析" → 补充Agent重跑
- "先看详细报告" → 展示具体Agent报告

## Phase 2: 女娲修复（多Agent并行修复）

> **目标**: 对Phase 1发现的问题，通过多Agent并行创造修复方案并执行。
> **核心原则**: 不只列出问题，要创造可执行的修复蓝图。
> **执行方式**: 按问题优先级启动修复Agent，每个P0/P1问题由独立Agent处理。

### 修复Agent设计

每个P0/P1问题启动一个修复Agent，Agent的任务：

1. **明确问题**：一句话说清"哪里不对"
2. **生成方案**：至少3种不同方向的修复方案
3. **评估代价**：每种方案对前后卷的影响（改一卷vs改多卷）
4. **推荐最优**：选代价最小、效果最好的方案
5. **输出修复蓝图**：具体的文件修改指令

### 修复蓝图格式

```
## 修复蓝图: {问题编号}-{简述}

### 问题根因
{一句话}

### 推荐方案
{方案描述}

### 代价评估
- 影响卷: {V3, V5, V6}
- 修改文件: {大纲/03-惨败.md, 设定/角色深化.md}
- 修改量: {小/中/大}
- 对其他问题的影响: {无/会影响#XX}

### 具体修改指令
1. 文件A, 第X段: {旧内容} → {新内容}
2. 文件B, 第Y段: 新增 {内容}
3. ...

### 备选方案
- 方案B: {描述}, 代价{高/中/低}
- 方案C: {描述}, 代价{高/中/低}
```

### 修复Agent并行策略

```
P0问题: 立即启动，全部并行
P1问题: P0修复完成后启动，按卷分组并行（同卷的问题由同一个Agent处理）
P2问题: 批量处理，一个Agent处理所有P2
```

### 交叉验证

修复Agent完成后，启动一个**验证Agent**：
1. 检查每个修复是否引入了新的矛盾
2. 检查不同修复之间是否冲突
3. 检查修复是否破坏了已有的伏笔/线索链
4. 输出验证结果：通过/需调整/冲突

### 🔒修复确认

展示修复蓝图+验证结果给用户。用户可选：
- "按蓝图执行" → 执行修改，进入Phase 3
- "调整方案" → 修改后重新确认
- "跳过某些问题" → 标记为"接受风险"，进入Phase 3

---

## Phase 3: 验证迭代

> **目标**: 验证修复效果，量化改进幅度，迭代直到达标。
> **执行方式**: 对修改过的维度重新启动审计Agent（轻量级，只检查修改影响范围），对比前后评分。

### 评分对比

```
## 达尔文进化记录

| 维度 | Phase 1分 | Phase 3分 | 变化 | 状态 |
|------|----------|----------|------|------|
| A 叙事节奏 | 78 | 85 | +7 | ✅达标 |
| B 因果逻辑 | 87 | 90 | +3 | ✅达标 |
| C 角色弧线 | 85 | 88 | +3 | ✅达标 |
| ... | ... | ... | ... | ... |
| 综合 | 79 | 86 | +7 | ✅达标 |

达标标准: 单维度≥75, 综合≥85
```

### 迭代规则

- 所有维度≥75且综合≥85 → **通过**，保存报告
- 有维度<75 → 该维度回到Phase 2重新修复，最多迭代3轮
- 3轮后仍不达标 → 标记"人工审查"，输出给用户决策

### 进化记录

每次审计结果追加到 `.claude/skills/darwin-skill/results.tsv`：
```
{timestamp}\t{commit}\t{审计类型}\t{Phase1分}\t{Phase3分}\t{status}\t{维度}\t{note}\t{mode}
```

## 问题分级标准

| 级别 | 定义 | 处理方式 |
|------|------|---------|
| **P0-致命** | 因果链断裂、开篇无钩子、关键动作动机缺失、设定根本矛盾 | 必须修复后才能确认 |
| **P1-严重** | 角色行为不合理、节奏拖沓、信息过载、爽点断层、伏笔间距过长 | 建议修复+女娲方案 |
| **P2-中等** | 伏笔悬空、配角工具人化、爽点不足、关系进展缺失 | 标记待优化 |
| **P3-轻微** | 命名/措辞/细节/节奏微调 | 可选修改 |

## 具象化三视图（Phase 1完成后、Phase 2之前执行）

> **触发时机**: 10维度文字审查完成后、🔒评分确认前。强制执行。
> **目的**: 用可视化表格暴露文字审查难以发现的时空矛盾、状态跳跃、物品丢失。
> **执行方式**: 可单Agent逐图输出，也可3Agent并行。

### 时空观图（Space-Time Map）

逐卷标注所有主要角色的**位置**和**时间线**，暴露空间跳跃和时间矛盾。

```markdown
## 时空观图

### 时间线总览
| 卷 | 时间跨度 | 距V1起点 | 关键时间节点 |
|----|---------|---------|-------------|
| V1 | {N天/周} | Day 0 | {兽潮日/出发日/...} |
| V2 | {N天/周} | Day X | {到达边境日/第二波兽潮/...} |
| ... | ... | ... | ... |

### 角色位置追踪
| 角色 | V1位置 | V2位置 | V3位置 | ... | V14位置 | 位置跳跃/矛盾 |
|------|--------|--------|--------|-----|---------|-------------|
| 沈野 | 废墟区 | 边境镇 | {X} | ... | 灵站旧址 | {无/有矛盾} |
| ... | ... | ... | ... | ... | ... | ... |

### 移动路径验证
| 角色 | 卷间移动 | 距离 | 合理耗时 | 大纲交代 | 问题 |
|------|---------|------|---------|---------|------|
| ... | ... | ... | ... | ... | ... |
```

**时空观检查项**：
- 每个主要角色每卷的位置是否明确标注
- 卷间移动的路径/耗时是否在大纲中有交代
- 时间线是否自洽
- 并行线的角色在同一时间点是否在同一区域
- 分兵后各组的距离是否与通讯/汇合条件匹配

### 人物状态观图（Character State Map）

逐卷追踪每个主要角色的**五维状态**：身体/能力/知识/情感/关系。

```markdown
## 人物状态观图

### 沈野状态追踪
| 维度 | V1 | V2 | V3 | ... | V14 | 状态跳跃/矛盾 |
|------|----|----|----|-----|-----|-------------|
| 身体 | 健康 | 轻伤 | {X} | ... | 疲惫但活 | {无/有} |
| 能力 | 拓印萌芽 | {X} | {X} | ... | 熟练 | {无/有} |
| 知识 | 不知真相 | {X} | {X} | ... | 全知 | {无/有} |
| 情感 | 保护妹妹 | {X} | {X} | ... | 释然 | {无/有} |
| 关系 | 沈念+方岩 | {+陆沉/汐} | {+江屿} | ... | {全部} | {无/有} |
```

**人物状态检查项**：
- 身体状态连续性（伤病不能突然消失）
- 能力等级单调性（不能退步/跳级，除非有触发+铺垫）
- 知识范围守恒（已知不遗忘，未知不突然知道）
- 情感弧线递进性（不能回弹，除非有触发事件）
- 关系网单调递增（新关系需要建立事件）

### 物品观图（Item/Artifact Map）

逐卷追踪所有**关键物品**的位置、持有者、状态变化。

```markdown
## 物品观图

### 关键物品追踪
| 物品 | 出现卷 | 当前持有者 | 位置/状态 | 转移历史 | 问题 |
|------|--------|-----------|----------|---------|------|
| 罗盘 | V1 | 方岩→碎裂 | 碎裂 | 方岩持有→碎 | {无} |
| 灵能共振卡 | V1 | 销毁 | 沈念出发前销毁 | 灵站→沈念→销毁 | {无} |
| ... | ... | ... | ... | ... | ... |
```

**物品观检查项**：
- 每个关键物品的完整链条
- 物品不能"消失"（除非有交代）
- 物品不能"凭空出现"（除非有获取途径）
- 知识类物品的持有者与"谁知道什么"一致

## 大纲审查检查清单（单卷验证用）

以下清单用于每卷规划完成后的快速验证（不需启动全量10维度Agent）。

### Agent A: 因果链 + 叙事结构

- [ ] 每个关键事件有充分前因
- [ ] 无"作者方便"事件
- [ ] 触发条件检查（重大行动前有足够信息/动机/压力）
- [ ] 巧合有前因铺垫
- [ ] 本卷开头有钩子
- [ ] 本卷有至少一个高潮场景
- [ ] 本卷结尾留了下一卷钩子

### Agent B: 角色动机 + 行为逻辑

- [ ] 每个关键动作动机匹配（"因为剧情需要"=问题）
- [ ] 角色掌握的信息足以支撑决定
- [ ] 符合Ghost/Lie/Want设定
- [ ] "救/帮/信任/给/隐瞒"类动作有充分理由（仅"善良"不够）
- [ ] 角色状态连续性（上卷末→本卷初一致）
- [ ] 信息差守恒（已知不遗忘，未知不突然知道）

### Agent C: 商业性 + 信息密度

- [ ] 本卷有≥2个爽点
- [ ] 爽点类型多样（不全是"逃跑成功"）
- [ ] 新概念≤5个（超过=过载风险）
- [ ] 新角色≤4个（超过=角色过载）
- [ ] 新概念分层释放（非集中一个段落）
- [ ] 无"教科书段落"（用角色行为展示设定，非直接说明）

### 前后卷交叉验证

- [ ] 角色状态连续性（位置/能力/关系/知识/目标）
- [ ] 承诺追踪（上卷悬念本卷有回应）
- [ ] 伏笔接力（上卷埋的伏笔本卷有推进）
- [ ] 能力连续性（不能突然变弱/变强）
- [ ] 关系连续性（不能"重置"）
- [ ] 下一卷可衔接

## 外部调研触发条件（Phase 2中，修复P0/P1时）

满足以下任一条件，修复Agent必须启动调研（不能闭门造车）：

- [ ] 新设计核心能力体系
- [ ] 新设计重要角色原型（反派/导师/竞争对手）
- [ ] 核心剧情反转设计
- [ ] 涉及现实领域知识（军事/医学/政治/经济）
- [ ] 读者可能质疑"为什么是这样"的设定

调研方法：
1. 同类作品参考（3-5部同类题材）
2. 现实逻辑验证
3. 读者反馈预判
4. 输出3-5条可落地设计建议，标注来源
