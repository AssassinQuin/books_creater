# 人物设计指南

> **核心原则**: 人物丰满多样，不全围着主角转。每个人物都是一个完整的"人"——有状态、有触发器、有语音指纹、有认知边界。

---

## 设计原则

1. **每个人物都有自己的生活在过** — 不出场的时候他们也在做自己的事
2. **每个人都有目标** — 不只是服务于主角剧情的工具人
3. **每个人都有弱点** — 完美的人物不真实
4. **每个人的说话方式不同** — 同一句话 5 个人有 5 种说法
5. **NPC 也要有个性** — 路边摊贩、酒馆老板、巡逻兵，每个人都有独特之处
6. **人物是活的** — 状态会变、关系会动、认知会扩展

---

## 角色蒸馏法（Character Distillation）

> 灵感来源：tavern-card-distiller 的角色卡蒸馏流程。从参考素材中系统提取人物核心，确保不遗漏关键维度。

### 蒸馏步骤

**第一步：信息萃取** — 从素材中提取原始信息
- 直接描写：外貌、身份、能力
- 间接描写：他人评价、环境暗示、历史记载
- 行为证据：关键决策、压力反应、日常习惯

**第二步：内核提炼** — 从原始信息提炼角色内核
- 核心矛盾：内心最深的冲突是什么？
- 行为驱动：什么情况下会做出反常举动？
- 情感锚点：最在意的人/事/信念是什么？

**第三步：维度定标** — 每个维度用具体行为定义，不用形容词
- ❌ "性格坚毅" → ✅ "连续三天不睡觉追查线索，手指磨破也不吭声"
- ❌ "善良温柔" → ✅ "打架时避开要害，但嘴上骂得最难听"
- ❌ "聪明狡猾" → ✅ "每次谈判前都准备三套方案，永远不第一个报价"

**第四步：语音锻造** — 确保一读对话就知道是谁说的
- 提取参考素材中的原话
- 总结句式偏好（长句/短句/省略/反问）
- 定义情绪变化时的语言特征
- 写 3-5 句示例对话作为标定

### 蒸馏模板

```
角色: {名字}
来源: {参考素材}

【萃取】
外貌: (从素材提取的具体描写)
身份: (社会角色/职业/地位)
能力: (已知的技能和水平)
关键行为: (3个最能代表这个人的行为)
他人评价: (其他角色怎么说他/她)

【提炼】
核心矛盾: (内心最深的冲突)
行为驱动: (什么让他/她做出反常举动)
情感锚点: (最在意的东西)
底线: (绝对不做的)
禁忌: (一碰就炸的)

【定标 — 用行为定义】
性格: (不用形容词，写3个具体行为)
弱点: (最致命的缺陷是什么)
习惯: (口头禅/小动作/偏好)

【语音锻造】
句式偏好: (长/短/省略/反问/排比...)
词汇特征: (书面/口语/方言/术语...)
情绪变化: (高兴时→/生气时→/紧张时→)
示例对话:
  日常: "..."
  愤怒: "..."
  紧张: "..."
  安慰别人: "..."
```

## 主角设计

### 必须定义

| 维度 | 问题 | novel-db 字段 |
|------|------|--------------|
| 出身 | 从哪来？家庭背景？ | `background` |
| 外部目标 | 具体要做什么？（活下去/报仇/找到XX） | `goals` |
| 内部渴望 | 深层想要什么？（自由/被认可/安全感） | `goals`（后半段） |
| 性格 | 用 3 个具体行为定义，不用形容词 | `personality` |
| 缺陷 | 最大毛病是什么？推动弧光的核心 | `weaknesses` |
| 习惯 | 口头禅/小动作/偏好 | `speech_style` + `catchphrase` |
| 底线 | 绝对不会做什么？ | `personality`（后半段） |
| 禁忌 | 一碰就炸的点？ | `personality`（后半段） |

### 语音画像（Speech Profile）

> 参照 tavern-card-distiller 的语音定标机制，每个角色必须有完整的语音指纹。

定义内容：
- **句式节奏**: 长句型/短句型/长短交替/省略型
- **词汇层**: 书面词汇/口语/方言/专业术语/粗话频率
- **语气特征**: 反问多/感叹多/陈述为主/爱用比喻
- **情绪变化时的语言偏移**:
  - 轻松时：句式变短，爱开玩笑
  - 紧张时：话变少，用陈述句
  - 愤怒时：嗓门大/冷声线（二选一，符合人设）
  - 受伤时：嘴硬/沉默/转移话题

存入 `speech_style` 字段，格式示例：
```
短句为主，爱用反问。粗话频率中，急了骂娘。轻松时话多带调侃，紧张时变沉默只剩单字。
```

`catchphrase` 存口头禅，如："麻烦死了" / "有意思" / "这不废话吗"

### 动态状态（Dynamic State）

> 借鉴 tavern-card-distiller 的状态追踪系统。长篇连载中人物状态必须可追踪、可演进。

用 `character_update(_status_json=...)` 维护 JSON 状态，结构如下：

```json
{
  "emotional_state": "压抑",
  "emotional_trend": "持续恶化",
  "key_possessions": ["父亲遗留的剑", "一枚不知来历的令牌"],
  "secrets": ["隐藏的血脉", "曾经背叛过师父"],
  "knowledge_scope": ["了解东城势力格局", "不知道师父的真实身份"],
  "current_arc": "从逃避到面对",
  "arc_progress": 0.3,
  "last_major_event": "发现师父的密信",
  "behavioral_flags": {
    "trust_level": "低 — 刚被背叛",
    "combat_style": "保守防守型",
    "social_mode": "警惕，不主动接触"
  }
}
```

**状态更新时机**：
- 每卷结束时更新 `arc_progress`
- 重大剧情后更新 `emotional_state` + `behavioral_flags`
- 获得新物品/信息时更新 `key_possessions` / `knowledge_scope`
- `writing_finish` 后检查是否需要更新

### 主角不能做的事

- ❌ 开始就无敌（没成长空间）
- ❌ 毫无理由地圣母（帮助陌生人不需要理由）
- ❌ 女性角色倒贴（不需要理由就喜欢主角）
- ❌ 所有人都喜欢他（不真实）
- ❌ 永远正确不犯错（无聊）

## 核心配角设计（至少 3 人）

### 配角类型

| 类型 | 功能 | 设计要点 |
|------|------|---------|
| **导师/引路人** | 带主角入门，传授知识 | 有自己的过去和遗憾，不是专职解说员 |
| **搭档/兄弟** | 陪伴主角，制造互动 | 有自己的目标和故事线，不只是附庸 |
| **对手/竞争者** | 激发主角成长 | 有自己的理由，可能最后成为盟友 |
| **羁绊/恋人** | 情感支点 | 有自己的生活，不是等待主角拯救的公主 |
| **信息源** | 提供消息和情报 | 有自己的立场和目的，不是免费百科 |

### 配角独立性检查

每个配角回答以下问题（答不上来说明是工具人）：
1. 他/她自己的目标是什么？（与主角无关的目标）
2. 如果主角不出现，他/她会在做什么？
3. 他/她有什么不为人知的秘密？
4. 他/她最害怕什么？
5. 他/她和主角有利益冲突吗？

### 配角专属：出场节拍器

> 百万字长跑中配角容易"消失"。用状态追踪防止遗忘。

```json
{
  "last_appear_chapter": 45,
  "appear_count_in_volume": 3,
  "current_whereabouts": "在南域执行家族任务",
  "pending_plot_threads": ["与三皇子的秘密交易尚未揭穿"],
  "next_scheduled": "卷四中期回归，带来南域情报"
}
```

**出场间隔规则**：
- 核心配角：不超过 8 章需要出场或侧面提及
- 重要配角：不超过 15 章需要出场或侧面提及
- 超过间隔 → `health_check` 标黄 → 安排侧面提及（路人转述/书信/回忆）

## 反派设计

### 反派不是"坏人"，是"对手"

好的反派要让读者觉得"如果我是他，我也可能这么做"。

### 必须定义

| 维度 | 问题 | novel-db 字段 |
|------|------|--------------|
| 目标 | 他想要什么？ | `goals` |
| 理由 | 为什么这个目标对他很重要？ | `background` |
| 手段 | 他用什么手段？为什么选这种？ | `personality` |
| 底线 | 他绝对不会做什么？ | `personality` |
| 弱点 | 他有什么致命缺陷？ | `weaknesses` |
| 视角 | 站在他的角度，他是对的吗？ | `arc_notes` |

### 反派层级

| 层级 | 出现时机 | 特点 |
|------|---------|------|
| 小BOSS | 前10章 | 展示主角实力的垫脚石，但要有自己的故事 |
| 中BOSS | 第一卷中后期 | 有自己的势力，对主角构成真正威胁 |
| 大BOSS | 贯穿全书 | 隐藏在幕后，逐渐揭示其全貌 |
| 隐藏BOSS | 后期反转 | 可能是主角身边的人，颠覆读者认知 |

### 反派状态追踪

```json
{
  "threat_level": "区域级",
  "current_scheme": "暗中控制东城商会",
  "known_by_protagonist": ["知道他是商会背后的手"],
  "unknown_by_protagonist": ["真实身份是前朝遗族", "与师父有旧"],
  "next_move": "在主角突破金丹前完成布局",
  "relationship_to_protagonist": "尚未正面接触，仅通过代理人交锋"
}
```

## NPC/路人设计

### 为什么 NPC 很重要

路人的一句话可以比作者写三段设定更有用：

**反面**（空洞）:
> 这座城市是大陆上最繁华的商贸中心，汇聚了来自各地的商人和冒险者。

**正面**（侧面描写）:
> 街边卖烤肉串的大爷看了他一眼："小伙子外地来的吧？看你这身行头，刚到潜龙城？告诉你，晚上别往南区走，最近那边不太平。对了，你要是手头紧，东城的佣兵公会正在招人。"

### NPC 设计模板

```
角色: {名字或描述}
出场: 在哪一章/什么场景
功能: 提供信息/制造氛围/侧面展示世界
特点: 一句话概括他的独特之处
说话风格: {方言/口头禅/语气}
世界观触发: 他能自然带出什么设定信息
```

> 世界观触发（World-Book Trigger）：借鉴 tavern-card-distiller 的 lorebook 触发机制。每个 NPC 关联 1-2 条世界观信息，出场时自然带出，而非硬性科普。

### 常用 NPC 场景

- **摊贩/店主**: 用物价和商品展示经济体系
- **酒馆常客**: 用八卦和传闻展示世界观
- **巡逻兵/守卫**: 用规矩和检查展示社会秩序
- **同行/竞争对手**: 用对比展示主角的水平和特点
- **老前辈/退休强者**: 用回忆展示历史和传说

## 认知地图（Knowledge Map）

> 每个人物的知识边界不同。信息差是制造张力和悬念的利器。

### 知识维度

| 类型 | 说明 | 存储位置 |
|------|------|---------|
| 已知事实 | 角色确定知道的信息 | `status.knowledge_scope` |
| 未知但相关 | 角色不知道但与己相关的信息 | `status.secrets`（别人的视角） |
| 错误认知 | 角色以为对但其实错的信息 | `arc_notes` 标注 |
| 信息差冲突 | 两个角色对同一件事知道的不同版本 | 关系描述中标注 |

### 信息差运用

- **读者知道，角色不知道** → 悬念/紧张
- **角色知道，读者不知道** → 伏笔/揭秘
- **角色A知道，角色B不知道** → 误会/戏剧性
- **所有人都以为对但其实错** → 反转

## 人物关系管理

### 关系类型

```
师徒/师生  —  传承、期望、叛逆
兄弟/战友  —  信任、牺牲、分歧
恋人/暧昧  —  障碍、误解、成长
敌对/竞争  —  动机、升级、转化
利用/交易  —  利益、背叛、反转
亲属/血缘  —  羁绊、责任、冲突
```

### 关系动态追踪

> 关系不是静态的。`relation_create` 的 `intensity` (1-10) 和 `description` 应随剧情更新。

关系演进路径（示例）：
```
陌生人 → 熟人 → 信任 → 背叛 → ？
敌人 → 对手 → 尊重 → ？
利用 → 习惯 → 依赖 → ？
```

每卷结束时检查：哪些关系需要更新 `intensity` 和 `description`？

### 关系图使用

用 `memory_graph` 工具：
- `memory_graph(action="subgraph", hash={主角hash}, radius=2)` 查看主角的二度关系
- 发现孤立的角色（没关系的NPC需要补充关联）
- 发现关系过密的区域（是否所有角色都只围着主角转？）

## 设计流程总览

```
A3 人物设计
│
├── 1. 读 world_query 召回世界观设定
│
├── 2. 角色蒸馏（每个角色走一遍）
│   ├── 萃取：从灵感/参考素材提取原始信息
│   ├── 提炼：内核矛盾 + 驱动 + 锚点
│   ├── 定标：用行为定义各维度
│   └── 锻造：语音画像 + 示例对话
│
├── 3. 写入 novel-db
│   ├── character_create(name, role, personality, speech_style, ...)
│   ├── character_update(_status_json={动态状态JSON})
│   └── relation_create(from, to, type, intensity, description)
│
├── 4. 交叉验证
│   ├── 群像独立检查（每人5问）
│   ├── 知识地图交叉（谁知道什么、信息差在哪）
│   ├── 世界观触发映射（NPC 关联哪些设定）
│   └── 关系网完整性（无孤立节点、非星型拓扑）
│
└── 5. git commit -m "A3: 人物完成 - {小说名}"
```
