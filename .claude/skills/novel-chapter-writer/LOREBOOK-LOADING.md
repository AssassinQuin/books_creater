# LOREBOOK-LOADING.md — 世界知识按需注入

> 本文档是 novel-chapter-writer Step 2.1 的详细指令。
> 借鉴 SillyTavern Lorebook 机制，将静态世界观转化为按需注入的智能知识图谱。

## Lorebook 加载流程（强制）

```
Step 2.1 世界知识注入
  │
  ├─ 2.1.1 加载常驻条目（constant=true 的全部条目）
  │   → 从 设定/lorebook/entries/ 读取所有 constant: true 的 YAML
  │   → 按 priority 排序，注入 before_char 位置
  │   → 12个核心常驻条目（LB-001/002/004/007/029/031/038/041/050/056/059/064）
  │
  ├─ 2.1.2 收集扫描文本
  │   → 当前章节事件大纲（从 chapter.outline 提取）
  │   → 上一章结尾摘要（前文回顾）
  │   → 出场角色名称列表
  │   → 当前场景地点/环境名
  │
  ├─ 2.1.3 关键词匹配
  │   → 遍历所有按需条目（constant=false）
  │   → 检查 keys 是否在扫描文本中命中（任一命中即通过）
  │   → 如果 selective=true，还需检查 secondary_keys + selective_logic
  │   → 检查 volume_range 是否包含当前卷
  │
  ├─ 2.1.4 时序过滤
  │   → 检查 delay：当前章号 < delay → 跳过
  │   → 检查 cooldown：距离上次激活章数 < cooldown → 跳过（除非 sticky 活跃）
  │   → 检查 sticky：上次激活 + sticky > 当前章 → 自动激活（跳过关键词检查）
  │
  ├─ 2.1.5 递归扫描
  │   → 新激活条目的 content 加入扫描文本
  │   → 检查 related 字段关联的条目是否应激活
  │   → 最多递归2层，防止无限展开
  │
  ├─ 2.1.6 包容组竞争
  │   → 同 group 的激活条目只保留权重最高的1个
  │
  ├─ 2.1.7 Token 预算裁剪
  │   → Lorebook 总预算 = 上下文窗口 × 20%（硬上限 4096 token）
  │   → 常驻条目占预算 40%（永不裁剪）
  │   → 按需条目按 priority 从高到低加载，超出预算停止
  │   → ignore_budget: true 的条目不受预算限制
  │
  └─ 2.1.8 分配注入位置
      → before_char: 基础世界观（势力/经济/核心设定）
      → after_char: 补充设定（物品详情/军事体系/医疗体系）
      → at_depth: 场景切换提示（写入章节中间位置）
      → author_note: 写作约束（风格提醒/禁用词/注意事项）
```

## 选择性逻辑速查

```
selective=false → keys 任一命中即激活
selective=true  → keys命中 + 次关键词检查：
  0 AND_ANY  → keys命中 且 (任一secondary命中)
  1 NOT_ALL  → keys命中 且 (并非所有secondary命中)
  2 NOT_ANY  → keys命中 且 (没有secondary命中)
  3 AND_ALL  → keys命中 且 (所有secondary命中)
```

## 与现有加载协议的集成

原 chapter-writer 加载流程：
```
1. 卷级大纲 → 2. 事件大纲 → 3. 伏笔/线索 → 4. 世界观 → 5. 地图
→ 6. 人物快照 → 7. 环境快照 → 8. 事件快照 → 9. 前文回顾
```

更新后：
```
1. 卷级大纲
2. 事件大纲
3. 伏笔/线索追踪
4. ★ Lorebook 按需注入（替代原"世界观"全量加载）
   ├─ 4a. 常驻条目（12个核心设定）
   └─ 4b. 按需条目（关键词触发）
5. 地图
6. 人物快照（从 设定/人物/{角色}.md 加载）
7. 环境快照
8. 事件快照
9. 前文回顾
```

**关键变化**：步骤4从"全量加载世界观md文件"变为"Lorebook按需注入"，大幅减少token消耗并提高写作精度。

## 扫描文本来源权重

| 来源 | 权重 | 说明 |
|------|------|------|
| 章节事件大纲 | 最高 | 当前要写的内容，最相关 |
| 出场角色名 | 高 | 角色名触发相关势力/物品/关系 |
| 场景地点名 | 高 | 地点名触发相关环境/势力设定 |
| 前文回顾 | 中 | 上一章内容的延续 |
| 已激活条目content | 低 | 递归发现关联设定 |

## 写作时的设定一致性检查

Lorebook 加载完成后，写作时遵守以下规则：

1. **禁止矛盾**：正文中的设定必须与已激活的 Lorebook 条目一致
2. **禁止超范围**：不能使用未激活条目中的设定（除非是常识性内容）
3. **物品闭环**：使用任何灵能物品时，必须有对应的 Lorebook 条目支撑（外观/功效/限制）
4. **能力边界**：角色使用能力时，参考人物档案中的能力体系 + Lorebook 中的能力等级
5. **经济一致**：涉及交易/物价时，参考 LB-029 灵晶 + 货币体系的数值

## 手动激活

写作时如果发现需要某个未自动激活的条目，可以手动指定：
```
[手动激活: LB-042 灵站建成前后变化]
```
系统会将该条目加入当前章节的激活列表，并记录到 state.yml。
