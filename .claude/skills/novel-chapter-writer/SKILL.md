# 逐章写作引擎

> 共享约定：读 `references/shared-conventions.md`
> 引擎加载：读 `references/engine-loading.md`（加载协议）
> 快照引擎：读 `references/engine-snapshot.md`（场景/事件/人物快照）
> 环境引擎：读 `references/engine-environment.md`（环境5要素+感官描写）
> 对话引擎：读 `references/engine-dialogue.md`（差异化对话+弦外之音+通感）
> 动作引擎：读 `references/engine-action.md`（动作链5拍+空间感知+具体化）
> 物品引擎：读 `references/engine-item.md`（物品全生命周期+一致性）

---

## 强制流程

```
Step 0 断点检测 → Step 1 引擎加载上下文 → Step 2 写正文 → Step 3 🔒状态同步 → Step 4 存盘
```

**Step 3 是不可跳过的强制步骤**。每章写完后必须执行质量检查，未完成则拒绝存盘。

---

## Step 0: 断点检测（续写场景必执行）

当用户说"继续写"/"接着写"时，在Step 1之前执行：

```
1. 检查目标章节文件：glob("novels/{小说名}/正文/第{NNN}章-*.md")
2. 检查writing_finish记录
3. 三态分支：
   (a) 文件不存在 → 正常从Step 1开始
   (b) 文件存在但<2500字且无finish → 🔒提示续写还是重写
   (c) 文件存在且≥2500字 → 🔒提示覆盖还是写下一章
```

新章节跳过此步骤。

---

## Step 1: 引擎加载上下文

按 `engine-loading.md` 的三级协议加载：

### Tier 1 必须加载

```
1. writing_start(novel_id, chapter_number) → 基础信息
2. volume_get(volume_id) → 当前卷规划
3. 每个出场人物 character_get → 按需提取:
   - 有对话 → speech_style + catchphrase + personality
   - 有动作 → ability_level + status
   - 有外观 → appearance + gender
4. relation_list → 人物关系（对话语气依据）
```

### Tier 2 按需加载

```
5. world_query(category="location", name="{本章地点}") → 环境档案
6. world_query(category="ability"/"economy", name="{物品名}") → 物品档案
7. world_query(category="history", name="{相关历史}") → 历史层
8. foreshadow_list(status="planted") → 未回收伏笔
```

### Tier 3 增强加载（重要章节时）

```
9. timeline_query(from_chapter=N-3, to_chapter=N) → 近期事件
10. dimension_query(from_chapter=N-3) → 近期变化
```

### 场景快照生成（写前必做）

按 `engine-snapshot.md` 生成本章场景快照（≤200字速记）：

```
地点: {参照环境档案}
时间: {时段+天气}
人物: {出场人物+位置+身体状态}
物品: {关键物品+状态}
目的: {这章的人物目标}
环境基线: {1-2个关键感官细节}
```

## Step 2: 写正文

### 2.0 前置检查（强制）

```
读 设定/写作执行规范.md — 小说特定规则
读 references/writing-style.md — 通用写作风格标准
读 references/scene-type-guide.md — 场景类型策略
读 references/scene-composition-guide.md — 复杂场面生成
读 references/scene-deepening-guide.md — 场景深化指南
```

**大纲事件拆解与分类（强制）：**

从 chapter.outline 提取事件，按逻辑排序：核心主线 > 支线 > 填充

**事件分类体系：**

| 事件类型 | 作用 | 特征 |
|---------|------|------|
| **线索推动型** | 推动线索进展 | 有线索标记（F1/F2...） |
| **人物关系型** | 推动关系变化 | 互动后信任/怀疑/依赖变化 |
| **场景铺垫型** | 为高潮铺垫 | 不直接推进，让后续更有冲击力 |
| **人物展示型** | 自然展现人物 | 通过对话/行动体现，禁评价词 |
| **伏笔埋设型** | 长线回收准备 | 必须填foreshadow_plant |

**事件层级：**

| 层级 | 粒度 | 爽点要求 |
|------|------|---------|
| 超级 | 卷级 | 卷终决战/命运转折 |
| 大 | 弧级(8-12章) | Boss战/重大转折 |
| 中 | 段级(3-5章) | 阶段胜利/关系突破 |
| 小 | 章级 | 小胜利/小揭露/角色高光 |
| 微 | 场景级 | 对话钩子/信息投放 |

**爽点密度（强制执行）：**

- 微/小爽点：每1章至少1个
- 中爽点：每3-5章
- 大高潮：每8-12章
- 超级高潮：每卷1-2次
- **平路不超过3章**

**卷级事件侧重：**

| 卷类型 | 冲突 | 揭露/关系 | 成长/日常 | 伏笔 |
|--------|------|----------|----------|------|
| 开篇卷 | 20% | 35% | 30% | 15% |
| 成长卷 | 20% | 35% | 30% | 15% |
| 高潮卷 | 35% | 25% | 25% | 15% |
| 过渡卷 | 15% | 30% | 40% | 15% |
| 终卷 | 30% | 25% | 25% | 20% |

**事件设计三大思维模型：**

1. **碰撞引擎**：因果链+信息不对称碰撞+空间共置碰撞
2. **信息缺口张力**：每章至少1个信息缺口（5W）
3. **自信犯错**：合理决策+信息不完整→出错→共情

**升级周期**：铺垫→积累→突破→展示（V1-4: 每5-8万字; V5-10: 每10-15万字; V11-14: 每15-20万字）

**输出：事件序列表**

| 序号 | 事件 | 类型 | 层级 | 涉及人物 | 爽点 | 线索/缺口 |
|------|------|------|------|---------|------|----------|

---

### 2.1 章节结构模板

**起承转合是参考骨架，不是模具。**

| 段落 | 占比 | 字数 | 内容 |
|------|------|------|------|
| 起 | ~17% | ~500字 | 收束上章+引入核心冲突 |
| 承 | ~40% | ~1200字 | 2-3事件推进+日常/NPC/世界观 |
| 转 | ~27% | ~800字 | 转折/冲突升级 |
| 合 | ~17% | ~500字 | 情绪峰值+章末钩子 |

**反AI结构僵化（强制）— 每5章至少2种变体：**

| 变体 | 适用 | 结构 |
|------|------|------|
| 标准型 | 常规推进 | 起→承→转→合 |
| 突入型 | 延续高潮 | 直接从转开始→合留悬念 |
| 日常型 | 过渡铺垫 | 起→长段日常承→安静收束 |
| 倒叙型 | 揭露回忆 | 合段开头→倒回起→承→解释 |
| 碎片型 | 多线切换 | 3-4个短场景碎片拼接 |
| 螺旋型 | 高潮核心 | 起极短→承极长→转爆发→合极短 |

**章末钩子4种（不是每章都要）：** 悬念式 / 反转式 / 情绪炸弹 / 信息投放

**4层内容模型（每章配比）：**

| 层 | 内容 | 占比 |
|---|------|------|
| A推进层 | 主线/冲突/升级 | 40-50% |
| B人物层 | 对话/心理/关系 | 25-30% |
| C世界层 | 环境/NPC/世界观 | 15-20% |
| D氛围层 | 感官/节奏/伏笔 | 5-10% |

---

### 2.2 按事件序列写作

从事件序列表逐一展开：

1. **环境搭建** → 参照 `engine-environment.md` 的5要素，首次完整、再访只写变化
2. **人物对话** → 参照 `engine-dialogue.md` 的关系差异化+弦外之音+微表情
3. **动作场景** → 参照 `engine-action.md` 的5拍+空间感知+具体化
4. **物品使用** → 参照 `engine-item.md`，加载档案保持一致
5. **过渡到下一事件** → 空行+过渡句

**变速原则：** 关键情节慢写（多感官多细节）、过渡情节快写（长句概述）

**战斗场景** → 使用 `/novel-battle` 独立skill处理（分镜→写正文→审计），再整合回本章

**场景搭建规则（强制）：**

每个场景100-200字五感铺垫（参照 `engine-environment.md` 感官层）：

| 感官 | 内容 | 示例 |
|------|------|------|
| 视觉 | 光影/色彩/细节 | 晨光照亮浮尘 |
| 听觉 | 环境音/远声 | 矿坑轰鸣像地底呼吸 |
| 嗅觉 | 气味 | 铁锈味混冷气 |
| 触觉 | 温度/质感 | 冷风冻得手麻 |
| 氛围 | 2-3感官综合 | 晨雾贴地涌，压得人喘不过气 |

**复杂场面（3+人）→ 角色矩阵**（见 scene-composition-guide.md）：

| 角色 | 目标 | 障碍 | 对他人态度 | 信息持有 |
|------|------|------|-----------|---------|

**场景缝合**：优先软过渡和零换行，避免全部硬切。

---

### 2.3 人物鲜活化（强制）

参照 `engine-dialogue.md` 的完整规则，核心要点：

**微表情与动作细节（禁止直白情绪词）：**
- ❌ "他惊讶""愤怒地说""悲伤地说"
- ✅ 手停在半空/指节敲桌/喉结动了动/嘴角压紧
- 每段对话至少1个微表情/动作细节

**说话风格差异化** → 从 character_get 的 speech_style/catchphrase 提取，按关系调节语气

**口头禅自然融入**：首次建立2-3次，后续每3-5次对话出现一次

---

### 2.4 NPC互动规则（强制）

**每章至少2个新NPC（非路人甲乙）：**

| 类型 | 动机 | 对话特点 |
|------|------|---------|
| 商贩 | 利益驱动 | 价格变动/供需/行情 |
| 居民 | 地区文化 | 生活态度/舆论/流言 |
| 军人 | 专业背景 | 术语/经验/立场 |
| 逃亡者 | 创伤求生 | 谨慎/回避/试探 |

NPC必须有：姓名/绰号 + 背景暗示 + 可见动机 + 与主角的互动痕迹

---

### 2.5 分支事件（强制）

- 分支事件占每章 **15%-25%** 字数
- 类型：日常闲聊/世界观观察/环境细节/人物小冲突/过渡填充
- 分支必须涉及人物互动或世界观展示
- 分支与主线自然过渡

---

### 2.6 内容丰富度检查（14项强制）

| 检查项 | 要求 |
|--------|------|
| 章节结构 | 使用了合适变体（非全部标准起承转合） |
| 结构变化 | 近5章至少2种不同变体 |
| 章末钩子 | 有钩子或确认是日常型 |
| 爽点密度 | 本章至少1个微/小爽点 |
| 信息缺口 | 至少1个（5W） |
| 日常事件 | 2-3个日常场景 |
| NPC出场 | 至少2个有动机的新NPC |
| 场景搭建 | 每场景五感氛围铺垫 |
| 世界观展示 | 至少3个元素自然融入 |
| 人物性格 | 微表情/动作展示（禁直白词） |
| 分支事件 | 占15%-25%字数 |
| 4层内容 | A40-50%+B25-30%+C15-20%+D5-10% |
| 反注水 | 无孤立感官/无因果过渡/无重复意象（→见 scene-deepening-guide.md） |
| 场景密度 | 每3段至少1段"同时做2+件事" |

---

### 2.7 字数分段控制（强制）

- **最低**: 3000字（不含标点）
- **目标**: 3000-5000字
- 每500字暂停检查字数
- 不足3000时用场景深化技法（→见 scene-deepening-guide.md），禁止注水
- 超过5000时考虑拆章

---

## Step 3: 状态同步（强制）

### 3.1 质量检查清单

| 检查项 | 标准 |
|--------|------|
| 事件完整性 | 大纲事件全部展开 |
| 事件类型混合 | 5种类型合理混合 |
| 分支事件 | 1-2个大纲外分支，15%-25% |
| 场景搭建 | 每场景100-200字五感铺垫 |
| 世界观植入 | 至少3个元素自然融入 |
| NPC出场 | 至少2个有动机NPC |
| 人物鲜活 | 微表情/动作，禁直白情绪词 |
| 口头禅 | 主要角色口头禅自然出现 |
| 字数达标 | ≥3000字 |
| 线索埋设 | 伏笔已标记并填写foreshadow_plant |
| 人物关系 | 互动体现关系变化 |
| 微动作泄露 | 离别/转折有微动作（禁"不舍""留恋""难过"） |
| 世界观自然度 | 通过场景/动作/对话带出，非角色科普 |
| 逻辑连贯 | 因果清晰，决策符合已知信息 |
| NPC传授途径 | 知识传授有合理途径（有交换才透露敏感信息） |

### 3.2 数据库同步（增量更新，参照 engine-snapshot.md）

```
1. writing_finish(chapter_id, summary, key_events, characters_involved, new_foreshadows, ...)
2. timeline_add() → 本章时间线
3. character_update() → 只更新变化的状态字段
4. relation_create/update() → 关系变化
5. foreshadow_plant/recall() → 伏笔回收
6. dimension_log() → 维度变化
7. 角色蒸馏文件 → novels/{小说名}/设定/角色蒸馏/{角色}-V{卷}CH{章}.md
   必含：位置/行为/心理/身体·受伤/装备·消耗/伏笔状态/下章预判
8. 受伤+物品同步 → character.status.injuries + inventory
9. 新设定同步 → world_upsert 写入新物品/异兽/能力/地点/势力
```

### 3.3 拒绝存盘条件

- 总字数 < 2500字
- 大纲事件未完成且无拆分方案
- 世界观植入 < 3个
- NPC < 2个
- 场景搭建缺失
- 人物描写直白（直白情绪词）
- 分支事件 < 15%

---

## Step 4: 存盘

```
novels/{小说名}/正文/第{NNN}章-{标题}.md
```

标题来自大纲或自拟，2-4字。
