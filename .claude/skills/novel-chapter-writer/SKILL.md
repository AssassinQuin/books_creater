# 逐章写作引擎（优化版）

> 共享约定：读 `.claude/skills/novel-writer/references/shared-conventions.md`（含流程纪律）

---

## 强制流程

```
Step 1 注入全量上下文 → Step 2 写正文 → Step 3 🔒状态同步 → Step 4 存盘
```

**Step 3 是不可跳过的强制步骤**。每章写完后必须执行质量检查，未完成则拒绝存盘。

---

## Step 1: 注入全量上下文

```
writing_start(novel_id, chapter_number)
→ 基础信息（前3章摘要+活跃人物+未回收伏笔）
```

**跨大纲全量加载（强制）：**

```
1. world_query(category="faction") → 势力范围、当前势力关系
2. world_query(category="location") → 区域设定、本章涉及地点详情
3. world_query(category="ability") | world_query(category="economy") → 物品/资源体系
4. character_get(character_id) → 章节涉及人物最新状态(status含position/inventory/mental_state)
5. relation_list() → 人物关系网，判断对话立场/冲突来源
6. timeline_query(from_chapter=1, to_chapter=当前章) → 全卷时间线，避免矛盾
7. volume_get(volume_id) → 当前卷完整规划，理解本章在卷中位置
```

## Step 2: 写正文

### 2.0 前置检查（强制）

```
读 设定/写作执行规范.md
```

**大纲事件拆解与排序（🔴 强制）：**

```
从 chapter.outline 中提取所有事件（用 + 分隔），按逻辑顺序排序：
1. 事件优先级：核心主线 > 支线 > 填充
2. 时间顺序：前序事件在前，后序事件在后
3. 因果连贯：每个事件必须推动剧情/人物关系/埋设线索
4. 缺失补充：大纲未列出的必要过渡事件（如时间过渡、空间移动）
```

**大纲与生成逻辑（强制执行）：**

大纲是主干，事件是枝干。每章生成时：

1. **线索推动型事件**：为后续事件/章节铺垫
   - 埋设线索，为后续回收做铺垫
   - 示例：方岩给路线图→后续路线异常事件
   - 特征：有明确伏笔标记（F1/F2...）

2. **人物关系型事件**：推动人物情感/立场变化
   - 建立/改变人物间信任/怀疑/依赖关系
   - 示例：沈念发病→沈野焦虑加深

3. **场景铺垫型事件**：为高潮/转折做准备
   - 营造氛围、展示世界观、引入关键元素
   - 示例：兽潮夜日常→沈野创伤回忆铺垫

4. **人物展示型事件**：自然展现人物特点
   - 通过对话/行动展现性格、能力、口头禅
   - 不直白描述"他善良""她坚强"
   - 示例：沈野用冷漠边界保护沈念，细节动作体现关心

5. **伏笔埋设型事件**：为长线回收做准备
   - 明确标记为伏笔，填写 foreshadow_plant
   - 必须有回收章节规划（planned_recall_chapter）
   - 示例：碎罗盘→F5伏笔，V5回收

**生成原则：**
- 事件不能堆砌，要有因果推进
- 每类事件合理混合，避免单类型重复
- 分支事件占每章15%-25%字数
- 大纲事件是主线必须完成，分支事件可增删

**输出：事件序列表**

| 序号 | 事件内容 | 涉及人物 | 预期目标 | 线索埋设 |
|------|----------|----------|----------|----------|
| E1 | {事件1} | {人物} | {目标} | {线索} |
| E2 | {事件2} | {人物} | {目标} | {线索} |
| ... | | | | |

**强制规则：**
- 事件必须按顺序展开，不可跳跃或合并
- 每个事件必须含至少1个人物互动或世界观展示
- 主线事件不得少于1000字
- 支线事件用于铺垫人物关系/世界观，不得偏离主线

### 2.1.1 按事件序列写作

```
从事件序列表中选择下一个事件E，按以下结构展开：
1. 场景搭建（100-200字环境+氛围）
2. 人物互动（基于关系网和人物档案）
3. 剧情推进（完成事件目标）
4. 线索埋设（自然融入世界观）
5. 过渡到下一事件（空行+过渡句）

每个事件完成后，标记E为已完成，继续下一事件
```

**场景搭建规则（强制执行）：**
- 视觉层：光影、色彩、物体细节（如"晨光穿过窗缝照亮浮尘"）
- 听觉层：环境音（风声/远处的谈话/机械运转声）
- 嗅觉层：气味（饭菜/金属/雨后泥土）
- 触觉层：温度、质感、重力感
- 氛围铺垫：用2-3个感官细节建立场景基调

**示例**："废墟的晨雾贴着地面涌，铁锈味混着隔夜的冷气。远处矿坑传来机械轰鸣，像地底的呼吸。"

**人物互动规则：**
- 查阅relation_list，判断人物间立场（盟友/敌对/中立）
- 参考人物档案中的speech_style/catchphrase/behavioral_flags
- NPC对话需体现背景和动机（非路人甲乙）
- 主要角色每次互动要有性格/关系推进

---

### 2.2 人物鲜活化规则（强制执行）

**微表情与动作细节：**
- 禁用"他惊讶""难以置信""愤怒地说"等直白描述
- 用动作体现情绪："手停在半空"（惊讶）、"指节敲桌"（不耐烦）、"喉结动了动"（紧张）
- 眼神/嘴角/姿态变化：每段对话至少1个细节

**说话风格差异化：**
- 冷漠角色（沈野）：短句、少标点、被动语态、"嗯"结尾
- 阳光角色（沈念）：口语化、感叹词、主动语态、"那个..."
- 压抑角色（方岩）：慢节奏、停顿、省略号
- 专业角色（灵站员工）：术语+礼貌、公式化

**口头禅自然融入：**
- 从character_get提取catchphrase字段
- 首次登场时建立：用2-3次对话自然植入
- 后续使用频率：每3-5次对话出现一次
- 如角色无预设口头禅：根据性格临时生成（沈野：那倒是.../沈念：嗯...）

**示例**：
```
沈野："嗯。"（看窗外）"雾太厚。"
沈念："哥哥，你又不说话..."（低头折衣角）"那个...方叔是不是又要来？"
```

---

### 2.3 世界观自然植入规则（强制执行）

**每章至少3个世界观元素：**
- 货币体系：铜币/银币/金币/灵晶的具体使用场景
  - 示例："三个铜币一碗杂粮""这袋灵晶能换半年饭钱"
- 宗教元素：教会的仪式/教义/祭司的日常表现
  - 示例："祭司路过时居民低头致敬""教义说黑月是天恩"
- 俚语/黑话：特定群体的语言习惯
  - 示例：觉醒者称普通人"市民"的轻蔑语调
- 食物/生活：具体食物名称+制作方式
  - 示例："杂粮饼""灵酒""黑月糕"
- 服饰/器具：灵能驱动的日常用品
  - 示例：灵能照明石/通讯石/检测器

**植入原则：**
- 不堆砌：通过人物对话或动作自然带出
- 语境契合：世界观元素必须贴合场景和人物身份
- 避免说明：用"展示"而非"告诉"（用人物视角体验而非作者介绍）

**示例**：
```
"三十五个铜币。"沈野数出钱，压在柜台上。"昨天两碗。"
"够了。"老板收起硬币，扔来一个布包。"黑月节要到了，这布染过。"（宗教+食物）
```

---

### 2.4 NPC互动规则（强制执行）

**每章至少2个新NPC出场（非路人甲乙）：**
- NPC命名：有姓名/绰号/职业标识
- 背景暗示：通过对话/动作透露NPC身份
- 动机可见：NPC有明确目标/立场，不是工具人
- 记忆点：NPC与主角的互动留下痕迹（后续可呼应）

**NPC类型与执行：**
- 商贩NPC：体现利益驱动+本地物价+市场动态
- 居民NPC：体现地区文化+生活态度+对势力看法
- 雇佣/军人NPC：体现专业背景+任务经验+世界观立场
- 逃亡者/流浪者NPC：体现创伤+求生状态+信息价值

**示例**：
```
"陈三，又来？"老欠的店主抬头，手还擦着台面。"灵站又加量了？"
"嗯。"沈野把袋子放地上。
"上周三十，这周五十。"店主摇头，从架下摸出一份清单。"老欠那边也不容易，他涨价了。"
```

---

### 2.5 分支事件触发（强制执行）

**大纲是主干，必须扩展枝干：**
- 每章至少1个大纲外的分支事件
- 分支类型：
  - 日常闲聊：路人谈话/邻里互动/集市偶遇
  - 世界观观察：看到灵能公告栏/集团巡逻队/异灵传闻
  - 环境细节：天气变化/动物行为/建筑特色
  - 人物小冲突：误会/争执/合作解决
  - 过渡填充：空间移动/时间流逝/准备动作
- 分支目的：不推动主线，但丰富世界、铺垫人物、建立氛围

**分支事件示例（以第1章为例）：**
- 路边偶遇其他拾荒者交换情报
- 灵站公告栏看到兽潮预警
- 集市角落黑市交易灵晶的对话
- 观察矿工排队领装备的场景
- 沈念和邻居小孩玩闹的片段

**执行原则：**
- 分支事件字数占每章15%-25%
- 分支与主线自然过渡，不突兀切入
- 分支必须涉及人物互动或世界观展示

### 2.1 角色分析指导（让人物活过来）

**目标**：基于novel-character技能的完整人物档案，使用角色蒸馏法分析当前剧情人物，推理反应/行为、话语，指导写作。

**强制遵守：**
- 最低字数：2500字（不含标点）
- 目标字数：2800-3500字
- 内容依据：本章大纲为纲，世界观/人物状态为准
- 检查清单：逐项勾选，写后逐项确认

**内容丰富度强制检查（9项）：**

| 检查项 | 强制要求 | 未达标处理 |
|--------|----------|----------|
| ✅ 日常事件 | 至少2-3个日常场景（衣食住行/闲聊/观察/训练） | 扩展日常场景 |
| ✅ NPC出场 | 至少1-2个新NPC出场（非路人甲乙） | 补充NPC互动 |
| ✅ 场景搭建 | 每个场景必须有环境描写+氛围铺垫（100-200字） | 补充场景描写 |
| ✅ 世界观展示 | 至少1个世界观元素自然融入（货币/宗教/服饰/俚语/食物） | 自然植入设定 |
| ✅ 人物性格 | 通过行动/话语/微表情展示人物（不用"他惊讶"） | 增加细节动作 |
| ✅ 分支事件 | 至少1个非大纲的枝干事件 | 补充支线内容 |
| ✅ 人口密度 | 村/镇等生活场景暗示"几十人"活跃 | 增加背景人物 |
| ✅ 口头禅/梗 | 主要角色1-2个口头禅或习惯动作 | 增加人物特色 |
| ✅ 短章舒适 | 字数过多可拆分章节，保证阅读节奏 | 分章节 |
| ⚠️ 分割符 | 禁用 `---` 过度使用场景分隔 | 用空行或过渡句 |

**字数分段控制：**
- 预估目标：2800-3500字
- 写作中每约500字暂停一次，检查当前字数：
   - 如当前字数 < 2500 且接近大纲结尾：警告"字数不足，需扩展日常场景"
   - 如当前字数 > 3500 且大纲未完：警告"大纲未完但字数已超，考虑拆分为第X章上+第X章下"
- 字数强制：最终字数必须 ≥ 2500，否则拒绝存盘

### 2.1 角色分析指导（让人物活过来）

**目标**：基于novel-character技能的完整人物档案，使用角色蒸馏法分析当前剧情人物，推理反应/行为、话语，指导写作。

**世界观一致约束（新增）：**
- **人物离开地区后返回**：人物离开某地区后"后面回来"期间，当地情况、人物、饮食、物价等保持不变
- **人物重逢记忆一致**：人物再次到曾经到过的地区或场景，记忆中的人物关系、当地习俗、地理认知要一致
- **多人物同地场景**：不同人物去同一个地方，可能是偶然相遇，但要通过对话说明当地特色、人物、饮食等
- **时间线连贯**：人物离开A地，去B地办事，"后面回来"——这段时间内B地的剧情不能推进到"前面"

**执行流程：**

```
1. character_get(character_id) × N → 获取所有涉及人物的完整档案
2. 角色蒸馏分析（7步）：
	   a. 萃取：从档案中提取外貌、身份、关键行为
	   b. 深度：Ghost→Lie因果链 + Want/Need矛盾 + 弧线类型判定
	   c. 洋葱三层：社交面具 + 自我认知 + 真实内核
	   d. 矛盾注入：主气质 × 矛盾特质 = 化学反应
	3. 剧情推理：
	   a. 当前处境：人物在哪？什么环境？谁在场？
	   b. 压力源：Ghost（创伤）？Lie（谎言）？Want（欲望）？Need（需求）？
	   c. 冲突分析：与谁对立？谁是盟友？谁是敌对？
	   d. 关系网络：与其他人物的关系强度
	4. 行为指导生成：
	   a. 说话风格：紧张/放松/愤怒时的用词、句式节奏
	   b. 行动倾向：主动/被动/犹豫/果断
	   c. 对话立场：对每个角色的具体态度
	   d. 情绪反应：遇到冲突时的真实反应（不"震惊""难以置信"）

5. **口头禅预定义**：
   - character_get 提取每个角色的 `catchphrase` 字段
   - 写作时自动将口头禅融入对话（如"那倒是...""嗯..."等）
   - 如角色无预设口头禅，根据性格特点在首次登场时临时生成（"那个...""嗯..."等）

**输出：写作指导卡片**

```

[人物分析指导 - 第{章节号}章]

涉及人物：
| 姓名 | 当前处境 | 压力源 | 冲突对象 | 说话风格 | 行动倾向 | 对话立场 | 口头禅 | 离开地区 | 目的地 |
|------|----------|---------|----------|----------|----------|----------|
| {A} | {描述} | {Ghost/Lie/Want/Need} | {人物名} | {具体描述} | {具体描述} | {从档案提取} | {原地点} | {B地目的} |
```
