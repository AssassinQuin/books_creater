# Phase 5 Agent A: 结构评估

## 8 维度评分

| 维度 | 分数 | 说明 |
|------|------|------|
| 1. 激活即执行性 | 3/5 | 激活规则说"用将夜式框架分析创作问题"，但没有明确的首步指令。AI知道要做什么风格，但不知道具体从哪个模型开始。缺少"首先判断用户问题类型→选择对应模型→输出分析"的编排逻辑。首次激活有声明模板，不错，但执行路径有歧义——7个模型都在同一层级，AI需要自己判断调用顺序。 |
| 2. 工作流清晰度 | 3/5 | 10条启发式有编号和if-then结构（"设计核心冲突时→识别三方博弈"），这是好的。但它们是平铺的列表，不是有序调用链。用户提出复杂问题时，多个启发式可能同时适用，缺乏联合调度逻辑。启发式之间有隐含优先级但未标注。 |
| 3. 边界条件 | 4/5 | 每个模型都有"局限"段落，诚实边界也明确列出6条局限。这是亮点。但缺少"什么时候不该用整个skill"的总体边界——比如用户问纯技术问题（怎么写prompt）、非创作问题时，skill没有退出指令。激活规则有退出机制（"用户说退出切回正常"），但何时应主动退出的判断标准缺失。 |
| 4. 检查点设计 | 2/5 | 几乎没有显式检查点。没有"分析完成后询问用户是否需要深化某个维度"的节点。没有"以下分析基于X模型，是否需要切换到Y视角"的确认机制。整个skill更像一份参考文档，而非交互式工作流。缺乏"停下来确认"的节点是最大的结构性缺失。 |
| 5. 指令具体性 | 3/5 | 表达DNA规则描述了高标准（"极简意象承载极重情感"），但缺乏具体句式模板。只有引用示例（"那年春..."），没有拆解这个句式的结构要素以便复用。心智模型的"应用"段落比较具体，但仍然偏抽象——"先识别三方"没有给出识别的具体方法。启发式"案例"部分较好，但案例只展示了结果，没有展示推理过程。 |
| 6. 模型联动 | 2/5 | 7个模型独立存在，缺少联合调度指引。现实中，复杂创作问题通常需要2-3个模型联动。比如设计一场大战役，需要"三方博弈"（冲突架构）+ "冷暖弧螺旋"（节奏定位）+ "日常即神圣"（选择承载细节）+ "看对方怎么输"（设计爽点）——但skill没有说明这些模型如何组合。这是Phase 4发现的第4个薄弱环节的直接体现。 |
| 7. 失败预防 | 3/5 | 诚实边界列出了将夜后期失效场景，但这是"认知局限"而非"使用失败预防"。缺少"AI最容易犯的错误"列表——比如：过度使用三方博弈导致日常场景也强行套用、冷暖弧比例机械套用、把"困住谱系"当成唯一反派模板等。模型局限提到了一些（"短篇用不上三方"），但不够系统。 |
| 8. 示例密度 | 3/5 | 每个模型都有案例，但案例集中在"将夜本身做了什么"，缺少"如何将这个模型应用到用户自己的创作中"的跨作品示例。表达DNA引用了经典句子但未拆解结构。启发式有案例但只展示结果。缺少反面示例（"错误做法"vs"将夜式做法"的对比），也缺少非将夜作品的参照（比如"在其他类型小说中怎么应用三方博弈"）。 |

**总分：23/40（均分 2.9/5）**

## 干跑测试结果

### Prompt 1: 反派扁平

- **skill 反应**：AI会触发模型7（反派困住谱系），给出四种困局类型（体制/执念/出身/恐惧），让用户选择。然后可能关联模型1（三方博弈）看反派在整体冲突中的位置。
- **可执行性**：中等。给出困局分类是可执行的，但缺少"如何让扁平反派变立体"的具体操作步骤——比如先写反派的一天日常、写反派的不可逆选择、写反派的恐惧来源。skill只给了框架（困局类型），没有给方法（怎么从框架推导到具体角色细节）。
- **卡点**：用户选择困局类型后，skill没有提供下一步指导——怎么把这个困局具体化到角色的对话、行为、选择中？模型7的"应用"只说了"不要写TA是坏的，写TA被什么困住"，这是一条否定指令，不是操作指令。

### Prompt 2: 书院见夫子

- **skill 反应**：AI会激活表达DNA的风格规则（长句思辨流+短句收束+化用经典），并结合模型3（日常即神圣——夫子不是高高在上的圣人，而是吃面喝酒的俗人）。可能会引用"书院什么最大？道理最大"的问答体。
- **可执行性**：偏低。表达DNA列了风格要素（句式/词汇混搭/化用经典/战斗/氛围/幽默/节奏），但没有提供场景级别的写作模板。AI知道要"极简意象承载极重情感"，但不知道在这个具体场景中该用什么意象、怎么安排铺垫和收束的比例。**这是Phase 4发现的第1个薄弱环节的直接体现——意象密度不稳定。**
- **卡点**：关键卡点：表达DNA说"先意象铺垫后短句收束"，但没说铺垫多少句、用什么类型的意象、短句收束到什么程度。对于"书院见夫子"这个场景，AI缺乏具体的意象库和句式模板，很容易写出"宁缺走进书院，夫子坐在石头上"这种平淡表达，达不到"那年春，夫子喝二壶酒，斩尽满山桃花"的意象浓度。

### Prompt 3: 50万字拖沓

- **skill 反应**：AI会触发模型2（冷暖弧螺旋——检查是否暖弧过长/冷弧不够深），模型9（引擎耗尽——是否需要引入新引擎），模型4（看对方怎么输——是否缺乏爽点）。
- **可执行性**：中等。三个模型都能给出诊断方向：冷暖弧数据化检查、引擎耗尽判断、爽点设计。但缺少具体诊断流程——先检查什么、再检查什么、怎么判断是哪个问题。三个模型的建议是平行的，不是串联的。
- **卡点**：最大卡点：模型间联动不足。这三个模型会给出三个独立建议，但AI不知道如何整合——是先调冷暖弧比例，还是先引入新引擎，还是先补爽点？缺少一个"节奏诊断流程"，把多个模型串联成有序的检查清单。**这是Phase 4发现的第4个薄弱环节的体现。**

## 最弱 2 个维度

1. **检查点设计（2/5）**：整个skill没有显式的"停下来确认"节点。作为交互式创作辅助工具，缺少检查点意味着AI要么一口气输出所有分析（信息过载），要么在错误方向上走得太远。7个模型+10条启发式+表达DNA全部平铺，AI没有机会在每一步确认用户的关注点。

2. **模型联动（2/5）**：7个独立模型缺少联合调度指引。复杂创作问题需要多模型协同，但skill没有提供组合模式、优先级、或串联流程。这是Phase 4发现的第4个薄弱环节的结构根因——"10条独立启发式缺乏联合调度指引"。

## 改进建议（针对最弱 2 维度）

### 建议 1: 添加模型联动矩阵

**问题**：7个模型独立存在，复杂问题时AI不知道如何组合。比如节奏问题需要模型2+4+9联动，但skill没有这种指引。当前文本中模型之间唯一的联系是各自"应用"段落中的简单提及，没有显式的组合模式。

**改后文本**：

```markdown
## 模型联动矩阵

复杂创作问题通常需要 2-3 个模型协同。以下是常见场景的模型组合：

| 用户问题类型 | 主模型 | 辅模型 | 调用顺序 |
|-------------|--------|--------|---------|
| 节奏拖沓 | 模型2（冷暖弧螺旋）→ 诊断当前弧位 | 模型9（引擎耗尽）→ 检查驱动源 + 模型4（看对方怎么输）→ 补爽点 | 先定位弧位 → 检查引擎 → 再调爽点 |
| 反派塑造 | 模型7（困住谱系）→ 确定困局类型 | 模型1（三方博弈）→ 定位反派角色 + 模型3（日常即神圣）→ 写日常细节 | 先选困局 → 放进博弈 → 写日常细节 |
| 大场面设计 | 模型1（三方博弈）→ 冲突架构 | 模型3（日常即神圣）→ 选承载细节 + 模型4（看对方怎么输）→ 设计爽点 | 先架构 → 选细节 → 定爽点 |
| 百万字规划 | 模型6（长线伏笔）→ 埋钩子 | 模型2（冷暖弧）→ 节奏骨架 + 模型5（文化原型）→ 确保根基 | 先骨架 → 埋伏笔 → 查根基 |
| 世界观设计 | 模型5（文化原型）→ 锚定根基 | 模型1（三方博弈）→ 设计冲突底座 | 先锚原型 → 建冲突 |

**联动原则**：
1. 先用主模型诊断/定位，再用辅模型深化
2. 一次分析不超过 3 个模型，避免信息过载
3. 如果主模型的诊断结果不明确，主动询问用户偏好
```

**插入位置**：放在「决策启发式」之后、「表达DNA」之前。

### 建议 2: 添加交互检查点与执行编排

**问题**：整个skill缺乏"停下来确认"的节点。AI拿到skill后不知道先做什么、做一步后是否需要确认、怎么避免一口气输出7个模型的分析导致信息过载。当前"激活规则"只说了首次声明，没有执行流程编排。

**改后文本**：

```markdown
## 执行编排（追加到激活规则末尾）

### 首步判断（激活后立即执行）

激活后，先判断用户问题类型，选择对应入口：

| 问题类型 | 入口模型 | 输出范围 |
|---------|---------|---------|
| 冲突/剧情设计 | 模型1（三方博弈） | 冲突架构分析 |
| 人物塑造 | 模型7（困住谱系） | 角色深度分析 |
| 节奏/结构问题 | 模型2（冷暖弧螺旋） | 节奏诊断 |
| 世界观/设定 | 模型5（文化原型） | 根基锚定 |
| 伏笔/线索 | 模型6（长线伏笔） | 伏笔工程建议 |
| 写作风格 | 表达DNA | 风格诊断 |
| 无法归类 | 启发式1-10逐一扫描 | 综合分析 |

### 检查点（每次分析后执行）

每完成一个模型的分析后，执行以下检查点：

1. **范围确认**：「以上基于 [模型名] 的分析，是否需要我用 [相关辅模型] 进一步深化？」
2. **诚实边界**：如果分析涉及将夜后期/修行体系/信息缺口领域，主动标注：「这个方向在将夜里是薄弱区域，建议谨慎参考。」
3. **可执行性检查**：给出的建议是否包含具体操作步骤？如果是纯框架性建议，追问：「需要我帮你把这个框架具体化到你的故事里吗？」
```

**插入位置**：追加到「激活规则」章节末尾，在"用户说退出切回正常"之后。
