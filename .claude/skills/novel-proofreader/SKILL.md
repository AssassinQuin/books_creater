# 正文质量检查引擎（v2）

> 代入每个角色的知识状态和心理状态，逐章扫描10大维度。多Agent并行时每个Agent必须加载完整角色基线。

## 强制流程

```
Step 1 加载角色状态 → Step 2 代入式逐章扫描(10维度) → Step 3 问题分级 → Step 4 输出报告
```

---

## Step 1: 加载角色状态

读取以下设定文件，建立每个角色的**知识边界**和**行为基线**：

```
1. 读 设定/角色深化.md — 每个角色的核心性格、Lie、Ghost、行为基线
2. 读 设定/人物/{角色名}.md — 当前快照（知道什么、不知道什么、秘密）
3. 🔴 读 设定/角色蒸馏/{角色名}-V{卷}CH{章}.md — 前一章的角色状态快照
   → 检查第N章时，加载第N-1章的蒸馏文件（如存在）
   → 蒸馏文件包含：位置/行为/心理/身体/伏笔状态/下章预判
   → 这是最精确的"角色此刻应该是什么状态"的数据源
4. 读 设定/锁定设定.md — 固定设定（名称、价格、地点）
5. 读 设定/大纲/线索追踪.md — 伏笔状态（谁在什么时候知道什么）
6. 读 设定/写作执行规范.md — 小说特定规则（字数/人物规则/检查清单）
7. 读 writing-style.md（同目录 references/）— 通用写作风格标准
7. novel-db: character_list + character_get — 最新人物状态
8. novel-db: timeline_query — 时间线（防止时空矛盾）
9. novel-db: foreshadow_list(status="planted") — 未回收伏笔
10. novel-db: volume_get — 当前卷规划（判断章在卷中位置）
```

**🔴 角色基线来源优先级（从高到低）**：

| 优先级 | 来源 | 用途 |
|--------|------|------|
| 1 | 角色蒸馏文件（前一章） | 精确状态：位置/装备/心理/身体/知识边界 |
| 2 | 角色深化.md | 核心性格/Lie/Ghost/行为基线/核心禁忌 |
| 3 | 锁定设定.md | 固定设定（不会变的） |
| 4 | novel-db character_get | 数据库中的状态快照 |

**蒸馏文件→OOC检查的映射**：

从蒸馏文件提取以下字段，用于2.1 OOC检查：

```
蒸馏字段 → 检查项
位置     → 场景空间一致性（角色是否出现在正确位置）
行为     → 行为匹配（角色是否做了符合当前状态的事）
心理     → 对话/决策合理性（角色的话语是否符合当前心理）
身体     → 体力/受伤/疾病一致性（角色是否能做出描述的动作）
伏笔状态 → 知识边界（角色此刻应该知道什么/不知道什么）
下章预判 → 预期行为方向（角色下一步是否偏离合理方向）
```

**核心角色硬性禁忌（不可违反，从角色深化.md动态提取，以下为当前项目快照）**：

> ⚠️ 以下为《这次不一样了》的角色快照。其他项目使用此skill时，应从各自的角色深化文件重新提取。

- **沈野**：妹妹优先（一切行为以此为基准）、不欠人不帮人（对外冷漠）、秃鹫本能、拓印萌芽
- **沈念**：天真≠蠢（能感知问题但善意解读）、有判断力+执行力+隐藏能力、压缩自己不说疼、生活所迫（不是自愿牺牲是被逼无奈）
- **方岩**：15年斥候经验、做了不说、指挥用短句不用长句、碎罗盘是命根子、12人之死是心结

## Step 2: 代入式逐章扫描（10维度）

对每章正文执行以下10个维度的检查。**核心原则：站在每个角色的立场上，问"如果我是这个角色，我现在知道什么？我会怎么做？"**

### 2.1 人物OOC检查（🔴 最高优先级）

**检查方法**：对每个出场角色的每个行为，问三个问题：

1. **知识匹配**：对照蒸馏文件中的"伏笔/线索状态"和角色深化的知识边界，这个角色此刻知道这个信息吗？
   - 检查方式：读前一章蒸馏文件→提取"该角色此刻知道什么/不知道什么"→逐条比对
   - 示例矛盾类型（不限于这些，每章根据蒸馏文件动态判断）：
     - 角色表现出知道他蒸馏文件中标注为"不知道"的信息
     - 角色说出只有读者/其他角色知道的信息
     - 角色在获取信息前就对此信息做出反应

2. **行为匹配**：对照角色深化的行为基线+蒸馏文件中的"本章状态/心理"，以这个角色的性格和当前状态，他会这么做吗？
   - 检查方式：读角色深化的核心禁忌→读蒸馏文件的当前心理→判断行为是否合理
   - 常见矛盾类型（动态生成，每章不同）：
     - 违反核心禁忌的行为（如妹妹优先的角色丢下妹妹）
     - 与蒸馏文件心理状态矛盾的行为（如心理写"恐惧"但行为勇敢无畏）
     - 与蒸馏文件身体状态矛盾的行为（如受伤角色跑得快）
     - 说话风格突变（如短句角色突然长篇大论）

3. **状态匹配**：对照蒸馏文件中的"位置/身体/装备"，以这个角色此刻的生理/心理状态，他能这么做吗？
   - 检查方式：读前一章蒸馏文件的"身体"字段→比对本章体力消耗/受伤描写是否连续
   - 常见矛盾类型：
     - 受伤严重但后续章节无跛行/疼痛描写
     - 连续战斗无体力消耗
     - 疾病症状突然消失无解释
     - 装备在上一章已消耗但本章仍使用

### 2.2 知识矛盾检查（🔴 与OOC同等优先级）

**核心规则**：角色只能基于他当前知道的信息做决定和反应。

检查清单：
- [ ] 角色是否表现出知道他不该知道的信息？
- [ ] 角色的对话是否泄露了只有读者知道的信息？
- [ ] 叙述视角是否突然切换导致信息泄漏？
- [ ] 前后章之间的信息获取是否连贯？（前章不知道→后章突然知道，中间要有获取过程）

### 2.3 逻辑连贯检查

**时间线检查**：
- 事件A到事件B的时间间隔是否合理？
- "第二天""过了两天"等时间标记是否与前文矛盾？
- 角色移动距离是否在合理时间内可达？

**因果链检查**：
- 角色的行为是否有充分动机？
- 事件之间的因果关系是否清晰？
- 是否有"突然出现"的信息或物品没有来源？

**空间一致性**：
- 角色在同一场景中的位置关系是否一致？
- 环境描写是否前后矛盾（如天气、光线、灵能浓度数据）

**🔴 章间衔接检查（强制）**：
- 本章开头是否与上章结尾连贯？（场景/位置/角色状态/情绪）
- 上章结尾是高潮→本章开头不能像无事发生
- 上章结尾留悬念→本章开头要收束该悬念

### 2.4 战斗场景质量检查（🔴 新增）

战斗场景使用独立skill `novel-battle-auditor` 进行专项审计。

当章节包含战斗场景时：
1. 先完成其他9个维度的检查
2. 标记战斗场景段落，使用 novel-battle-auditor skill 执行八维度战斗审计
3. 战斗审计结果合并到本章总报告

战斗审计核心维度速查（详见 novel-battle-auditor/SKILL.md）：

**分镜检查**（是否有5种机位切换）：

| 机位 | 应有内容 | 常见缺失 |
|------|---------|---------|
| 远景 | 战场全貌/敌我态势/环境/规模 | 只写个体不写全局 |
| 中景 | 战术动作/走位/配合 | 缺失 |
| 近景 | 武器碰撞/灵能效果/伤害细节 | "打了一下就赢了" |
| 特写 | 微表情/关键细节/决策瞬间 | 无 |
| 慢镜头 | 关键转折/致命一击/重大瞬间 | 全是正常速度叙事 |

**异兽风格差异化**：
- [ ] 同一类型的异兽是否有不同行为模式？
- [ ] T1群殴 vs T1独居 vs T2智能 vs T3个体——是否有明确区分？
- [ ] 每场战斗的异兽是否有至少1个独特行为/弱点/战术？

**能力展示检查**（从角色深化·能力字段+蒸馏文件·新信息动态提取）：
- [ ] 读取每个战斗参与角色的能力设定（从角色深化或蒸馏文件提取）
- [ ] 该角色的独特能力是否在战斗中自然展示？
- [ ] 能力使用是否符合当前阶段？（不能超越蒸馏文件中标注的能力阶段）
- [ ] 角色的战斗方式是否与身份背景一致？（斥候→地形利用；拾荒者→陷阱配合；军人→短句指挥）

**热血燃点检查**：
- [ ] 战斗是否有"险境→绝地→反击"弧线？
- [ ] 是否有代价感（体力消耗/装备损耗/受伤）？
- [ ] 关键瞬间是否有慢镜头/时间拉长？

### 2.5 经济逻辑检查（🔴 新增）

**物价体系一致性**：

| 物品 | 参考价 | 来源 |
|------|-------|------|
| 碎灵晶 | 3铜板 | 正文Ch006 |
| 粗面3斤+盐半斤 | 1标准碎片 | 正文Ch006 |
| 碎渣弹 | ~5铜板 | 正文 |
| 碎渣(低纯) | 10-15铜板 | 正文Ch006 |

**收入一致性**：
- 拾荒者日收入：30块碎渣≈45铜板
- 碎灵晶额外：一周2-3颗≈9铜板
- 月收入：~1400铜板

**检查清单**：
- [ ] 角色提到的金额是否在合理范围？（300铜板是否合理？需要几个月攒？）
- [ ] 灵衰症治疗费用与角色收入是否匹配？（产生"不够"的紧迫感）
- [ ] 角色提到"攒了X钱"时，与已知收入和工作时间是否一致？
- [ ] 物价是否前后一致？（同一物品不同章价格不能矛盾）

**🔴 账目必查**：
- 角色说"攒了X铜板" → 反推需要多少天/月攒 → 是否有足够时间
- 角色说"花了X" → 收入能否支撑 → 是否需要解释额外支出
- 如果金额不合理，标记为P1并建议调整金额或补充说明

### 2.6 微动作泄露内心检查（🔴 新增）

**禁止直白情绪词**：
- ❌ "他惊讶""难以置信""愤怒地说""悲伤地说""是怕""很担心"
- ✅ 用动作体现：手停在半空、眼睛微微睁大、呼吸停了一拍、喉结动了动

**离别/告别/离开场景专项**：
- [ ] 角色是否有2-3个不舍微动作？（手指多停一秒/回头看/脚步放慢）
- [ ] 是否避免了一刀切的干净离开？
- [ ] 情感重量是否通过身体语言而非心理描写传达？

**习惯动作一致性**（从角色深化·行为基线+蒸馏文件动态提取）：
- [ ] 读取每个出场角色的"习惯动作/口头禅"（从角色深化或蒸馏文件提取）
- [ ] 检查该动作是否在该出现时出现（如焦虑场景是否触发焦虑习惯动作）
- [ ] 检查该动作是否在不该出现时乱出现（如平静场景突然出现焦虑动作）
- [ ] 检查习惯动作是否全卷一致（不能前5章有后20章消失）

### 2.7 结构变异检查（🔴 新增）

**反AI结构僵化**：
- [ ] 近5章内是否至少使用了2种不同结构变体？
- [ ] 是否存在连续3章以上使用标准"起承转合"？
- [ ] 变体选择是否合理？（高潮章→螺旋/突入；日常章→日常型；揭露→倒叙型）

| 变体 | 识别特征 |
|------|---------|
| 标准型 | 起→承→转→合 |
| 突入型 | 无起段，直接从转开始 |
| 日常型 | 无明确转段，安静收束 |
| 倒叙型 | 先给结果/悬念，再回溯 |
| 碎片型 | 3-4个短场景拼接 |
| 螺旋型 | 起极短→承极长→转爆发→合极短 |

### 2.8 爽点密度检查（🔴 新增）

| 爽点级别 | 间隔要求 | 检查项 |
|----------|---------|--------|
| 微/小爽点 | 每章至少1个 | 小胜利/小揭露/角色高光 |
| 中爽点 | 每3-5章 | 阶段胜利/关系突破/能力展示 |
| 大高潮 | 每8-12章 | 卷内高潮/Boss战/重大转折 |
| 超级高潮 | 每卷1-2次 | 卷终决战/命运转折/真相揭露 |

**平路检测**：
- [ ] 是否有连续3章以上无爽点？
- [ ] 如果有，标记为P1并建议在中间章补小爽点

**信息缺口密度**：
- [ ] 每章是否至少投放1个信息缺口（谁/为什么/怎么/什么时候/会怎样）？
- [ ] 信息缺口是否在后续章节有回应？

### 2.9 伏笔一致性检查（🔴 新增）

**跨章伏笔追踪**：
- [ ] 已埋伏笔在本章是否有推进/呼应？（不能埋了就忘）
- [ ] 本章新埋伏笔是否与已有伏笔矛盾？
- [ ] 伏笔的描述在不同章节是否一致？（细节不能前后矛盾）
- [ ] 回收伏笔时是否与埋设时的设定一致？

**伏笔-章节交叉检查**：
```
从foreshadow_list获取所有伏笔 →
对每条伏笔，grep所有提及该伏笔的章节 →
检查描述是否一致
```

### 2.10 NPC深度检查

**每章至少2个有动机的NPC**：
- [ ] NPC是否有姓名/绰号/职业标识？
- [ ] NPC是否有明确动机（不是工具人）？
- [ ] NPC对话是否体现身份背景？
- [ ] 拾荒者NPC是否有合理的警惕性？（不能太亲切/太信任）

### 2.11 叙述视角与错别字

**POV一致性**：
- 确认当前章节的主视角角色
- 叙述中不能出现主视角角色看不到/听不到/感觉不到的信息
- 不能出现"他不知道"这种全知叙述（除非是有意设计的信息差）

**错别字和术语统一**：
- 的/得/地、做/作、在/再
- 灵能（非灵力/魔力）、灵衰症（非衰竭症）、灵晶（非晶石）
- T1/T2/T3/T4 等级称呼一致
- 灵站/灵枢 区分正确

### 2.12 🔴 受伤连贯性检查（新增）

**跨章受伤追踪**：

从novel-db character.status.injuries提取所有未痊愈(resolved=false)的受伤记录，逐章检查：

- [ ] 本章出场角色，其DB中的未痊愈伤是否有体现？（跛行/疼痛/受限动作/包扎描写）
- [ ] 受伤恢复进度是否与healing_timeline匹配？（轻伤3天该好了、中伤10天该有明显好转）
- [ ] 是否有"伤好得比时间线快"的问题？（2天前受中伤本章已活蹦乱跳）
- [ ] 是否有"新伤叠加旧伤"的累计效果？
- [ ] 慢性疾病（如灵衰症）的进展是否与设定milestones一致？

**检查方法**：
```
1. character_get → 提取status.injuries
2. 对每个resolved=false的injury:
   a. 计算受伤到本章的"章数差"
   b. 对照healing_timeline判断当前应处于什么恢复阶段
   c. 检查本章正文是否有对应的伤情体现
3. 生成受伤状态表（见报告格式）
```

**受伤严重度→恢复时间线标准**（与battle-writer/auditor统一）：

| 严重度 | 恢复时间 | 后续表现要求 |
|--------|---------|------------|
| 轻 | 1-3天 | 下1-2章有疼痛提及→之后消退 |
| 中 | 5-10天 | 2-3章内行动受限→逐步好转→结痂 |
| 重 | 15-30天 | 4-6章持续影响→需治疗场景 |
| 危 | 需灵能修复 | 直到获得专业治疗前持续严重 |

### 2.13 🔴 物品/装备状态检查（新增）

**跨章物品追踪**：

从novel-db character.status.inventory提取物品清单，逐章检查：

- [ ] 消耗品（碎渣弹/干粮/灵能碎渣）使用后数量是否递减？
- [ ] 损毁装备（被划破的背包/耗尽的灵能短刀）后续是否保持损坏状态直到修复？
- [ ] 角色使用了他当前不应拥有的物品？（已消耗/已丢失/从未获取）
- [ ] 新获取的物品是否在后续章节有交代来源？
- [ ] 经济逻辑：购买物品的金额与角色收入是否匹配？

### 2.14 🔴 新设定/物品/概念/能力合理性检查（新增）

**扫描正文新增世界观元素**：

逐段扫描本章正文，识别在已有设定文件中找不到对应条目的世界观元素：

- [ ] **新物品/装备**：是否已追加到 `设定/世界观/灵能物品与装备.md`？原理/价格/限制是否与已有体系逻辑一致？
- [ ] **新异兽/灵兽**：是否已追加到 `设定/世界观/灵兽与异兽.md`？等级/行为/弱点是否与同等级异兽体系一致？
- [ ] **新能力/灵能现象**：是否已追加到 `设定/世界观/灵能体系.md`？是否有明确的限制/代价/副作用？是否破坏已有能力平衡？
- [ ] **新地点/区域**：是否已在 `设定/地图.md` 和 `设定/世界观/地理与势力.md` 中标注？位置与已有地理体系是否矛盾？
- [ ] **新疾病/生理现象**：是否与已有医学体系（灵衰症分期等）逻辑一致？
- [ ] **新势力/组织**：是否与已有势力关系网矛盾？
- [ ] **新经济规则/价格**：是否与已有物价体系矛盾？（同物不同价/收入不匹配）

**合理性校验清单**：
- [ ] 新元素的原理是否能在已有灵能体系框架内解释？（不能凭空出现全新机制）
- [ ] 新元素的限制/代价是否明确？（没有代价的设定是设定漏洞）
- [ ] 新元素是否与已有设定文件中同类元素的风格/规则一致？
- [ ] novel-db world_query 验证：新增内容是否已通过 world_upsert 写入数据库？
- [ ] 设定文件指针：世界观.md 详细设定索引是否需要更新？

### 2.15 🔴 文笔风格检查

> 完整标准见 `references/writing-style.md`（通用写作标准）。以下为核心摘要：

- [ ] 时间表达文学化：无精确时间（"看了两秒"→"愣了愣神"），过渡用文学化表述
- [ ] 描述感官化：距离/大小/程度用感官类比替代精确数字
- [ ] 去AI味：句式长短交替/少修饰/对话有废话/情绪克制
- [ ] 所有风格检查项以 `references/writing-style.md` 为准

## Step 3: 问题分级

| 等级 | 定义 | 示例类型 | 处理 |
|------|------|---------|------|
| **P0-致命** | 人物OOC/知识矛盾/受伤消失，破坏核心人设 | 角色知道不该知道的信息；违反核心禁忌的行为；状态与蒸馏文件严重矛盾；正文受伤但DB无记录；受伤角色无伤情体现 | 立即修复 |
| **P1-严重** | 逻辑断裂/因果不通/经济矛盾/物品矛盾 | 角色突然出现无解释；时间线矛盾；金额与收入不符；战斗无代价；连续3章无爽点；使用已消耗/丢失的物品；物品数量不递减 | 必须修复 |
| **P2-中等** | 叙述泄漏/战斗太平/结构僵化 | 全知视角混入有限视角；战斗全是中景无分镜；连续5章相同结构 | 建议修复 |
| **P3-轻微** | 错别字/名称不一致/描写重复 | 的得地混用；术语不统一；微动作遗漏 | 批量修复 |
| **P4-建议** | 可优化但不影响阅读 | 节奏微调；NPC深度增强；过渡句优化 | 可选 |

## 批量执行模式

当用户说"检查第X章到第Y章"或"检查V1正文"时：

1. 获取章节列表（glob正文目录）
2. 按顺序逐章执行 Step 2
3. 每5章一批，结果汇总后继续
4. 全部完成后输出总报告

**并行Agent策略**（超过5章时）：

可根据检查维度拆分Agent，每个Agent覆盖不同维度：

| Agent | 覆盖维度 | 说明 |
|-------|---------|------|
| Agent A | 2.1 + 2.2 + 2.6 | 人设OOC + 知识矛盾 + 微动作 |
| Agent B | 2.3 + 2.5 + 2.9 | 逻辑连贯 + 经济逻辑 + 伏笔 |
| Agent C | 2.4 + 2.7 + 2.8 | 战斗质量 + 结构变异 + 爽点 |

每个Agent必须：
- 加载完整的角色知识档案
- 读取所有相关设定文件
- 输出标准格式报告

最后主线程汇总去重，生成总报告。

## 修复模式

当用户说"修复第X章"或"修复全部"时：
1. 读取该章的问题清单
2. 对每个P0/P1问题生成修复方案
3. 展示修复方案给用户确认
4. 确认后执行Edit修改
5. 修改后重新检查确认问题已解决
