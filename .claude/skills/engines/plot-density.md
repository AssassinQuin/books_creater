# 情节密度引擎（Plot Density Engine）

> **核心原则**：线性叙事只有一股推动力（主角的目标）。螺旋叙事有多股推动力同时运行——主角在追他的目标，NPC 在追他们的目标，世界在自己的节奏里运转，这些力量碰撞出读者意想不到的事件。
> **定位**：与 `spiral-structure.md` 配套。螺旋结构解决"怎么揭示"，情节密度解决"有多少可以揭示"。
> **触发时机**：novel-planner-volume 设计事件架构时（Step 1）、novel-qa 审查大纲时。

---

## 一、并行因果链要求

### 核心概念

每卷的事件架构不只设计一条主因果链，必须同时设计 **3-5 条并行活跃链**：

| 链类型 | 定义 | 驱动力 | 在 V1 中的可能示例 |
|--------|------|--------|-------------------|
| **主线** | 主角的核心驱动 | 主角的主动目标/生存需求 | {主角妹妹}病情→必须走 |
| **NPC 议程链** | 有目标的 NPC 在主动做事 | NPC 的个人目标 | {配角A}争取调岗→做了一些事→产生意外后果 |
| **世界运转链** | 体系的内在逻辑在运行 | 制度/规则/利益结构 | {资源站}配额制度→有人在操控→制造了某种短缺 |
| **暗线** | 读者能感知到但主角不知道的事 | 隐藏角色的行动 | {配角B}的调查→发现了什么→被某人注意到了 |
| **支线** | 配角的独立故事 | 配角的个人弧线 | 邻居女儿的灰斑→她的家庭做了什么选择→映照主线 |

### 规则

1. 每卷至少 **3 条活跃并行链**（主线 + 2 条其他）
2. 每章至少 **2 条链有可见推进**（不要求全部推进，但 ≥2）
3. 每 **3 章**所有活跃链都必须至少推进 1 次（防止某条链消失太久）
4. 并行链之间必须有**碰撞点**——至少每卷 2 次不同链的事件产生交叉后果

### 追踪模板

```markdown
| 链 | 类型 | 驱动力 | Ch1 | Ch2 | Ch3 | Ch4 | ... | ChN |
|----|------|--------|-----|-----|-----|-----|-----|-----|
| 主线 | 主线 | {驱动力} | ✓ | ✓ | ✓ | ✓ | | ✓ |
| {NPC名}议程 | NPC | {NPC目标} | | ✓ | | ✓ | | ✓ |
| {制度/体系} | 世界 | {运转逻辑} | | | ✓ | | | ✓ |
| {暗线名} | 暗线 | {隐藏力量} | ✓ | | ✓ | | | |
| {配角名}线 | 支线 | {配角弧线} | | | | ✓ | | ✓ |

✓ = 本链在该章有可见推进（读者能感知到）
碰撞 = 标注不同链的事件交叉点
```

## 二、NPC 议程设计

### 核心原则

NPC 不只是"为主角提供信息的工具人"或"制造障碍的背景板"。每个戏份 ≥3 场的 NPC 都有自己的生活和目标，他们**在主角看不到的地方做着影响主角的事**。

### NPC 议程四要素

每个 NPC（戏份 ≥3 场）必须有：

| 要素 | 说明 | 示例（{配角A}） |
|------|------|-------------|
| **主动目标** | 他想达成什么（不是"服务于主角情节"） | 争取调离{资源站}去{守卫势力}辖区 |
| **正在做的事** | 他为了目标在做什么行动 | 每月提交异常报告试图证明自己能干 |
| **信息差** | 他知道什么/不知道什么 | 知道{资源站}有指标要求，不知道{主角妹妹}的特殊性 |
| **冲突源** | 他的目标和谁/什么冲突 | 和{资源站}运营指标冲突（异常少=站点正常=不需要人） |

### NPC 议程追踪表（每卷必填）

```markdown
| NPC | 主动目标 | 正在做什么 | 和谁冲突 | 信息差 | 第N章可见行动 |
|-----|---------|-----------|---------|--------|-------------|
| {名} | {目标} | {行动} | {冲突对象} | {知/不知} | Ch{N}:{具体行为} |
```

### 规则

1. NPC 议程行动**不需要每章都和主角交叉**——NPC 有自己的生活节奏
2. NPC 的行动后果**必须最终影响主角**（可以是间接的、延迟的、通过连锁反应的）
3. 至少 **1 个 NPC** 的行动在主角**不知情**的情况下**改变了主角的选择空间**
4. NPC 的行动必须基于**角色的合理判断和信息**（不能是"故意做坏事推动剧情"）

### NPC 议程驱动事件的生成方法

```
1. 列出本卷戏份≥3场的所有NPC
2. 为每个NPC填写议程四要素
3. 问：如果这个NPC按自己的议程行动，他会做什么？什么时候做？
4. 问：他的行动会波及谁？主角什么时候会感受到后果？
5. 将NPC行动映射到章节时间线上，标注碰撞点
```

## 三、复杂化引擎

### 核心原则

**每个解决方案都制造新问题。**角色做 X 解决了 A，但 X 同时带来了 B。这不叫"角色变笨"——这叫"生活"。现实中每个决定都有副作用。

### 四种复杂化模式

#### 模式 1：解决方案代价

角色做了 X 解决了 A，但 X 带来了新问题 B。

```
示例：{主角}偷偷多拿了一份稳定剂→解决了{主角妹妹}当天的需求→但配额出现异常被{配角A}注意到
```

#### 模式 2：意外后果

角色做 A 为了达成 B，但无意中触发了完全没想到的 C。

```
示例：{主角}触碰残片为了研究纹理→但触碰触发了某种共鸣，被远处的什么感知到了
```

#### 模式 3：两难选择

两个好选项但只能选一个，或者两个坏选项必须选一个。

```
示例：去废弃{资源站}找线索 vs 留下来陪{主角妹妹}做双轮吸收——两个都重要，只能选一个
```

#### 模式 4：信息误用

角色基于不完整信息做了合理决定，但信息本身有缺陷。

```
示例：{主角}以为{资源站}的预警是安全的→但其实{配角A}为了报告好看调低了某项阈值
```

### 规则

1. 每章至少 **1 次复杂化**（4 种模式任选）
2. 复杂化**不能是"角色变笨"**——必须基于角色的合理判断和当时可得的信息
3. 连续 **2 章不能用同一种**复杂化模式
4. 复杂化产生的新问题必须有**后续处理**（不能制造了就忘）
5. 复杂化与回旋镖决策（spiral-structure.md §三）天然配合——复杂化就是回旋镖的隐藏后果

### 复杂化追踪表

```markdown
| Ch | 模式 | 角色做了什么 | 表面效果 | 隐藏问题 | 后续处理章 |
|----|------|------------|---------|---------|-----------|
| {N} | {1-4} | {行为} | {解决了什么} | {制造了什么} | {M} |
```

## 四、事件密度升级

### 现有要求（shared-constraints.md）

- ≥4 主事件 + 3-5 微事件/章

### 新增要求

1. 主事件中 **≥1 个**必须来自非主角驱动的线索（NPC 议程 / 世界运转 / 暗线）
2. 微事件中 **≥1 个**必须是"看似无关但后来重要"的种子（与 spiral-structure 的回旋镖配合）
3. 每章至少 **1 个"读者会记住的细节"**（不是情感触动，是信息碎片——一个数字、一个名称、一个不一致）

### 密度验证方法

读者读完一章后能否列出 **≥5 个"发生了什么"**？

- 如果能列出 ≥5 个 → 事件密度合格
- 如果只能列出 ≤3 个 → **事件密度不足** → 触发复杂化引擎补充
- 如果能列出但都是主角的事 → **并行链不足** → 检查 NPC 议程和世界运转链

### 与弹性事件储备的关系

`shared-constraints.md` 的弹性事件储备（2-3 个/章）是字数安全网。本引擎的复杂化和并行链是**情节结构安全网**。两者互补：

- 弹性事件解决"字数不够"（展开已有内容的纹理）
- 情节密度解决"情节不够"（增加新的并行事件）

## 五、与现有系统的整合

### 与 spiral-structure.md 的关系

- `plot-density.md` 提供足够多的并行事件和 NPC 行动（"有什么可以翻新"）
- `spiral-structure.md` 设计这些事件的揭示方式（"怎么翻新"）
- **没有密度，螺旋没东西可以转。没有螺旋，密度只是线性堆砌。**

### 与 causality.md 的关系

- `causality.md` 设计单条因果链的逻辑完整性
- `plot-density.md` 要求多条因果链同时运行并碰撞
- 碰撞点就是 `causality.md` 的因果链升级点——两条链的交叉产生新的因果节点

### 与 shared-constraints.md 的关系

本引擎的规则是 shared-constraints 的**增量补充**，不替代现有约束：

| 现有约束 | 本引擎补充 |
|---------|-----------|
| ≥4 主事件/章 | 其中 ≥1 个来自非主角线索 |
| 微事件 3-5 个/章 | 其中 ≥1 个是"后来重要的种子" |
| NPC 有自己的生活 | NPC 有主动议程并产生可见行动 |
| 巧合计 ≤1 次/卷 | 复杂化模式不连续使用同一种 |

### 在 novel-planner-volume 中的使用

事件架构师（Step 1）完成因果链后，加载本引擎设计：
1. 列出本卷 3-5 条并行活跃链
2. 填写 NPC 议程追踪表
3. 设计每章的复杂化事件
4. 验证事件密度（读者能否列出 ≥5 个"发生了什么"）
