# 剧情爆破引擎（Drama Boost Engine）

> **本文件职责**：正文写作阶段的戏剧性增强——"太平了"时的应急方案。
> **触发时机**：novel-fix 戏剧增强模式 / novel-write Step 2 创意决策时场面"太平"
> **定位**：与 plot-density.md 互补。plot-density 是大纲阶段的复杂化引擎，本引擎是正文阶段的戏剧性增强。
> **配合文件**: 因果链→`causality.md`｜螺旋揭示→`spiral-structure.md`｜扩写技法→`scene-deepening.md`

---

## 一、两种模式

### 模式 A：爆破（Booming）— 改变终点

场面不够强，需要**升级冲突**或**颠覆预期**。

适用场景：
- 大纲设计的事件太"平"
- 读者读到这段不会有反应
- 核心冲突缺少张力

### 模式 B：加戏（Fuck-it）— 不改终点，只加过程

终点没问题，但**到达终点的过程太顺/太平/太快**。

适用场景：
- 事件本身OK但过程无聊
- 角色解决问题太顺利
- 缺少中间障碍和意外

## 二、10 套爆破方案（模式 A）

### 2.1 逆向爆破
**角色的正确决定导致最坏结果。**

生成方法：
```
角色基于当前信息做了合理决定 → 决定本身没问题 → 但触发了角色不知道的连锁反应 → 结果比不行动还糟
```

与 plot-density 复杂化引擎模式 1（解决方案代价）的关系：同源，但本引擎用于正文阶段即时增强。

### 2.2 信息差爆破
**读者知道但角色不知道的信息制造张力。**

生成方法：
```
识别当前场景中读者已知但 POV 角色未知的信息 → 让读者看到角色正在走向陷阱/错过关键线索
→ 但角色有自己的合理理由（不是变笨）→ 张力来自"不能提醒他"的无助感
```

与 spiral-structure 的关系：螺旋揭示控制信息释放节奏，本引擎用信息差制造即时张力。

### 2.3 NPC 爆破
**NPC 的自主行动改变主角处境。**

生成方法：
```
找一个在场或附近的NPC → 基于NPC自己的议程做一件与主角无关的事 → 这件事的意外后果改变了主角的选择空间
→ NPC不是在帮助或阻碍主角，只是在做自己的事
```

### 2.4 时间炸弹
**设置一个倒计时紧迫感。**

生成方法：
```
从世界观中找一个自然时间限制（灵气消退的周期/巡逻队的间隔/药物的时效/比赛的截止）
→ 把它缩短到比预期更紧 → 角色必须在信息不足的情况下做决定
```

### 2.5 反转爆破
**前提被颠覆——以为是 A 实际是 B。**

生成方法：
```
识别场景中角色（和读者）的默认假设 → 颠覆这个假设 → 但颠覆本身有充分的前因铺垫（不能是机械降神）
→ 角色必须重新评估局势
```

### 2.6 代价爆破
**解决问题需要不可逆的牺牲。**

生成方法：
```
角色找到了解决方案 → 但执行这个方案需要付出不可恢复的代价（身体/关系/资源/信息/信任）
→ 角色必须在"忍受问题"和"付出代价"之间选择 → 不管选哪个都有损失
```

### 2.7 关系爆破
**信任/联盟突然破裂。**

生成方法：
```
找一个角色间的信任基础 → 暴露这个信任基础的一个裂缝（不是完全崩塌，是第一次出现疑问）
→ 裂缝源于角色的合理怀疑（不是误会/不沟通这种烂桥段）→ 后续处理不需要在本章完成
```

### 2.8 规则爆破
**世界规则出现例外/漏洞。**

生成方法：
```
从世界观中找一个角色依赖的规则/规律 → 在关键时刻这个规则出现意外行为
→ 不是规则错了，是角色对规则的理解不完整 → 迫使角色重新学习/适应
```

### 2.9 身份爆破
**角色隐藏的身份/能力/过去暴露。**

生成方法：
```
找一个角色在隐藏的信息 → 设计一个自然的暴露场景（不是自爆，是被迫或意外）
→ 暴露后其他角色的反应才是重点（不是暴露本身）
→ 反应必须基于各自的性格和利益，不是统一反应
```

### 2.10 平静爆破
**在最安全时制造最危险的信号。**

生成方法：
```
在一个平静/安全的场景中 → 插入一个微小但不对劲的信号（不是危险本身，是危险的预兆）
→ 角色注意到了但不确定意味着什么 → 读者比角色更早意识到不对 → 张力来自"平静的表面下暗流涌动"
```

## 三、15 种单章加戏方向（模式 B）

不改终点，只加过程。每个方向可以单独使用或组合。

### 阻碍类

| # | 方向 | 方法 | 适用场面 |
|---|------|------|---------|
| 1 | **环境阻碍** | 天气/地形/建筑/光线等物理条件突然不利于角色行动 | 户外/探索/逃亡 |
| 2 | **工具失效** | 角色依赖的物品/能力/信息源在关键时刻不如预期 | 战斗/调查/谈判 |
| 3 | **身体限制** | 角色（或同伴）的伤/病/疲劳/中毒突然影响行动 | 持续行动/紧急任务 |

### 人物类

| # | 方向 | 方法 | 适用场面 |
|---|------|------|---------|
| 4 | **NPC 意外** | 在场 NPC 做了一件意料之外的事（基于自己的议程） | 任何有多人在场的场景 |
| 5 | **分歧升级** | 角色间的意见分歧从隐性变为显性，从讨论变为冲突 | 组队/计划/决策场景 |
| 6 | **情绪失控** | 某个角色在高压下做出不理性的行为（符合性格但非理性） | 高压/长时间紧张 |
| 7 | **旁观者视角** | 引入一个局外人的观察/评价，打破主角的叙事泡泡 | 日常/社交场景 |

### 信息类

| # | 方向 | 方法 | 适用场面 |
|---|------|------|---------|
| 8 | **隐藏信息揭示** | 揭示一个读者不知道但角色知道的信息（改变读者对事件的理解） | 回忆/对话/发现 |
| 9 | **错误信息** | 角色基于错误信息做了决定，读者能察觉但角色不能 | 调查/计划/判断 |
| 10 | **信息过载** | 一次性给出太多信息让角色无法判断哪些重要 | 发现/揭秘/战斗 |

### 节奏类

| # | 方向 | 方法 | 适用场面 |
|---|------|------|---------|
| 11 | **时间压缩** | 把预期时间缩短到不够用，制造紧迫感 | 任务/比赛/倒计时 |
| 12 | **节奏打断** | 在流畅推进中突然插入一个不相关的打断（NPC/事件/回忆） | 连续行动/顺利推进 |
| 13 | **视角切换** | 短暂切到另一个角色的 POV 展示同一事件的不同面貌 | 关键决策/冲突 |

### 结构类

| # | 方向 | 方法 | 适用场面 |
|---|------|------|---------|
| 14 | **前闪/后闪** | 插入一小段过去或未来的画面，给当前事件添加纵深 | 任何场景 |
| 15 | **平行事件** | 同时发生的另一件事通过侧面信息传入当前场景 | 任何场景 |

## 四、使用方法

### 在 novel-fix 中（戏剧增强模式）

```
1. 分析当前章节：场面类型、冲突强度、推进速度、角色活跃度
2. 判断缺什么：
   - 缺冲突强度 → 模式A（爆破）
   - 缺过程曲折 → 模式B（加戏）
3. 从对应模式中选择 2-3 个适合当前场面类型的方案
4. 输出方案摘要 → 用户选择 → 修改正文
5. validate_chapter 重新校验
```

### 在 novel-write 中（Step 2 创意决策时）

```
如果上下文包显示：
- 本章无重大冲突事件 → 提示"场面偏平，建议调用 drama-boost"
- 连续 2+ 章无意外 → 强制要求至少使用 1 个加戏方向
```

### 在 novel-plan 中（卷级事件设计时）

```
如果卷级大纲中存在：
- 连续 3+ 章无碰撞点 → 标记需要爆破方案
- 某章只有主线推进无其他链 → 标记需要加戏方向
```

## 五、与现有系统的协同

| 系统 | 阶段 | 本引擎的关系 |
|------|------|------------|
| plot-density.md | 大纲 | 设计并行链和NPC议程；本引擎是正文阶段的即时增强 |
| scene-deepening.md | 正文 | 扩写技法解决"薄"；本引擎解决"平" |
| spiral-structure.md | 大纲+正文 | 螺旋控制信息揭示节奏；本引擎提供可揭示的意外内容 |
| causality.md | 大纲 | 因果链保证逻辑；本引擎在链上增加意外节点 |
| pre-write-reflection.md | 正文写前 | 反思的"翻车预警"与本引擎互补——反思预防已知风险，本引擎增加未知变量 |
