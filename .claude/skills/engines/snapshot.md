# 快照引擎 engine-snapshot.md

> 统一的场景/事件/人物状态快照协议。所有写作类和质检类skill通用。

## 加载时机

| Skill | 加载场景 |
|-------|---------|
| novel-chapter-writer | 写正文前搭建场景快照，写完后生成事件快照 |
| novel-planner | 规划事件时设计环境快照，规划完保存地点到DB |
| novel-qa | 校对时加载快照做一致性验证 |
| novel-reviser | 批量修订时对比快照确认状态 |
| novel-battle | 战斗场景的环境快照+战斗后状态快照 |

---

## 三种快照格式

### 1. 场景快照

写正文前必须搭建，写完后按需更新。

```yaml
场景快照:
  位置: {具体地点名，如"第三区管道断裂口"/"聚落市集碎石地"}
  空间: {开阔/狭窄/管道内部/废墟高处，出入口方位}
  时间: {文学化，如"辰时刚过"/"天擦黑"/"夜深"}
  天气: {晴/雾/雨/风/静，灵能浓度相关的天气}
  光照: {光源+色温+亮度，如"{光源+色温}}
  温度: {冷/凉/温/热，体感描述}
  气味: {主气味+次要气味}
  声音: {环境音+远近声源}
  在场人物:
    - {角色名}: {位置}{状态}{当前目的}
  物品:
    - {物品名}: {位置}{状态}
  潜在冲突: {本章可能爆发的矛盾}
```

**存储**: 关键地点用 `world(action="upsert", novel_name="{小说名}", category="location", name="{地点名}", data={快照})` 保存。首次完整5要素，后续只更新变化部分。

### 2. 事件快照

大事件跨多章时，每章结束后更新。

```yaml
事件快照:
  事件名: {如"兽潮来袭"/"聚落防御战"/"废墟逃生"}
  起因: {一句话}
  当前进展: {到本章为止的状态}
  参与者变化:
    - {角色名}: {本章状态变化}
  环境变化: {地点/灵能浓度/结构变化}
  物品变化: {消耗/获得/损坏}
  伏笔状态: {planted/recalled/新增}
  下一步预判: {下一章可能的走向}
```

**存储**: 写完后通过 `writing_finish` 的 key_events + characters_involved 同步到DB。

### 3. 人物状态快照

每章写完后，对出场的活跃人物更新状态。

```yaml
人物状态快照:
  角色名: {名}
  位置: {当前在哪}
  身体: {健康/受伤程度/{世界特有疾病}进展/体力}
  心理: {当前情绪/压力/决心}
  知识边界: {知道什么/不知道什么/刚学到什么}
  装备: {身上有什么/背包里有什么/刚消耗了什么}
  关系变化: {本章和谁的关系有变化}
  能力状态: {能力进展/副作用/新发现}
```

**存储**: 通过 `character_update_by_name(novel_name="{小说名}", character_name={character_name}, _status_json={JSON字符串})` 写入DB。下游skill用 `character_get_by_name` 读取。

## 增量更新协议

```
写完一章后:
1. 生成场景快照 → 如果是新地点，world_upsert保存；已有地点，只更新变化字段
2. 生成事件快照 → 如果是大事件的一部分，追加到事件链；独立事件，独立保存
3. 更新人物状态 → 只更新本章出场的人物，未出场的不动
4. 伏笔状态 → 新增的foreshadow_plant，回收的foreshadow_recall

原则:
- 不全量重写，只增量更新
- 快照是"此刻的状态"，不是历史记录
- 历史记录通过timeline_add和chapter_save_summary保存
```

## 一致性验证规则

QA校对时检查:
- **人物位置**: 上一章在A地，本章突然在B地，中间没有移动描写 → 报错
- **物品状态**: 上一章用完了，本章还在用 → 报错
- **环境细节**: 同一地点首次描写有"铁锈味"，后续描写说"没有气味" → 报错
- **身体状态**: 上一章受伤的手，本章没提就恢复正常 → 标记提醒
- **知识边界**: 角色不知道的信息在本章被他使用 → OOC报错
