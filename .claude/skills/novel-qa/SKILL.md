# 小说质量保障

> 共享约定：读 `references/shared-conventions.md`
> 快照引擎：读 `references/engine-snapshot.md`（一致性校验规则）
> 物品引擎：读 `references/engine-item.md`（物品一致性校验）

## 强制流程

```
B3审阅: 数据获取 → 3Agent并行分析 → 🔒评分卡 → 汇总报告
C2诊断: health_check → 健康指标对比 → 🔒破局方案
C3更新: 改数据 → db_search找影响 → 🔒确认改哪些
```

输出结构化结果到 `novels/{小说名}/审阅报告/`。无文件输出 = 流程未完成。

## B3: 审阅

### 大纲审阅（Phase 1-3 达尔文评估体系）

触发: "审阅大纲"/"检查大纲"

**Phase 1 达尔文评估**：
- 10维度并行Agent审计（根据卷类型选5-10维度）
- 每维度0-100分
- 参照 `references/outline-review-checklist.md`

**Phase 2 女娲修复**：
- P0/P1问题进入自动修复流程
- 每个问题生成3个修复方案 + 代价评估 + 修复蓝图
- 参照 `references/outline-review-checklist.md`

**Phase 3 验证迭代**：
- 修复后重新评估，与修复前分数对比
- 综合≥85通过，最多3轮迭代

### 正文审阅（15维度扫描）

触发: "审阅正文"/"检查正文"/"校对"/"proofread"

**Step 1: 加载角色状态**

| 优先级 | 来源 | 用途 |
|--------|------|------|
| 1 | 角色蒸馏文件（前一章） | 精确状态：位置/装备/心理/身体/伏笔状态 |
| 2 | 角色深化.md | 核心性格/Lie/Ghost/行为基线 |
| 3 | 锁定设定.md | 固定设定（名称/价格/地点） |
| 4 | novel-db character_get | 数据库状态快照 |

**核心角色禁忌**（从蒸馏文件和角色深化提取，以下为当前项目示例）：
- 沈野：妹妹第一/他人冷漠/秃鹫本能/拓印萌芽
- 沈念：天真≠蠢（能感知问题但善意解读）/判断力+执行力+隐藏能力/压缩式痛苦表达
- 方岩：15年斥候经验/行动先于言语/短指令/碎罗盘是命/12人阵亡创伤

**Step 2: 15维度逐章扫描**

3Agent并行（每Agent必须加载完整角色基线）：

**Agent A — 人物维度（2.1+2.2+2.6）**：

- **2.1 人设OOC检查（最高优先级）**：
  每个角色行为3问：
  1. 知识匹配：该角色根据蒸馏文件知道这个信息吗？
  2. 行为匹配：这个动作符合角色基线吗？
  3. 状态匹配：该角色当前状态能执行这个动作吗？

- **2.2 知识矛盾检查**：
  角色只能基于当前知识行动，检查信息泄露和叙事视角切换

- **2.6 微动作检查**：
  禁止情绪直白词（"惊讶""愤怒地"），用动作表达情绪
  告别场景：2-3个犹豫微动作

**Agent B — 逻辑维度（2.3+2.5+2.9+2.12+2.13+2.14）**：

- **2.3 逻辑连贯**：时间间隔/距离移动时间/因果/空间一致性/章节衔接
- **2.5 经济逻辑**：价格体系一致性（碎灵晶3铜/粗面+盐1标准碎片/碎渣弹~5铜/拾荒者日收~45铜）
- **2.9 伏笔一致性**：跨伏笔追踪，伏笔-章节交叉检查
- **2.12 受伤一致性**：跨章受伤追踪，恢复时间线标准（轻1-3天/中5-10天/重15-30天/危需灵能修复）
- **2.13 物品/装备状态**：消耗品数量递减，损毁装备持续存在
- **2.14 新元素合理性**：新物品/异兽/能力/地点与现有世界观一致

**Agent C — 质量维度（2.4+2.7+2.8+2.10+2.11+2.15）**：

- **2.4 战斗质量**：调用 `/novel-battle` 战斗审计（分镜/POV/动作反馈/异兽差异/代价/燃点/节奏/精准动词）
- **2.7 结构变异**：反AI结构僵化，检查结构变体使用
- **2.8 爽点密度**：微/小每章/中每3-5章/大每8-12章/超级每卷1-2次
- **2.10 NPC深度**：每章≥2有动机NPC
- **2.11 叙事视角+术语**：POV一致性，灵/灵衰症/灵晶，T1/T2/T3，灵站/灵枢
- **2.15 写作风格**：时间表达文学化/感官描写/AI味检测

**Step 3: 问题分级**

| 级别 | 定义 | 处理 |
|------|------|------|
| P0-致命 | 人设OOC/知识矛盾/受伤消失 | 立即修复 |
| P1-严重 | 逻辑断裂/因果不连贯/经济矛盾 | 必须修复 |
| P2-中等 | 叙事泄露/战斗扁平/结构僵化 | 建议修复 |
| P3-轻微 | 错别字/术语不一致/描写重复 | 批量修复 |
| P4-建议 | 可优化但不影响阅读 | 可选 |

**Step 4: 输出报告**

报告结构：
1. 15维度检查结果表
2. 问题清单（含等级）
3. 角色知识状态验证
4. 伏笔追踪
5. 受伤状态验证
6. 物品状态验证
7. 统计摘要

**评级**: A(无P0/P1) / B(有P1无P0) / C(有P0) / D(严重OOC)

**批量执行**：超过3章时用并行Agent执行，每章独立报告，最后总览。

**修复模式**：P0/P1问题生成修复方案 → 用户确认 → Edit修改 → 重新验证

## C2: 健康诊断

触发: "诊断"/"卡文"/"疲劳"/"写不动"

**一键诊断**：`health_check(novel_id)`

**健康指标**：

| 指标 | 健康 | 异常 |
|------|------|------|
| 伏笔积压 | 回收率>40% | >50%且最旧>30章 |
| 配角活跃 | 核心角色5章内提及 | >10章未提及 |
| 升级节奏 | 符合品类建议 | 40章无升级无替代 |
| 日常密度 | 5-8章有日常 | 10+章纯战斗 |
| 暗线推进 | 15-20章有新进展 | >30章无新线索 |

**破局策略**：
- 升级衰减 → 切换爽点类型（碾压→博弈/智斗/信息差/以弱胜强）
- 配角遗忘 → 信息差回归/独立线交汇/侧面描写维持存在感
- 伏笔膨胀 → 批量回收/延迟长线/放弃不重要的
