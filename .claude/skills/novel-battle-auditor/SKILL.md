# 战斗场面审计引擎

> 代入POV角色的视角，逐段扫描8大维度。多Agent并行时每个Agent必须加载完整角色状态。

## 强制流程

```
Step 1 加载上下文 → Step 2 八维度审计 → Step 3 问题分级 → Step 4 输出报告
```

---

## Step 1: 加载上下文

```
1. 读取战斗场景所在的章节正文
2. 读取角色蒸馏文件（前一章）→ 参战角色状态（体力/装备/位置/心理/身体）
3. 读取角色深化.md → 能力字段 + 战斗风格 + 行为基线
4. 读取 references/writing-style.md → 通用写作风格标准
5. novel-db: character_get → 最新人物状态
6. novel-db: timeline_query → 时间线（防止战斗跨时空）
7. 读取审阅报告中的战斗重构方案（如存在）
8. 读取 novel-battle-writer/SKILL.md → 写作标准（作为审计基准）
```

**角色基线优先级**：

| 优先级 | 来源 | 用途 |
|--------|------|------|
| 1 | 角色蒸馏文件（前一章） | 当前体力/装备/位置/心理/身体 |
| 2 | 角色深化.md | 能力字段/战斗风格/行为基线 |
| 3 | novel-db character_get | 最新状态快照 |

---

## Step 2: 八维度审计

### 2.1 分镜完整性审计

逐段标注每个段落的机位类型，统计覆盖率：

| 机位 | 检查要点 | 缺失后果 |
|------|---------|---------|
| 远景 | 战场全貌/敌我位置/环境/规模 | 读者不知道在哪打 |
| 中景 | 战术动作/走位/配合 | 只有个人特写无全局 |
| 近景 | 武器碰撞/灵能效果/伤害 | "打了一下就赢了" |
| 特写 | 微表情/关键细节/决策瞬间 | 缺少爆发感 |
| 慢镜头 | 转折/致命一击/重大瞬间 | 全程匀速无高潮 |
| 快切 | 短句密集/1句1动作 | 缺少紧迫感 |

**标准**：≥3种机位切换。

**输出**：分镜图谱（每段标注机位类型）

```
L1-5   [远景] 战场环境
L6-12  [中景] 对峙试探
L13-16 [快切] 密集交手
L17-25 [慢镜头] 关键转折
L26-28 [特写] 致命一击
L29-32 [中景] 余波代价
```

### 2.2 POV一致性审计

- 确认本场战斗的POV角色
- 逐段检查：
  - 是否有POV角色看不到/听不到/感觉不到的信息？
  - 是否出现全知叙述（"他不知道""另一个方向"）？
  - 是否出现其他角色的心理描写？
- 🔴 一场战斗中途不可切换POV
- ✅ 不同战斗场景可用不同POV（如场景A用沈野POV，场景B用方岩POV）

### 2.3 动作-反馈链审计

建立动作链表，逐个检查：

```
动作1: {攻击/防御} → 结果1: {命中/闪避/格挡/受伤} → 连贯: ✅/❌
动作2: {攻击/防御} → 结果2: {?} → 连贯: ✅/❌
...
```

检查清单：
- [ ] 每次攻击是否有具体结果？
- [ ] 每次受伤是否有具体描写（部位/程度/后续影响）？
- [ ] 是否有悬空动作（攻击了但没有结果描述）？
- [ ] 反馈是否符合物理/灵能逻辑？
- [ ] 受伤是否在后续段落有延续（不能伤完就忘）？

### 2.4 异兽差异化审计

对每种出场的异兽，提取其行为特征：

```
异兽1: T1灰蜥(先锋)
  行为: {描述}
  独特行为: {有/无}
  独特弱点: {有/无}
  与同类差异: {有/无}
```

检查清单：
- [ ] 每种异兽有≥1个独特行为/攻击方式？
- [ ] 不同等级（T1/T2/T3）风格明确区分？
- [ ] 是否存在"通用异兽模板"（所有异兽行为一样）？
- [ ] 异兽行为符合等级设定（T1=本能/T2=智能）？
- [ ] 同场多只同等级异兽是否有行为差异？

### 2.5 代价系统审计

| 代价类型 | 是否出现 | 具体描写 | 后续连贯性 |
|---------|---------|---------|-----------|
| 体力消耗 | ✅/❌ | 引用原文 | 后续章是否延续 |
| 资源消耗 | ✅/❌ | 引用原文 | 后续是否记得减少 |
| 身体损伤 | ✅/❌ | 引用原文 | 伤情是否具体/后续体现 |
| 精神代价 | ✅/❌ | 引用原文 | — |

**标准**：每场战斗至少覆盖3种代价类型。

**连贯性检查**：
- 本章受伤 → 下一章是否有伤情描写？
- 本章资源消耗 → 后续是否记得减少？
- 蒸馏文件的"身体"字段是否反映战斗代价？

**🔴 受伤状态DB审计（强制）**：

检查novel-db character.status.injuries是否与正文一致：

| 检查项 | 标准 | 问题等级 |
|--------|------|---------|
| 正文描写了受伤但DB无记录 | 每处正文受伤必须有对应injuries条目 | P0 |
| DB记录的严重度与正文不符 | severity必须匹配正文描写程度 | P1 |
| 恢复时间线不合理 | healing_timeline必须符合严重度标准（见下表） | P1 |
| 后续章未体现受伤影响 | 下章角色行为必须受injuries.affects约束 | P0 |
| 已痊愈的伤仍在DB标记未解决 | 超过healing_timeline的伤应标记resolved=true | P2 |

**受伤严重度→恢复时间线标准**：

| 严重度 | 类型示例 | 恢复时间 | 后续表现 |
|--------|---------|---------|---------|
| 轻 | 皮外伤/擦伤/轻度淤青 | 1-3天 | 短期疼痛/不影响行动/下章基本消退 |
| 中 | 深度切割/灵能灼烧(面积<手掌)/扭伤 | 5-10天 | 行动受限/需包扎/2-3章后明显好转 |
| 重 | 骨折/大面积灵能灼烧/内伤/深度撕裂 | 15-30天 | 需专业治疗/持续影响4-6章 |
| 危 | 致命伤/灵能侵蚀内脏/断肢 | 需灵能修复 | 无法行动/不治疗会死 |

**🔴 物品/装备状态DB审计（强制）**：

检查novel-db character.status.inventory是否与正文一致：

| 检查项 | 标准 | 问题等级 |
|--------|------|---------|
| 正文消耗了物品但DB未更新 | 每次消耗品使用必须反映在inventory | P1 |
| 正文损毁了装备但DB仍标记完好 | 装备损坏/丢失必须更新 | P0 |
| 正文获取了新物品但DB无记录 | 战利品/拾取物品必须添加 | P1 |
| 灵能装备能耗状态未追踪 | 灵能短刀/碎渣仓能耗需标注 | P2 |

### 2.6 燃点审计

检查清单：
- [ ] 是否有≥1个燃点？
- [ ] 燃点类型是什么（绝地反击/团队配合/能力觉醒/代价高光/环境杀）？
- [ ] 燃点是否有充分铺垫（前面有压力递增）？
- [ ] 燃点是否绑定角色情感/关系/目标？
- [ ] 燃点爆发是否使用了慢镜头/特写技术？
- [ ] 燃点后是否有代价（不能白燃）？
- [ ] 燃点是否推动剧情/人物关系变化？

### 2.7 节奏审计

逐段标注节奏：

```
L1-5   [慢] 远景环境
L6-12  [中] 试探
L13-16 [快] 快切交手
L17-25 [极慢] 慢镜头转折
L26-28 [快] 反击
L29-32 [慢] 余波
```

检查清单：
- [ ] 是否存在节奏变化（不能全程匀速）？
- [ ] 快慢交替是否合理（高潮前加速，高潮时拉长）？
- [ ] 段落长度是否匹配节奏（快=短段/慢=长段）？
- [ ] 连续快切是否超过5段（超过则疲劳）？
- [ ] 是否存在"慢→快"的突然加速（应有过渡）？

### 2.8 精准动词审计

扫描模式：

| 问题模式 | 示例 | 修复建议 |
|---------|------|---------|
| 副词+动词 | "猛烈地砍" | → "劈" |
| 副词+动词 | "快速地闪" | → "侧身" |
| 形容词+名词 | "强有力的一击" | → "刀劈到骨头" |
| 重复动词 | "砍"连续出现>3次 | → 换用"劈/扎/划/斩" |
| 模糊动词 | "攻击/防御/战斗" | → 具体动作 |

**输出**：动词替换清单

| 位置 | 原文 | 问题 | 建议替换 |
|------|------|------|---------|
| L{行号} | "{原文}" | {问题类型} | "{建议}" |

## Step 3: 问题分级

| 等级 | 定义 | 战斗特有示例 | 处理 |
|------|------|------------|------|
| **P0** | 核心规则违反 | POV中途切换/无任何代价/异兽通用模板/动作悬空无反馈 | 必须重写 |
| **P1** | 严重质量缺陷 | 缺少≥2种机位/燃点无铺垫/全程匀速/代价不连贯 | 必须修改 |
| **P2** | 中等质量不足 | 精准动词不足/环境利用缺失/感官描写单一 | 建议修改 |
| **P3** | 轻微问题 | 重复动词/副词堆砌/过渡句粗糙 | 批量修复 |

## 批量执行模式

当用户说"检查V1战斗"或"审计Ch009-014"时：

1. 逐章执行 Step 2
2. 每章输出独立报告
3. 全部完成后输出总览

**并行Agent策略**（超过3章时）：

| Agent | 覆盖章节 | 说明 |
|-------|---------|------|
| Agent A | Ch009/010 | 审计+报告 |
| Agent B | Ch011/012 | 审计+报告 |
| Agent C | Ch013/014 | 审计+报告 |

每个Agent必须加载完整的角色状态和设定文件。

---

## 修复模式

当用户说"修复Ch009战斗"时：
1. 读取该章的问题清单
2. 对每个P0/P1问题生成修复方案
3. 展示修复方案给用户确认
4. 确认后执行Edit修改
5. 修改后重新审计确认问题已解决
