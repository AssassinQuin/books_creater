> 方法：单 agent 依次执行，交替使用 zhihu-search / global-search 避免 rate limit

## 执行策略（避免 rate limit）

- **交替搜索**：zhihu-search 和 global-search 交替使用（不同端点，降低同一端点限流概率）
- **节奏控制**：每 3 次搜索后穿插 1 次 Read+Edit，给 MCP 端点冷却时间
- **降级方案**：MCP 被限时自动切换 WebSearch 兜底
- **总量控制**：分 6 个 Phase，每 Phase 4-5 次搜索，Phase 间有文件写入间隔

## 搜索后处理规则

每次搜索完成后：
1. **判断相关性**：只取与洪荒流世界观相关的信息
2. **标注来源**：知乎/百科/网文
3. **版本冲突全存**：多版本用 `〔版本A〕〔版本B〕` 标注
4. **精彩叙事**：对精彩故事/算计，保留叙事细节（不要只存结论）
5. **因果标注**：每个故事/事件标注因果链关系（上游因→本体→下游果）
6. **写入文件**：Edit 到对应文件 + 补充到 20-因果链总工程图.md
