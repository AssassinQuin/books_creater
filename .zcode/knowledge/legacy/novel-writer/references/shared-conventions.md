# 共享约定

> 所有小说创作skill共用的铁律、数据规范和Git约定。

## 铁律（所有输出必须遵守）

1. **人物群像** — NPC有自己的生活，反派有自己的逻辑，配角有自己的故事线，不全围着主角转
2. **去AI味** — 禁止：不禁/缓缓/淡淡/微微/代价/反噬/寿命折损/精神崩溃。对话像真人，描写有画面
3. **日常即世界观** — 用摊贩大爷的闲聊、告示栏的排名、酒馆的物价展示世界，不空洞堆设定
4. **百万字是马拉松** — 卷级规划、配角轮换、伏笔回收节奏、升级衰减后的替代爽点，从第一天就设计
5. **明暗双线** — 每卷有明线（主角推进）和暗线（隐藏真相），暗线不一次揭完，分卷递进

## 数据分层

| 数据 | 存储 | 原因 |
|------|------|------|
| 世界观/人物/章节/伏笔/时间线/维度 | **novel-db** | 结构化查询，百万字规模 |

## 流程纪律（防止跑偏）

### 规则1：步骤不可跳过

每个skill有编号步骤。**必须按序执行，不可跳步**。上一步的输出是下一步的输入。如果缺少前置条件，暂停并说明需要先做什么。

### 规则2：关键检查点必须确认

标注 `🔒` 的步骤是**强制检查点**——执行后必须向用户确认结果，用户说"OK"/"继续"/"没问题"才能进入下一步。用户说"改一下"则回退修改。

### 规则3：偏差纠回

用户在流程中问了无关问题 → 先**简短回答**（不超过3句），然后说"我们刚才在{步骤名}，继续？" 如果用户说"算了先聊聊别的" → 保存当前进度到 Memory（tags=`project:{名},flow-state`），等用户说继续时恢复。

### 规则4：断点续传

每次skill被触发时，先检查 Memory 中是否有该项目的 `flow-state`：
```
memory_search(query="flow-state", tags=["project:{名},flow-state"])
```
如果有 → 读取上次停在哪一步，问用户"上次我们在{步骤}暂停了，从那里继续？"而不是从头开始。

### 规则5：写后必存

`novel-chapter-writer` 的 `writing_finish` 是**不可跳过的步骤**。写完正文后，无论发生什么，必须调用 `writing_finish` 更新状态。如果用户在写完正文后说了别的话，先完成 `writing_finish`，再回应用户。
