# 小说质量保障（novel-doctor）

> 源自达尔文优化版，移植到 ZCode 文件流。共享铁律见 `.zcode/knowledge/legacy/novel-writer/references/shared-conventions.md`。

## 强制流程

```
B3审阅: 数据获取 → 3线并行分析(spawn) → 🔒评分卡 → 汇总报告落盘
C2诊断: book_status+tracking_check → 对比健康指标 → 🔒破局方案
C3更新: 改设定文件 → ref_search 找影响 → 🔒确认改哪些
```

审阅/诊断结束时，**必须输出结构化结果文件**到 `novels/{书名}/审阅报告/`。没有输出文件视为流程未完成。

## ZCode 编排

- **主力子 agent**：`novel-doctor`（简报 `.zcode/agents/novel-doctor.md`）；三线审阅、健康诊断、破局方案由它并行/串行执行，主流程汇总
- **数据获取**：`context_pack` + `tracking_check` + `ai_check` + `ref_search(scope="book")` 替代原 db_search 系
- 断点续传：`novels/{书名}/审阅报告/` 最新一次报告的日期与范围

## B3: 审阅

触发: "审阅"/"检查"/"review"

1. 读 `.zcode/knowledge/legacy/novel-writer/references/review-checklist.md`
2. 数据获取：`tracking_check`（状态一致性）+ `ai_check`（AI 味）+ `ref_search(scope="book")`（设定/伏笔检索）
3. spawn `novel-doctor` 四线并行分析：
   - **A-逻辑**: 时间/空间/能力一致性（时间线+角色状态快照），伏笔超30章未回收标黄
   - **B-人设**: 角色行为对照 `设定/角色/*.md` 检查 OOC，AI 味对照 `ai_check` 报告 + 黑名单
   - **C-合规+竞争力**: 平台合规（`ref_route(平台上架)`），爽点密度，钩子有效性，侧面描写
   - **D-契约**: 因果权+结算权（高光/收益归属）、期待债偿还、终局储备透支、三条可证伪核对（爽点铺垫/配角差异化反应/详略按目的词）；每项标 契约安全/需补强/契约破坏
4. 🔒**章节评分卡**（每章量化打分）：

   | 维度 | 1-3分 | 4-6分 | 7-10分 |
   |------|-------|-------|--------|
   | 文笔 | 大量AI味词/空洞描写 | 基本流畅/偶有AI味 | 生动有画面/句式多变 |
   | 节奏 | 拖沓或赶进度 | 有节奏但平淡 | 张弛有度/有钩子 |
   | 人设一致 | 明显OOC | 轻微偏离 | 行为符合人设 |
   | 伏笔推进 | 无进展无提及 | 有提及但机械 | 自然融入/暗线推进 |
   | 去AI味 | ≥5个黑名单词 | 1-2个黑名单词 | 0个/对话有废话 |

5. 汇总 → `novels/{书名}/审阅报告/第{N}次审阅_{范围}.md` → 问题分级（致命/严重/轻微）+ 评分卡
   ```
   章节{N}总分: {Σ各维度}/50
   趋势: {与最近5章均分对比 ↑↓→}
   短板: {最低分维度}
   ```

## C2: 健康诊断

触发: "诊断"/"卡文"/"疲劳"/"写不动"

**一键诊断**：`book_status` + `tracking_check` + 正文/大纲扫描 →

**健康指标**：

| 指标 | 健康 | 异常 |
|------|------|------|
| 伏笔积压 | 未回收<40% | >50%且最老>30章 |
| 配角活跃 | 核心配角5章内提及 | >10章无提及 |
| 升级节奏 | 符合genre建议 | 40章无升级且无替代爽点 |
| 日常密度 | 5-8章有日常 | 连续10章纯战斗 |
| 暗线推进 | 15-20章有新进展 | >30章无新线索 |

**破局方案**（spawn `novel-doctor` 生成，附具体章节点）：
- **升级衰减**：切爽点类型（升级碾压→势力博弈/智斗/信息差/以弱胜强），引新体系（炼丹/阵法/灵兽）
- **配角遗忘**：信息差回归（他在暗处做了什么？），独立线与主线交汇，侧面描写维持存在
- **伏笔膨胀**：批量回收（选3-5条重要伏笔2-3章内回收），长线伏笔延后新卷，果断放弃不重要的

## C3: 级联更新

触发: "改设定"/"改人物"/"调整"

1. 改对应设定文件（`设定/世界观/*.md`、`设定/角色/*.md`——整体重写，不打补丁）
2. `ref_search(keyword, scope="book")` 找受影响内容（设定/大纲/正文）
3. 列出受影响章节 → 询问用户哪些需要改
4. 改正文后：`tracking_commit(mode="revision")` + `ai_check` 复核 + commit

> 写作中途说"改设定" → 暂停写作，先走本流程，处理完回来（冲突消歧最高优先级）。
