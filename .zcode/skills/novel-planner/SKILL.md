# 小说卷规划（novel-planner）

> 源自达尔文优化版，移植到 ZCode 文件流。共享铁律见 `.zcode/knowledge/legacy/novel-writer/references/shared-conventions.md`。

## 强制流程

```
B1: 召回数据 → 全书总纲(首卷,🔒确认) → 逐卷规划(每卷🔒确认) → 章节场景清单 → 跨卷伏笔 → commit
```

每卷规划完必须 🔒确认 才能进入章节场景创建。用户说"改"→ 回退修改。

## ZCode 编排

- **主力子 agent**：`plot-planner`（简报 `.zcode/agents/plot-planner.md`）；总纲、卷纲、细纲场景清单、伏笔规划都 spawn 它执行
- **spawn 前**：`ref_route`（大纲卷纲 / 细纲与单章钩子 / 线索伏笔悬念）取权威文件清单贴进任务提示
- **首批细纲产出后立即** `tracking_init`（`mcp__story-flow__tracking_init`），让追踪状态与大纲同步诞生
- 断点续传：`novels/{书名}/大纲/` 已有大纲.md/卷纲/细纲 的最大章号判断停在哪一步

## B1: 卷规划

触发: "规划卷"/"大纲"/"出细纲" | 前置: A 层完成（世界观+人物）

1. 召回：`novels/{书名}/` 下 选题决策.md + 设定/世界观/* + 设定/角色/* + 设定/关系.md + 已有 大纲/*
2. 如果是第一卷 → 先生成**全书总纲** → `novels/{书名}/大纲/大纲.md`（一页纸）：
   - **中心点**：主角核心欲望/终极命题一句话——所有人物、支线、冲突都是它的不同投射（形散神不散的"神"）
   - 核心冲突 + 终极方向
   - 预计卷数（百万字≈500章/8-15卷）
   - 主角成长弧线关键节点
   - 明暗双线全局规划（暗线分几层揭示）
   - 🔒**用户确认总纲**后才继续
3. **逐卷规划** → `novels/{书名}/大纲/卷纲_第N卷.md`：

   **每卷必定义**：
   - **卷契约**：本卷开始时的输入状态 / 结束时必须达成的战果（主推线+战果归属）
   - **剧情单元**：本卷拆成若干剧情单元（单元ID/位置/单元情绪引擎/对标剧情参照），细纲按单元成批出
   - **终局底牌边界**：本卷最多动用哪一级储备（多线齐涨的战果允许）；未来揭示计划留在大纲，不写入正文事实
   - 卷名 + 主线/暗线/配角线三线（各含 description + purpose）
   - **期待管理（两短一长）**：任意章节时段必须同时挂两个短期期待（1-3章/10-30章内兑现）+ 一个长期期待（卷级/全书级）——爽点是期待被满足的结果，满足即动力消失，爽完必须立即接新期待（防满足性弃书）
   - 主线推进程度 + 暗线揭示多少（不能一次揭完）
   - 重点出场配角(2-4人)及弧光
   - 升级节点（如有）或替代爽点（势力博弈/智斗/信息差/以弱胜强）
   - 伏笔计划：埋几条、回收几条旧伏笔
   - 卷尾状态：主角水平、世界格局变化

   🔒**每卷规划后确认**才进入章节场景。

4. 卷确认后 → 章节场景清单 → `novels/{书名}/大纲/细纲_第NNN章.md`（每章一个文件）：

   ```markdown
   # 细纲·第NNN章 {标题}
   章节定位: {主线/暗线/配角线} · 情绪: {主情绪} · 字数目标: {N字，默认3000}
   本章三要素: 目标 {主角这章要做什么} / 阻碍 {什么人·环境·规则挡路} / 爆点 {怎么破局·获得什么}
   阶段位置: {卷内阶段：铺垫/推进/高潮/收束}
   本章结构公式: {如 危机→反证→公开代价}
   禁止提前释放: {本章不得泄露的后续真相/底牌/关系结论，无则写"无"}
   ## 场景表
   | # | 地点 | 人物 | 冲突 | emotion_type | key_beats |
   |---|------|------|------|--------------|-----------|
   | 1 | ...  | ...  | ...  | dialogue/action/atmosphere/psychology/daily/montage | ... |
   ## 情节安排（逐点字数预算）
   主线: … / 辅线: … / 事件线: … / 感情线: … / 逻辑线: …
   ## 人物关系和出场顺序: …
   ## 钩子: 章首…/章尾…
   ## 伏笔: 埋设…/回收…（标注对应 tracking 伏笔ID）
   ```

   - `emotion_type` 必填（novel-chapter-writer 按它切换写作策略）；同一章场景类型不超过2种
   - **本章要消费的旧信息（伏笔ID/久别角色）在细纲里点名**——写前旧信息查询超 3 次说明细纲没写清
   - 开书首批细纲 10 章；按剧情单元成批出纲
   - 开新卷若引入新角色/势力，先提示回 A2/A3 增补设定
5. 跨卷伏笔：写入卷纲的「伏笔计划」段（description + 埋设章号 + 计划回收章号 + importance + 关联角色）；已 init 追踪的项目同时 `tracking_commit` 登记伏笔
6. `git commit -m "B1: 第{N}卷规划完成"`

完成后建议：`/novel-chapter-writer` 开始逐章写作。

## 大纲更新

触发: 用户在写作过程中想修改某卷规划

1. 读 `大纲/卷纲_第N卷.md` 当前规划
2. 修改（整体重写受影响段落，不打补丁）
3. 如果改了已写章节的大纲 → 扫 `正文/` 列出受影响章节，提醒用户
4. `git commit -m "更新: 第{N}卷大纲调整"`
